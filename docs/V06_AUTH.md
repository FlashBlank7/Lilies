# v0.6 登录与项目成员

本阶段使用用户名和密码开放注册，不需要注册令牌或人工审批。普通账号只看自己创建或被加入的项目；平台管理员管理全部项目及账号。模型连接由项目负责人配置，注册不会获得平台的模型密钥。

## 部署与首次登录

使用平台相同的环境配置运行：

```sh
.venv/bin/python -m agent_platform.auth 管理员用户名
```

命令交互式输入两次密码，不将密码放入命令行。已有账号不会被覆盖或自动提升权限。公开注册永远创建普通用户，不再将首个注册者提升为管理员。

打开 `/register` 注册，或在 `/login` 登录。右上角进入账号设置和退出；管理员另有“账号管理”入口，可禁用、恢复或重置密码。忘记密码由管理员重置；首版不需要邮件或短信服务。

浏览器通过同源 `/api/platform` 代理访问后端，使用 HttpOnly、SameSite=Lax Cookie。HTTPS 部署自动设置 Secure；局域网 HTTP 试用支持普通 Cookie。后端令牌只存哈希，会话默认七天，允许多个设备同时登录。退出仅撤销当前会话；改密、管理员重置或禁用账号撤销所有会话及原有客户端令牌。注销不取消已经提交的计算任务。

前端不再读取或自动补充服务器 API_TOKEN，也不接受浏览器手工传入的管理员令牌。下载、事件流使用会话 Cookie，不将令牌写入 URL。显式服务端 Bearer Token 集成保留，默认 `change-me` 无效；签名集成回调继续使用原有签名及身份校验。

## 项目共享

新建项目的账号是负责人。在项目“设置 → 项目成员”输入已有用户的准确用户名，可添加协作者或转交负责人。协作者能编辑、运行和读取项目结果，不能管理成员及连接。完整本机智能体能力只由平台管理员授权。

旧项目不会被新注册者认领：迁移后先仅管理员可见，管理员从项目设置指定负责人。原始资料、模型、工作流和报告保留。

直接访问工作流、文件和运行地址也验证项目成员；跨项目资料复制要求能访问来源和目标，复制模型连接要求管理两边的连接。移出成员后新请求即失去访问权限，已有文件的本地副本不会撤回。

## 代理部署与登录限速

默认每个地址每小时允许 20 次注册尝试，同一地址及用户名每 15 分钟允许 10 次失败登录；分别由后端 `AUTH_REGISTER_PER_HOUR` 和 `AUTH_LOGIN_FAILURES_PER_15M` 配置。成功登录清除该地址和用户名的失败计数，其他来源的计数保留。限速返回 HTTP 429 及 `Retry-After`，前端代理保留此响应头。

经过代理时，只有可信入口提供的地址才能参与计数。部署时生成一次随机值，分别设置前端和后端进程的 `AUTH_PROXY_SECRET`（至少 32 个字母、数字、下划线或短横线），并在入口代理设置相同值；前端只从进程环境读取，不能使用 `NEXT_PUBLIC_` 前缀。示例生成命令：

```sh
python -c 'import secrets; print(secrets.token_urlsafe(32))'
```

将其保存在本机受限的部署配置中，不提交仓库。它只验证限速地址来源，不提供账号或项目权限。修改配置后重启前后端及入口代理。Compose 已向前端传入同名环境变量，后端继续从 `.env` 读取。

下面是直接面向访客的 Nginx 入口示例，前后端仅在本机回环地址或受限内网开放。替换密钥占位符，HTTPS 部署时放入已有 TLS server 配置；代理必须覆盖这两个自定义请求头，不能转用访客提供的 `X-Forwarded-For`。相关覆盖行为见 [Nginx 官方 proxy_set_header 文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_set_header)。

```nginx
server {
    listen 8080;
    client_max_body_size 260m;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $http_host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Lilies-Client-IP $remote_addr;
        proxy_set_header X-Lilies-Proxy-Key "REPLACE_WITH_AUTH_PROXY_SECRET";
        proxy_set_header X-Forwarded-For "";
        proxy_set_header X-Real-IP "";
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

后端建议使用 `uvicorn ... --no-proxy-headers`，由上述专用头传递限速地址。缺少密钥、密钥不匹配、非法 IP 或地址列表均回退到后端连接地址，不采纳伪造身份。没有入口代理时保持 `AUTH_PROXY_SECRET` 为空；多个浏览器通过同一个前端访问会共享后端所见地址额度，不宣称此模式已按访客区分。多级代理需让可信最外层识别客户端地址，不能直接照搬此单入口示例。

计数按 IP 而非物理设备识别：共享 NAT 出口可能共用注册额度；IPv6 等价写法及 IPv4 映射 IPv6 地址归为同一地址。真实设备与网络拓扑仍需在部署环境验收。

实际串联 Nginx、生产前端及隔离后端验证：两个不同网络来源分别注册成功，各自再次注册返回 429；经入口及直连前端伪造地址均不能重置计数；注册产生的会话可读取当前账号。诊断环境将额度设为每小时 1 次，不修改用户项目与模型连接。
