# 项目工作区界面

客户从 `/projects` 打开项目。创建和需求包导入使用弹窗，只创建空白项目；确认需求、开始建设和试用仍由客户发出指令。

## 页面与主题

`app/theme.css` 提供共享冷色变量：背景 `#F5F7FA`、内容白色、正文 `#202B3D`、强调 `#3F639F`。旧全局样式和各页面模块使用同一组变量。`AppShell` 提供可收起导航；项目页以对话为主，右侧显示目标、能力、具体问题和最近结果。窄屏通过进展面板查看详情。

需求、长回复、业务结果和项目文件可以在阅读窗口中打开。CSV 使用 Papa Parse，保留字符串标识，预览前 200 行；超过 2 MB 的文件提供下载。HTML 报告在禁止脚本和外部资源的独立框架中阅读。相对文件链接只能打开当前项目内的资料与结果。输入草稿、反馈对象和对话滚动位置按项目保留在当前浏览器标签页；服务端仍负责保存进展、消息、任务和实际结果。

进展中的结果同时关联文件和任务时，先阅读原文件，并提供“查看关联结果”。报告内的相对链接按报告所在目录解析，可访问同项目的相邻目录；越出项目资料目录的链接不生效。转去反馈结果只绑定反馈对象，保留尚未发送的文字。

工作流编辑器使用浅色画布。`embedded=1` 隐藏编辑器外框，不改变工作流内容、权限、测试或版本语义。项目中可进入完整编辑器。

## 持久执行过程

`GET /api/v1/projects/{id}/conversation` 保持默认最近 50 条客户消息，支持 `before`、`after`、`limit`。回复附带不含原始参数/输出的 `current_activity` 和当前页面请求的 `request_activity`。

`kind=activity` 按需返回步骤更新，可附 `request_id` 限定某次请求。每个新操作保存 `operation_id`、`request_id`、起止时间、工作流/事项/任务关联及实际返回。工具开始、任务创建、工具结束沿用同一操作标识；并行工具调用保持独立关联。前端按操作标识合并更新，展开后读取子运行和原始参数。

客户补充继承当前请求关联；不会因为省略可选标识而丢掉原反馈。停止和服务重启会收束未结束步骤，重启不自动执行。继续处理沿用原事项/任务；修改后试用仍创建新任务并通过 `feedback_task_id` 关联原结果。工具操作结束、工作流运行状态和业务能力可用程度分别展示。旧事件没有的关联不补猜。

建设测试结果保留在操作记录和开发详情；客户试用结果进入对话卡片。全部业务输出仍来自现有实际运行记录。

## 工作流的业务说明与需求对照

项目「业务流程」默认进入说明页，先显示用途、所需输入和产出，再按业务能力展示当前进展、逐项原要求、实际结果及差距。多项能力先给概览，选择后展开对应的对照与结果。单个成员显示它参与的业务事项，明确区分业务能力整体状态与成员自身实现，不能把共同完成的结果自动归功于每条工作流。

说明复用项目推进记录：`value.workflows` 存储 `workflow_id/purpose/inputs/outputs`；`items[].requirements` 存储 `requirement/source/current/status/gap/results`。结论为已满足此项、部分满足、尚未满足、尚未验证。没有说明时明确显示缺失，并可通过原项目对话请求统筹补充；不从节点数、运行成功或测试数计算达标率，不增加运行门槛。所有结果和成员引用仍校验项目范围，修订号冲突仍明确返回。

「协作如何执行」从 `/topology` 返回的 `flows` 读取当前草稿节点与连线，显示先后顺序和可展开的真实条件分支；不会把成员列表当作执行顺序。点击调用步骤进入对应成员说明。「编辑画布」进入原编辑器，保留全部编辑能力。
