## 1. 总览

v0.2.x 已把实验从“灵感 backlog”推进为可追踪的实验台账：Builder benchmark 基线链路已应用，E01 已完成多轮 paid/live plan-first 切片，E02/E04 已完成 proxy 或局部对照，E05 已完成多任务族 reuse-depth 对照、工程修复和第一版 adaptive policy 确定性回测，E08 已完成工程证据审查但未做 sidecar/passmode 对照。

当前结论必须保持克制：

- 已应用：Builder test self-consistency、benchmark node equivalence、terminal-node equivalence、repair confirmation boundary、marketplace Template expandability、timeout/build-deadline evidence boundary、customer-support Template guardrails、Builder teammate deadline/repair-budget governance。
- 已验证但未关闭原始问题：E01 complex required single case、E02 readable TestFrame proxy、E04 localized repair、E05 reuse-depth 多轮 case 与 adaptive policy live validation。
- 未开始或仅有工程前置：E03、E06、E07、E08、E09、E10。
- Platform Harness 多数 stage 是 slice，不得写成完整 Platform Harness 已闭环。

`v0.2.48` 新增的约束是：不能再把 `shallow` 当作跨任务族的默认候选去描述，而且不能把“adaptive policy 已实现”误写成“E05 已关闭”。现有三族证据已经足以支撑第一版 adaptive policy 上线，但还需要 live validation 来验证真实 Builder 收益。
