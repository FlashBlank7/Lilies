# v0.2.20 Platform Harness Worker Lease

## 1. Stage Goal

Complete the first hard-boundary Platform Harness gap carried from `v0.2.19`: worker lease and durable execution semantics.

This stage implements a worker lease primitive, not a full distributed execution queue:

- task records persist `worker_id`, `lease_expires_at`, and `lease_version`;
- Harness exposes claim, renew, release, and expired-lease reconciliation operations;
- API exposes bounded lease operations for future workers/operators;
- expired leases become failed task records with explicit metadata and events;
- late success after lease expiry cannot silently mark work as succeeded;
- Studio task monitor typing and cards can show lease state.
