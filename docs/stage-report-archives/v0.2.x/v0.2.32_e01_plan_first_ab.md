Evidence:

- Plan-first required: `docs/experiment-status/evidence/experiment_v0.2.32_e01_plan_first_required_2026_07_09.json`
- Node-by-node disabled: `docs/experiment-status/evidence/experiment_v0.2.32_e01_node_by_node_disabled_2026_07_09.json`
- Summary: `docs/experiment-status/evidence/experiment_v0.2.32_e01_ab_summary_2026_07_09.json`
- Report: `docs/experiment-status/reports/2026-07-09_1834_E01_plan_first_vs_node_by_node_ab.docx`

| Metric | Plan-first required | Node-by-node disabled |
| --- | --- | --- |
| Build status | `ready` | `ready` |
| Benchmark score | `0.85` | `0.85` |
| Pass rate | `1.0` | `1.0` |
| Duration | `183.7s` | `87.4s` |

Conclusion:

- On the simple summary smoke task, both modes produced a ready BlockFlow with the same benchmark score.
- Node-by-node was cheaper and faster.
- This result does not answer whether plan-first helps complex multi-module BlockFlows.
