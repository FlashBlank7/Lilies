# 从使用轨迹发现问题并接续改进

2026-09-28。管理员从顶部「使用改进」进入 `/improvements`。员工正常操作即可留下已有运行及接口记录，不要求填写反馈表。主动意见反馈继续作为补充。

## 已实现的路径

后台每分钟整理最近30天、最近更新的最多500个工作流任务及500次失败接口操作。页面明确显示采样范围，超出部分不冒称已覆盖。读取任务编号、状态、版本、关联关系和输入参数是否相同；不把个人对话正文、文件内容、输入输出正文、凭据和原始错误文字复制到线索库。

当前可提取四类线索：

- 同项目同工作流同冻结版本，至少两个不同任务出现完全相同的错误文字。页面仅显示固定错误类别。停止、等待回答和请求被接受均不等于失败。
- 成功任务通过 `feedback_task_id` 明确关联原失败任务，显示冻结内容及输入参数是否变化。时间相邻的两个任务不会被猜成修复关系。
- 同一冻结版本至少三个业务任务成功，且至少两组输入参数不同。相同参数反复测试和 `build_test` 不作为方法复用。
- 同资源同类操作至少两次返回相同失败状态。HTTP 状态记录不含提交正文，401/403/404 权限失败不参与推断。

输入参数相同不保证外部文件字节相同；成功不等于业务效果通过或员工采纳。修复前后同时改变输入和工作流时，两种变化均显示，不能直接推断因果关系。

线索有稳定编号，重复整理更新同一条。可查看运行轨迹、标记处理中/已处理/忽略/重新打开，并下载包含相关任务、限制和建议的改进说明。标记已处理只是管理员的整理操作，不阻拦任何业务，也不会调用模型；之后扫描保留这个标记。某条线索在新扫描中不再成立或移出采样范围时，保留历史并标明「本轮未再观察到」，不自动宣称已解决，也不再自动派发。旧版本失败仍可检查，但当前草稿已经变化时不自动处理。

## 查看处理进展与继续沟通

建立处理会话后，点击「查看处理进展」才读取该会话，展开期间每30秒刷新，也可手动刷新。显示实际排队/运行/结束/失败/中断状态、当前轮最新回复、错误及本会话最近20个关联任务与总数。新一轮还没有回复时，不会把上一轮的答案充作本轮结论；会话数据无法读取时提供重试，不显示虚假的完成状态。

只有处理会话所属的管理员可以读取这些回复，其他管理员也不能借线索查看其私聊。扫描和线索列表仍不读取对话正文。关联任务仅限此项目、此处理会话，不混入原始失败任务或其他员工的运行；运行成功仍不等于改进有效。

运行中可点击「停止处理」，复用现有会话停止机制；「继续沟通」只打开原会话，由管理员输入并发送后才继续模型工作。启动前连接失败的会话保留「重试启动」。智能体本轮结束不会自动将线索标记为已处理，管理员可自行整理状态。关闭自动处理只影响之后的派发，需要停止已启动工作时使用停止按钮。

## 自动处理与已有智能体

自动整理始终不调用模型。管理员可勾选项目并启用「自动交给官方智能体」；默认关闭，避免把所有历史项目直接交给模型处理。项目需已经获准、启用完整智能体能力，并选择官方智能体作为任务来源；系统不复制连接、不改变供应商，任务智能体不自动改用 API 计费；若执行已有工作流，其中模型节点和计算仍按项目原配置执行。

自动处理仅在官方队列空闲时启动，已启动的工作不被新任务自动抢占。过去24小时最多处理的线索数默认1，可调整为1至10；这是自动处理数量，不改变现有单任务token上限、模型、思考模式、时间或额度保留设置。关闭自动处理后不启动新项，已经启动的会话通过项目现有停止/继续入口操作。

每条线索交给开启设置的管理员自己的独立项目会话，复用已有工具、权限、持久排队、用量记录和停止机制。自动尝试失败或中断后不循环重试；即使重启服务仍保留尝试次数，可手动进入原会话检查。取消授权、改用API或管理员失去权限时不会启动自动模型工作；失效项目不阻塞其他可用项目。维护会话产生的任务排除在下一轮候选之外，避免系统从自己的试验中不断生成更多工作。

纯测试和用途不明的历史任务不会自动派发；接口报错可下载定位说明或手动交给智能体分析。手动「让项目智能体处理」沿用该项目当前选择的模型，重复点击复用同一会话。后台发现不触发员工的原会话，也不覆盖员工正在写的消息。

改进任务要求智能体辨别预期失败测试、资料缺项和真正缺陷；需要修改时先创建独立工作流副本，使用原失败输入及一个变化输入验证，保留原结果。**这是交给已有智能体的任务要求，不是额外的只读沙箱**：执行权限仍是项目原有权限，管理员应只对允许自主修改的项目启用自动处理。

首版自动处理的范围是项目内工作流、方法说明及资源问题。平台仓库代码的问题交付复现和修改建议，供开发者处理；未实现无人值守修改平台源码、发布或回滚。也未接入全页面点击采集或从个人聊天全文推断满意度。

## 验证范围

- 从已有平台运行记录的本地私有副本抽查最近500条实际任务，得到重复错误、明确关联的失败后成功和多输入复用线索；这些记录包含开发验收，不等于真实员工意见。详细项目名和内容留在本地。
- 后端行为检查覆盖实际工作流两次失败、幂等重试不增计数、修改后的关联成功、不同输入复用、测试/停止排除、权限与正文隔离、旧库迁移、扫描故障、连接失败后的幂等接续、自动次数限制、设置关闭的并发情形、失效项目跳过及维护任务排除。
- 使用官方智能体协议替身实际调用平台工具，创建独立修复副本，并让真实运行时计算原输入和变化输入；原流程与失败结果保留。替身不证明真实模型能够自主发现正确修法，也未新增模型费用。
- 前端行为检查覆盖管理员入口、筛选、轨迹、下载、设置保存、未保存设置不被刷新覆盖、失败提示、显式启动与会话选择、普通账号无权限和旧线索显示；生产构建包含类型检查。
- 后续真实官方智能体复验使用自编的“可选数量应默认1却被错误设为必填”案例：两个原失败记录保留，智能体创建独立副本，运行两项断言测试和两次业务计算，分别得到1和4；原流程内容哈希不变。不是客户业务准确率验收。首次被出口设置阻止、第二次恢复文件缺失均未执行模型；修复接续后在同一平台会话完成，模型/思考沿用 Luna/max，无其他模型连接。
- 该真实任务记录23次工具操作（2次失败），模型执行89.67秒、服务记录286,861 token。这里只报告服务用量，不换算订阅费用或猜测内部模型请求次数；单次小任务的成本偏高，暂不据此默认批量开启自动维护。
- 桌面页面实测展开失败记录、重试读取、进入原会话、明确发送接续任务、返回查看真实回复和三项关联任务、标记已处理与重新打开。前端行为测试覆盖延迟响应、账号切换、停止后刷新和不发送消息的继续入口；390像素内嵌页面检查基础布局，未冒称物理手机或真实员工验证。

## 9月28日：减耗取证与已实施调整

对上述同一次真实任务的原生记录进一步拆解：16次模型响应，输入283,071 token（其中缓存输入224,768、非缓存输入58,303），输出3,790（其中推理1,982，已包含在输出中），累计286,861。缓存输入约占输入79.4%；这些记录不能直接换算成订阅费用。一次响应有21,653输入但没有缓存命中，日志未说明原因，不将其归因于本地代码。

发现并处理了两个具体浪费来源：

- 项目智能体的 `workflow_run(action="validate")` 过去会因为没有强制验收测试判为无效。本次真实模型因此补了测试、再次验证并运行测试。现在该动作明确返回 `validation_scope="structure"`，只校验图、配置、引用和项目能力；未绑定模型/工具资源可保留，运行时再检查。不会新建或删除测试；显式 `tests` 仍运行原有断言并报告真实失败。旧发布及非项目验证默认语义保持兼容。
- 每次读取积木说明都附带相同的节点、连线及测试 schema。项目工具现在默认完整返回所选积木的配置、端口和示例，通用 schema 通过 `schema_type="node"/"edge"/"test"/"workflow"` 按需读取。`view="full"` 保留旧组合返回，非项目工具默认仍为旧格式。`block_type="workflow"` 返回图格式，避免把“工作流”误当不存在的积木。草稿工具明确用 `view="summary"` 读取，错用 `action` 时给出正确参数提示，不修改草稿。

关闭两个模型出口后，使用相同自编缺陷完成工具回放：原图保留，在独立副本中修改默认值，没有保存验收测试，结构验证通过，两组真实计算仍输出1和4。两份积木说明从18,365降为4,541字节；加上一次按需图 schema 后共8,244字节，相比原来两份组合返回减少约55.1%。这是实际工具数据量的比较，**不是模型 token 或耗时降低比例**，也不证明真实模型会选择相同调用次序。本轮模型调用为0。

随后处理了原生工具发现过宽的问题。原记录用 `workflow|draft|clone|copy` 搜索名称和描述，返回15项、17,426字节（含执行包装）。原工具组介绍含有 workflow，被适配器重复放到11个延迟工具的描述前，使网页检索、共享记录等无关能力也命中。

现在工具组只用中性介绍，各工具默认提供简短用途及必要操作约束。17个工具的名称、完整参数、权限及调用方式保留；需要例子或完整说明时，按工具名读取 `block_catalog`。原始API模型也使用简短介绍、完整参数，手册不是调用前置条件。进度完整替换、人工回答、独立测试授权及公开检索边界等必要提醒保留。

同一套现有工具定义按紧凑JSON序列化：完整介绍36,803字节，简短介绍32,612字节。另固定原生记录中的参数声明和原查询，仅离线替换介绍，命中由15项降为7项、JSON正文17,379→7,805字节；未命中的工具仍可按名称发现和调用。这是说明改动的离线对照，未重新生成真实原生响应，也没有计入上一轮新增的目录schema字段，**不能当作新模型运行、实际token降幅或耗时改善**。

受影响后端97项通过、4项按既有条件跳过。协议替身检查全部工具和schema仍被传给官方接入；API会话替身未读取手册，直接通过真实平台保存流程并执行得到4。完整帮助、项目能力限制、旧会话工具更新接续均通过相关行为测试。本轮新增真实模型调用为0，前端未改。自动模型派发保持关闭；真实任务的调用次数、总用量和回答质量变化，留待后续必要的受控复验。
