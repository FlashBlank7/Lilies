# v0.6 项目知识库与语义检索

当前实现项目资料解析、切分、独立 Embedding 连接、索引版本、语义检索及原文出处展示。页面、项目智能体的 `project_knowledge` 工具和 `knowledge_search` 积木共用同一实现。现已提供普通积木组成的引用问答工作流、回答和出处展示及下载。真实生成效果仍待授权模型连接恢复后验收，不能把模型替身的回答当作真实 RAG 效果。

## 页面使用

1. 登录后进入项目的“资料与知识”，填写知识库名称、稳定引用名称、片段长度和重叠长度，保存配置。
2. 可以立即创建检索工作流。即使没有模型、资料或索引，也可以保存并编辑；运行时明确指出缺少可用索引，不自动更换模型。
3. 项目负责人配置独立的 OpenAI 兼容 Embedding 连接。API 地址以 `/v1` 等接口前缀结尾，平台调用其 `/embeddings`。此连接只做向量化，不能当作对话模型；密钥仅保存在后端连接目录，普通成员看不到明文。
4. 选择已有项目文件，或粘贴正文。支持可提取文字的 PDF、DOCX 和 UTF-8 文本。扫描 PDF 需要先提供 OCR 文本；当前不解析图片内语义。资料保存页码、段落或行起点、字符偏移及内容哈希。
5. 建立语义索引，输入问题、返回条数和最低相似度进行试用。模型需要的文档/查询前缀可分别填写。运行结果直接展示原文和出处，并可下载包含索引版本的 JSON。
6. 工作流使用知识库下拉选择器；检索返回 `results`、`context`、`version` 和 `retrieved_count`。点击“创建引用问答工作流”得到可编辑的普通积木：输入 → 检索 → 有无资料条件 → 文本模板 → 原始 LLM → 回答和出处。没有资料时走另一条结束分支，不调用 LLM。
7. 在项目设置配置主模型，供回答节点使用；Embedding 连接独立。流程可在主模型未配置时保存，执行到回答节点时才检查模型。模型调用失败保留具体错误，不自动换供应商或增加审查调用。模板、上游字段、系统提示词和模型可通过画布表单修改。
8. 回答和编号对应的原文同时展示，可下载含问题、回答、原文及索引版本的 Markdown/JSON。页面提示不存在的引用编号或未标注引用的回答，保留模型原文；编号能对应并不证明结论受到原文支持，不做额外模型审查或自动重写。
9. 项目 Skill“项目知识与引用问答”介绍知识库查询和已有工作流的发现、输入输出检查及调用方式。列表只返回名称与用途，正文按需读取，用户可以编辑。

每个知识库最多 100 份资料、1000 个片段，单份文件最多 20 MB、正文最多 100 万字符，PDF 最多 500 页。当前采用按原文字符窗口切分及向量余弦相似度，未引入重排器或大规模向量数据库。切分不会调用大模型。

## 索引、权限和失败处理

资料或切分配置变化后显示待建立索引；模型地址、名称或协议变化后拒绝混用旧向量。一次建立索引期间资料被编辑时，提交返回冲突，旧索引保留。失败不会覆盖已有版本，已就绪版本再次点击建立索引不会重复向量化。

每次工作流运行固定知识索引版本；后续新运行读取新版本，已保存结果不随资料修改而变化。继续旧运行仍需原 Embedding 连接可用。版本记录的是配置的模型标识和地址，服务商在同名模型下原地替换权重不在当前可检测范围内。

项目成员权限同时覆盖知识库、资料操作、检索与连接接口。协作者可以使用和编辑共享知识，但仅负责人或管理员可以修改模型连接。跨项目读取、移除成员后的读取和检索均拒绝。索引建立当前是页面发起的同步操作，展示执行中状态；尚未提供独立的索引任务停止/恢复页面。

远程出口默认为关闭。关闭时不会把正文或查询发送到远程 Embedding 服务；显式配置的本机回环接口可用于本地模型。没有自动选择服务商、模型或开启远程访问。

在隔离数据库和生产前端中，从页面注册账号、新建诊断项目、保存空白知识库并创建三节点检索流程。提前运行显示 `node search failed: 本次运行没有绑定可用知识索引`。

页面配置本地 Ollama 的 `embeddinggemma:300m`，地址 `http://127.0.0.1:11434/v1`，无密钥，远程出口保持关闭。模型在本机运行，返回 768 维向量；没有使用本地代码智能体代替向量模型，也没有更换已授权的对话服务商。

诊断资料通过页面粘贴：英文电池维护建议和英文食堂介绍。中文问题“如何延长蓄电池使用寿命？”命中电池建议，相似度 0.667244，阈值 0.3 下未返回食堂资料。页面和原工作流均返回相同原文、行号和版本。这是小规模跨语言诊断，不能推断其他资料或所有问题的检索准确率。

删除电池资料并从页面重建后，同一工作流的新运行返回 0 条结果。旧运行仍显示原电池资料及旧版本；浏览器下载的 JSON 与旧运行结果逐项一致，文件 SHA256 为 `b5f701b824ce3c10333383a915e2afa45f8db22fef4ae6710102d3a705f04878`。下载事件观察超时，但实际下载文件已落盘并核对，没有据超时重复下载。

后端全量 3684 项通过、14 跳过；后续文档解析错误修复与知识库复测 9 项通过。前端 145 项、类型检查及生产构建通过。自动测试用替身向量验证版本、并发、连接变化、权限、错误及回归；上述页面诊断另用真实本地 Embedding，未把替身结果当作真实语义效果。PDF 页码、DOCX 段落/表格和损坏文件通过解析测试验证，原生文件选择器仍未验收。

## 引用问答实现与联调

后续阶段从同一隔离项目页面创建引用问答流程，未配置主模型仍能保存。中文电池问题对仅含食堂资料的真实本地索引返回零条，结束分支正常返回缺少依据；中文午餐问题命中原文后准确报错 `node answer failed: 本项目尚未启用工作流模型调用`。因此修正了项目运行策略把“没有连接”当作“禁止整图”的旧耦合；原始模型节点自身仍检查项目连接和远程出口，显式运行权限及完整智能体限制没有移除。

为了联调回答展示，单独在该隔离项目的页面配置本机 HTTP 模型替身，名称与回答正文均明确标注诊断用途。没有修改正式项目的服务商或连接。实际流程把问题和检索原文交给替身一次，收到含 `[1]` 的预设回答；页面显示对应原文并下载。JSON 与保存的回答和知识结果完全一致，Markdown 包含问题、回答、原文及位置。之后将提示词拼接改为模板转换积木，重新从页面创建流程；在表单增加“请简短回答”，保存后再次运行，收到的模型请求确实使用新模板。替身用于验证调用、引用展示和下载，不能验证模型理解、真实性或引用准确率。

后端全量 3697 项通过、14 跳过；后续模板及输出字段的受影响回归另行记录在周报。前端 147 项、类型检查和生产构建通过。测试执行页面使用的实际工作流定义，覆盖无资源保存、无资料零次生成、有资料一次原始模型调用、用量保留、HTTP 402 不换模型、Skill 按需读取和工具复用知识索引。

已授权远程连接通过 [DeepSeek 官方余额查询接口](https://api-docs.deepseek.com/api/get-user-balance/) 重新核实仍不可用，因此没有追加付费生成请求或自动切换连接。余额数额、密钥与原始诊断运行日志不进入仓库。
