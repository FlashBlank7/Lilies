# 参数扫描结果与连续区间

2026-09-25。从既有工艺参数扫描代码提炼：把“最高分在哪里”推进到“哪些连续采样片段符合本次条件，能否形成所需宽度”。工作流使用现有代码积木、条件检查和项目运行服务；读取已有扫描表，不生成候选、不训练、不再次预测。

在项目空间「公共工作流市场」加入同名流程，或从示例创建「参数扫描结果与连续区间」。项目得到可编辑副本、使用 Skill、自编资料及修改练习。员工可以直接运行，也可以通过对话让智能体发现并调用。

## 使用方法

1. 选择项目内 CSV、TSV 或 XLSX，每行一个数值参数点。Excel 多工作表需指定名称。不同样品或实验指定分组列，各组独立分析。
2. 指定参数列、分数列和比较方向，说明数值来自模型、测量还是示例。分数的业务含义和单位需明确；可以使用现有模型预测结果中的指标。
3. 在条件行表配置必需条件。固定值与同一行对比列选一个；条件缺值或格式错误不会自动放行。未声明条件也能运行，但明确只分析分数范围。
4. 按扫描方案填写最大相邻间隔，不从最小步长猜测。填写近最佳容差、最小宽度、最少点数；需要限制范围时再填最大宽度。
5. 查看各组结论、区间和逐点原因，下载完整表。修改条件或宽度后重新运行，旧输入和结果保留；不会因此触发预测或训练。

## 方法和边界

| 问题 | 处理 |
| --- | --- |
| 中间有不合格点、未知条件或无效分数 | 在原参数轴上断开，不能先删点再跨过去连接 |
| 两点间距超过配置上限 | 标记扫描缺口，断开区间 |
| 最高分是孤立点 | 保留最佳点，但不将其当作区间；其他稍低分的宽区间列为备选 |
| 多处同分或多个窗口 | 保留并列、备选和重叠，不任意选第一个 |
| 分数需要平滑 | 默认不平滑；可选相邻3/5点均值，仅在连续且条件可用的点内计算，不跨失败点或缺口；边缘使用已有点 |
| 中间点不在近最佳容差内 | 断开近最佳片段，即使其他条件满足 |
| 区间过宽 | 按最大宽度列出最大连续窗口；全部端点取自输入，不插值裁切 |
| 同组数值参数重复 | 报出具体记录，先明确重复测量如何汇总，不直接平均或任取第一条 |
| 没有满足要求的区间 | 交付具体缺项或宽度/点数不足原因，不强行推荐 |

比较分与原分数方向一致，近最佳容差使用分数单位；越小越好时接受不高于最佳值加容差的点。计算与判断使用精确有理数，展示值最多90位十进制精度；不会先把参数四舍五入再连接。输入数值沿用最多40位有效数字、非零数量级1e-40至1e40的限制。

平滑按采样点数取平均，不按不等间距进行物理加权。最少点数至少2；最大宽度启用时，保留不能继续向两侧扩大的窗口，窗口可能重叠。最小宽度和最少点数不足的片段仍输出原因。

输出的是满足已声明规则的**连续采样片段**，点与点之间未实际测量的位置不保证满足条件。模型分数符合规则，不等于实际测量、生产安全或全局最优。首版只分析一维参数；不能把多个独立一维区间直接组合成多参数方案。

## 输出与复用

- `source_path`：逐点分析 CSV，原字段、源记录号、原分数、比较分、条件状态、近最佳标记和中断原因。
- `intervals_path`：区间及不足原因 CSV，包括分组、实测/计算输入端点、宽度、点数、是否包含最佳点及是否符合本次要求。
- 条件检查 CSV：每个条件的实际值、比较值和原因。
- JSON 与 Markdown：输入内容标识、本次配置、完整分组结果和普通语言说明。

这些是分析结果表，不能把辅助状态列直接当作训练特征。报告预览限制为20组、20个区间及12个点；完整结果在下载文件中。单表最多2万点、10 MB，条件数量与计算量沿用候选比较流程限制。
