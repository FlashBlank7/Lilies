## 发现与修正

1. **思考耗尽节点输出额度。** 初次业务 API 沿用默认思考，2,200 token 输出额度用尽且正文为空；官方智能体又以相同配置尝试一次，仍失败。页面手动停止后，在项目模型设置关闭业务 API 思考，再用同一输入运行。官方智能体仍用 Luna/max。运行错误现在说明具体节点、实际输出上限、思考可能计入额度，以及可修改的配置；平台没有自动换模型或扩额。模型设置增加对应说明。
2. **统计解释越过事实范围。** 旧提示词出现把完全重复解释为不同时点、把前几行时间规律推广到整表、混淆产品质量与数据质量的问题，也未在业务含义不清时展示补充表单。模板现在说明统计范围、完全重复定义和业务问题；自编文件不变，仅更新工作流后重跑。最终报告正确保留未知、统计事实和未执行检查。
3. **遗漏待办及无必要追问。** 会议纪要最初遗漏没有负责人却已经决定的内部试用。第一次修正后仍把已给出会议日期说成缺失、给已完成事项增加确认问题；第二次局部修正后，同一资料中试用与培训均在行动项，待确认只保留试用负责人。

失败任务和旧报告均保留。一次新会话复用了旧分析，没有运行新草稿；该请求只记为已有结果读取。随后明确要求重新运行当前草稿，才验证新配置。模板更新不会覆盖员工已经安装的副本；本轮仅通过正常修订接口更新自身试用副本。

七次官方请求合计报告 **387,268 token**，包括失败、旧结果读取、上下文及缓存输入；不是用户输入字数、订阅扣费或账号容量估计。两次会议局部修正通过页面直接运行，没有追加官方智能体请求。每任务 token 上限保持用户选择的无限额，执行时限 600 秒、并发 1、50% 额度保留及手动停止保留。

修正后数据工作流的两次原始 LLM 分别为 7.14/7.69 秒，报告输入 1,998/3,465、输出 1,438/1,578 token；最终会议节点 1.76 秒、输入 246/输出 262；两次周报节点 3.20/2.52 秒、输入 230/190、输出 714/517。服务未报告费用，不能把存储中的零值称为免费。官方请求时间包括工具操作与等待，不与单个原始 LLM 节点直接比较。

本次解决具体错误并完成路径，**尚未证明稳定低用量**。特别是接续解释的报告用量明显高于业务节点，应按相同任务继续定位上下文读取及工具返回成本，保持回答质量后再比较，不能从这几个不同请求推导提速比例。
