## Problem

The Try tab can report missing required input, but the next action is still implicit. Users must infer whether to fill sample data, edit fields manually, or run the draft.

## Boundary

- Guidance only.
- The existing `试运行当前草稿` and `运行已发布版本` buttons remain the only run entry points.
- The sample button may fill fields, but no new affordance may call `startRun(...)`.

## Solution

- Add a deterministic `tryRunNextAction` state:
  - `no_inputs`: workflow declares no Start inputs; run draft is available.
  - `fill_sample`: required input is missing or invalid; use sample first.
  - `run_draft`: inputs parse successfully; try current draft.
- Render a small next-action strip under readiness guidance.
- Keep it bilingual and testable with:
  - `data-try-sample-next-action`
  - `trySampleNextAction`

## Acceptance Criteria

- Missing-input state explicitly recommends filling sample input.
- Ready-input state explicitly recommends trying the current draft.
- No-input state explains that empty input is expected.
- Harness fixtures verify the mapping without live browser tooling.

## Final State

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` as `trySampleNextAction`.
- Added `data-try-sample-next-action` states for `no_inputs`, `fill_sample`, and `run_draft`.
- Preserved the run boundary: the new next-action strip is guidance only, and existing run buttons remain the only `startRun(...)` callers.
- Verified by `try_run_next_action_fixture` in the v0.3.32 harness.
