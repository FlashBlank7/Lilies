## Problem

v0.3.1 verifies customer example intake without mutation. The next evidence gap is whether a customer example can become a real local application and reopen safely. The test must avoid uncontrolled model calls and make the local-state side effect explicit.

## Boundary

The harness may create a local application with a `v0.3.2-smoke` marker. It must not call `/api/v1/applications/{id}/builds`, must not publish, and must not run the workflow. Because there is no delete application API, created smoke apps remain as local evidence until a later cleanup feature exists.

## Solution

Add a versioned script that:

- loads API token from `--token`, environment, or `.env` without printing it,
- creates a local application from a customer fixture through `POST /api/v1/applications`,
- reads the created application and draft through GET endpoints,
- fetches the frontend detail route for the created id,
- verifies active version is unset, draft revision is zero, and no build id is created,
- emits JSON evidence and a P0/P1 bug ledger for create/open/detail.

## Acceptance Criteria

- Script exits non-zero on auth, create, open, draft, detail, or safety failures.
- Script records the created application id and smoke marker.
- Script records no call to `/builds`.
- Focused pytest covers payload construction, token loading fallback behavior, and evidence gates without live services.
- Live run passes against local services.

## Evidence Requirements

- Live harness command and JSON path.
- Focused pytest command.
- Any created local application marker.
- Remaining cleanup or browser-visual limits recorded in workingon and stage report.
