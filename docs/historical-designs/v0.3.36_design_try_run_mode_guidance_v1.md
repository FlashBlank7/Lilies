## Problem

Draft and published runs imply different decisions. Draft mode is for debugging current edits; published mode is for validating a fixed deliverable. The result panel should say that directly.

## Boundary

- Copy and display only.
- Do not alter run payloads beyond existing `use_draft`.
- Do not auto-publish or auto-accept.

## Solution

- Add mode-specific title and detail copy.
- Render a compact mode strip before result interpretation.
- Keep existing result interpretation, recovery affordance, preview, and raw JSON.

## Acceptance Criteria

- Draft result guidance points toward editing, retrying, or acceptance once satisfied.
- Published result guidance points toward fixed-version validation.
- Unknown mode explains that the mode is unavailable after refresh or older state.

## Final State

- Added `tryRunModeLabel`, `tryRunModeDraft`, `tryRunModePublished`, and `tryRunModeUnknown` copy.
- Added mode-specific detail copy for draft debugging, published validation, and unknown local mode.
- Rendered the mode strip before result interpretation, preview, and raw JSON.
