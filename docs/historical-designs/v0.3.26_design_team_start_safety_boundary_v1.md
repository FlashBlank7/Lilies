# design_v0326_team_start_safety_boundary

状态：completed

## Source

- Source stage report: `docs/stage-reports/v0.3.25_create_action_state_explainer.md`
- Source tasks:
  - `Preserve team-start safety boundary`

## Problem

A recommended-action control could accidentally make model-team startup feel like a one-click path if it directly starts the build in the confirm-team state.

## Boundary

- Recommended action must not submit the form or call `/builds`.
- Existing two-step team-start guard remains the only path to model team startup.
- Confirm-team recommendation may focus or point to the explicit guarded button only.

## Solution

- Map confirm-team recommendation to a guarded-button focus target.
- Display copy that tells users to use the explicit confirmed team-start button.
- Keep the recommendation button `type="button"`.

## Acceptance Criteria

- Confirm-team recommendation does not call build APIs.
- Harness records confirm-team target as `guarded_build_button`.
- Source markers prove the recommendation button is not a form submit button.

## Final State

- Confirm-team recommendation maps to `guarded_build_button`.
- Recommendation button is `type="button"` and does not submit the create form.
- Existing two-step team-start guard remains the only model-team startup path.
- Live evidence calls only `GET /health`.
