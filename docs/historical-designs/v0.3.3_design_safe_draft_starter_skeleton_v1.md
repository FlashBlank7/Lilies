## Problem

v0.3.2 lets a user save a customer example as a local draft without starting the builder team. The opened detail page is real, but the draft contains zero nodes and zero tests. That still feels confusing to a non-technical user.

## Boundary

This design uses existing draft mutation APIs only. It does not call `/builds`, does not run the workflow, does not call a model, and does not add a new backend endpoint.

## Solution

After safe draft creation, seed the draft with:

- one `start` node with a `customer_request` input,
- one `answer` node with a visible placeholder answer bound to the start input,
- one edge from Start to Answer,
- one structural-only acceptance placeholder requiring `start` and `answer` nodes.

The skeleton is intentionally small: it gives the user something visible and editable while preserving the "not built yet" state.

## Acceptance Criteria

- Safe draft-only path creates at least two nodes, one edge, and one acceptance placeholder.
- The path still does not call `/builds`.
- If skeleton seeding fails, the UI reports an error instead of silently claiming success.
- TypeScript check passes.
- v0.3.3 harness verifies the structure live.
