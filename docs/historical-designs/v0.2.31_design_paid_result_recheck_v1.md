## 1. Problem

After repairing the confirmation boundary, the project should determine whether the old v0.2.29 paid result would now reach `ready` when reused. The old build is already terminal, so it cannot replay the Builder loop. Because this fix changes live Builder control flow, a fresh bounded paid/live rerun is required to validate industrial behavior.

## 2. Design Goal

Goal:

- Reuse or re-evaluate the v0.2.29 evidence without a fresh paid Builder generation when possible.
- Run a fresh bounded paid/live Builder rerun when reuse cannot validate the changed control flow.
- Record whether the repair-cycle fix can be validated by deterministic simulation and/or old-result recheck.
- Update the E01 report and ledger only for the narrow applied fix.

Non-goals:

- Do not run unbounded paid Builder calls.
- Do not close E01 original A/B.
