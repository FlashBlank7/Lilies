## Problem

The detail page has `build`, `edit`, `test`, `run`, and `monitor` tabs, but home-page links cannot currently open a specific tab. Quick actions would be misleading if every action only landed on the default build tab.

## Boundary

- Only accept known tab ids.
- Keep existing `?build=<id>` behavior intact.
- No backend changes.

## Solution

- Add a small `isStudioTab` guard.
- Read `?tab=<id>` on detail page load and set the initial tab when valid.
- Keep build-event watch behavior independent of tab links.

## Acceptance Criteria

- `/applications/{id}?tab=test` opens the acceptance tab.
- `/applications/{id}?tab=run` opens the try tab.
- `/applications/{id}?tab=monitor` opens the monitor tab.
- Invalid tab values are ignored.
