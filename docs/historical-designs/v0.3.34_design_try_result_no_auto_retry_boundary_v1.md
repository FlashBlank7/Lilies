# design_v0334_try_result_no_auto_retry_boundary

状态：completed

## Source

## Problem

A recovery affordance can accidentally become a hidden retry/resume/cancel action. That would violate the explicit-control boundary for Try runs.

## Boundary

- `focusTryResultRecoveryTarget` may call `setStudioTab`, `scrollIntoView`, `focus`, and `setNotice`.
- It must not call `startRun`, `resumeRun`, `cancelRun`, `api`, or model/build functions.

## Solution

- Keep the focus handler local and side-effect-light.
- Use existing explicit buttons for all mutating behavior.
- Add harness checks that inspect the handler body and fixture safety.

## Acceptance Criteria

- Recovery focus action has no API/mutation calls.
- Existing run/resume/cancel controls remain unchanged.
- Live evidence calls only `/health`.

## Final State

- `focusTryResultRecoveryTarget` is limited to `setStudioTab`, `scrollIntoView`, `focus`, and `setNotice`.
- Existing `startRun`, `resumeRun`, and `cancelRun` callers remain explicit buttons only.
- Harness body inspection reports no forbidden calls in the focus handler.
