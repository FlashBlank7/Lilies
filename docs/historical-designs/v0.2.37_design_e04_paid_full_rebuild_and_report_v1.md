# design_v0.2.37_e04_paid_full_rebuild_and_report_v1

## Goal

Run a bounded paid Builder full rebuild for the same greeting requirement and compare it against the local repair arm.

## Module Boundary

In scope:

- The v0.2.37 experiment script.
- Paid Builder build through the real `/builds` API when credentials are available.
- DOCX report and experiment ledger update.

Out of scope:

- Broad claims that full rebuild is inferior.
- Changing Builder prompts or repair-loop semantics.
- Multi-case statistical study.

## Experiment Design

Use the same requirement as the fixed failing draft:

`Build a workflow that accepts name and returns greeting exactly Hello {name}. For name Ada the output must be Hello Ada. Include a mandatory acceptance test.`

Arms:

1. Local repair: one real draft update operation on the failing existing draft.
2. Full rebuild: new application, Builder Team creates a fresh BlockFlow from the same requirement with bounded `max_turns` and `max_repair_cycles`.

Metrics:

- success/failure
- elapsed seconds
- model/tool usage for full rebuild
- draft node/edge/test counts
- operations count for local repair
- test pass status

## Acceptance Criteria

- Paid full rebuild is attempted when credentials are configured.
- If paid full rebuild fails, the failure is recorded and not hidden.
- DOCX report contains `背景`, `实验设计`, `结果结论`, `图片或截图`, `证据链`, and `工程应用状态`.
- E04 is closed only for the localized-failure case; broader local-vs-rebuild claims remain open.
