## Problem

After all default-safety prerequisites became satisfied, the project needed to prevent accidental default enablement.

## Boundary

This design preserved the enablement boundary only. It did not enable router defaults.

## Final Design

- `allowed_to_enable_default=true` means the guardrail prerequisites are satisfied.
- `default_enabled=false` means no default router behavior is active.
- The next stage must explicitly decide enablement review versus deferral.

## Acceptance

- Stage report distinguishes allowed enablement review from actual default enablement.

## Remaining Risk

The next stage must not skip the explicit decision.
