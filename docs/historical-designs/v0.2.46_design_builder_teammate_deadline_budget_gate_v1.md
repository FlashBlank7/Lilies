# design_builder_teammate_deadline_budget_gate

## Problem

`v0.2.45` showed that the deep customer-support E05 arm can spend minutes inside a nested Builder teammate/debug branch after tests have already exhausted repair headroom, then hit the 600 second build deadline.

## Boundary

- In scope: Builder teammate governance inside `platform/backend/src/agent_platform/builder.py`, deterministic regression coverage, and event/evidence visibility needed to explain the new behavior.
- In scope: preventing nested teammate/debug work from continuing after repair-budget exhaustion, and optionally blocking new teammate work when remaining deadline budget is too small to justify it.
- Out of scope: changing the user-facing build API, broad Platform Harness productization, or claiming global E05 closure.

## Solution

Add Builder-side teammate budget governance:

1. Make teammate entry points deadline-aware so `spawn_teammate` and `send_message` can refuse to open a long-tail branch when the remaining build deadline is already too small.
2. Make nested teammate loops stop immediately after `test_run` reports `maximum repair cycles reached`, returning bounded evidence back to the coordinator instead of continuing long debug work.
3. Emit clear failure/stopped reasons so stage reports and experiment summaries can distinguish governance stops from provider/model failures.

## Implementation Plan

1. Add helper logic in `builder.py` to compute remaining build budget and to detect repair-budget exhaustion at the current revision.
2. Thread build timing context into teammate tools so `spawn_teammate` and `send_message` can apply the guard.
3. Stop teammate `_agent_loop` early when a teammate-side `test_run` returns `maximum repair cycles reached`.
4. Add deterministic tests for:
   - teammate stop on repair-budget exhaustion,
   - teammate refusal when deadline budget is too low,
   - preserved build/task metadata and events.

## Acceptance

- A deterministic test proves nested teammate work does not continue after teammate-side repair-budget exhaustion.
- A deterministic test proves teammate entry can be refused by deadline budget.
- Existing Builder and E05 tests still pass.
- The change is narrow: no API rename, no unrelated refactor, no false claim of global E05 closure.
