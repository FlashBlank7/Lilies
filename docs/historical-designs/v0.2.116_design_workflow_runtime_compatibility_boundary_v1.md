## Problem

Workflow runtime already owns validation, workspace resolution, persisted run creation, async execution, and Platform Harness task lifecycle for real runs. Worker offload must reuse that contract.

## Boundary

- Worker handler creates a run; it does not synchronously execute graph nodes itself.
- The created workflow run remains governed by the existing runtime task id and finish lifecycle.
- The queued worker task remains the offload boundary and parent task.

## Acceptance

- API-created runs still use `origin="api"`.
- Worker-created runs use `origin="worker"`.
- Runtime-created run task has `parent_task_id` equal to the worker task id.
- Heartbeat registry records worker lifecycle around the handler.
