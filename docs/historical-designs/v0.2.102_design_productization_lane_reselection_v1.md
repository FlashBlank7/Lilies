## Source

- Source stage report: `docs/stage-reports/v0.2.101_e08_post_runbook_disposition.md`
- Source task: `Perform productization lane reselection`
- Current version: `v0.2.102_productization_lane_reselection`

## Problem

v0.2.101 paused the current E08 tranche after API, Studio controls, and operator runbook completion. The next version must choose the next productization lane from the experiment status and ledgers, without using `docs/workingon/` as a planning source.

## Boundary

- Select only from current experiment status and ledgers.
- Do not select E02 true human panel without an external panel.
- Do not select E10 governed memory implementation without an accepted governance boundary.
- Do not claim E08 full sidecar completion.
- Prefer a concrete unblocked productization slice over broad architecture closure.

## Final Scheme

Use a deterministic selector that scores candidate lanes by product value, readiness, evidence maturity, next-slice specificity, and blocker severity. The selector must emit raw JSON plus a readable summary into `docs/workingon/` only after this source-linked design exists.

## Acceptance

- Generated decision evidence names the selected lane and rejected/blocked lanes.
- Tests prove blocked lanes are not selected.
- Tests prove E08 broader sidecar boundary is preserved as not complete.
- Stage report records the fixed template sections and the next-stage task set.
