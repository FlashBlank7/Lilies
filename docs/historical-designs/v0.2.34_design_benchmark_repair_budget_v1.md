# design_v0.2.34_benchmark_repair_budget_v1

## Goal

Make repair budget explicit in `scripts/live_builder_benchmark_suite.py` so complex Builder experiments can be reproduced with a declared `max_repair_cycles` value.

## Module Boundary

- In scope:
  - `scripts/live_builder_benchmark_suite.py`
  - deterministic test coverage in `tests/test_workflow.py`
- Out of scope:
  - changing default production Builder budget
  - changing Builder repair-loop semantics
  - changing benchmark scoring

## Design

Add:

- `LIVE_BUILDER_BENCHMARK_MAX_REPAIR_CYCLES`, default `1`
- `MAX_REPAIR_CYCLES` field in result JSON
- build request uses `MAX_REPAIR_CYCLES` instead of hard-coded `1`

The default remains `1` to preserve v0.2.33 comparability. Complex reruns must declare the higher budget in command evidence.

## Acceptance Criteria

- Existing default behavior remains unchanged.
- Focused deterministic test can verify the configuration surface without calling a paid model.
- Result JSON records `max_repair_cycles`.
