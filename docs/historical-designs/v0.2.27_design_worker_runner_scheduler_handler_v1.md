## 1. Goal

Add one real built-in worker handler for queued `scheduler_manual_trigger` tasks.

## 2. Module Boundary

Backend:

- `platform/backend/src/agent_platform/worker_runner.py`
- `platform/backend/src/agent_platform/scheduler.py`

## 3. Implementation Plan

1. Extend `WorkflowScheduler.trigger_now()` to optionally use an existing Platform Harness task id and leave final task completion to the caller.
2. Add `scheduler_manual_trigger_handler()` that reads the application id from `task.owner_id` and optional inputs from `task.metadata.inputs`.
3. Add `build_platform_worker_handlers(services)` to register the scheduler handler.
4. Return run id and application id in handler result metadata.

## 4. Acceptance Criteria

- Handler starts a real workflow run through existing scheduler/runtime. Completed.
- The queued worker task is the parent Platform Harness boundary. Completed.
- Existing direct scheduler manual trigger behavior remains unchanged. Completed.
