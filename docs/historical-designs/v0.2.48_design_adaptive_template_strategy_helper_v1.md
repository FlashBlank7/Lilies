- Final status: completed

## Problem

`v0.2.47` showed that fixed `shallow` defaulting no longer matches multi-family E05 evidence, but Lilies still lacked a shared backend strategy layer for template suggestions.

## Boundary

- In scope: a shared helper that scores template matches and resolves `none / shallow / deep / adaptive` into an explicit effective depth for API and Builder template suggestions.
- Out of scope: online learning, benchmark-wide model routing, or fresh paid/live validation in the same slice.

## Final Design

- Add `platform/backend/src/agent_platform/template_strategy.py` as the shared strategy layer.
- Centralize allowed reuse-depth values, template scoring, adaptive resolution, and recommended-action mapping.
- Extend API `GET /api/v1/templates/suggestions` to accept `reuse_depth=adaptive` and return:
  - `effective_reuse_depth`
  - `recommended_action`
  - `policy_reason`
- Extend Builder `template_suggestions` to use the same helper and expose top-level effective depth so the coordinator can concretize BuildPlan reuse depth before mutating the draft.
- Keep the first adaptive rule narrow:
  - no credible match -> `none`
  - matched template contains visible complex dataflow hints such as `parameter_extractor`, `iteration`, `loop`, `variable_aggregator` -> `deep`
  - otherwise -> `shallow`

## Acceptance

- API accepts `reuse_depth=adaptive`.
- Builder `template_suggestions` accepts `adaptive` and returns explicit effective depth metadata.
- `data_analyzer` adaptive resolution returns `deep`.
- `code_reviewer` and `customer_support_router` adaptive resolution return `shallow`.

- `platform/backend/src/agent_platform/builder.py`

## Remaining Risk

- The first adaptive rule is heuristic and template-metadata-driven; it does not yet incorporate runtime success/cost outcomes directly.
- `customer_support_router` remains a conservative bounded choice because the family evidence is mixed across governance slices.
