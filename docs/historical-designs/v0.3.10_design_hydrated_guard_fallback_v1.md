## Problem

The build action guard is product-visible and should ideally be verified by a hydrated click trace. Browser runtime is unavailable, so the project needs a reliable fallback that is explicit about what it proves.

## Boundary

Do not trigger the second-click build path because that intentionally starts model/team work. Preserve no-build behavior.

## Solution

- Add source-level state-machine checks for home and detail build guards.
- Verify the first guard branch appears before the `/builds` call.
- Verify intent resets after requirement edits, scenario changes, successful build start, and build deadline edits.
- Keep live smoke evidence no-build and cleanup-only.

## Acceptance Criteria

- Fallback evidence passes when build guard state-machine markers are correct.
- Evidence states that hydrated browser click verification is unavailable when no browser/toolchain path exists.
- Endpoint ledger excludes `POST /api/v1/applications/{id}/builds`.

## Evidence Requirements

- v0.3.10 JSON evidence.
- Focused tests.
