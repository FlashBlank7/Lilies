# v0.2.91 design: rollback and unknown observability safety

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.90_complexity_router_runtime_activation_path.md`
- Source task: `Preserve rollback-to-disabled and conservative unknown handling`
- Version target: `v0.2.91_complexity_router_runtime_activation_observability`

## Problem

Observability can accidentally present disabled or unknown decisions as active rollout success if the metrics do not preserve the safety categories explicitly.

## Boundary

- Disabled/default settings must appear as bypassed/disabled, not active.
- Unknown requirements must be counted separately as conservative unknown.
- Request planning-mode overrides must remain visible.

## Design

- Derive status categories from persisted activation metadata:
  - `active`
  - `disabled_default`
  - `conservative_unknown`
  - `request_override`
  - `bypassed`
- Preserve `rollback_value="disabled"` in the metrics response.

## Acceptance

- Unknown samples increment conservative unknown and do not increment active.
- Default-disabled samples increment disabled/default or bypassed.
- Explicit request overrides are counted independently from normal active routing.

Completed in v0.2.91.
