# v0.2.89 design: default-disabled preservation

## Source

- Source stage report: `docs/stage-reports/v0.2.88_complexity_router_limited_default_enablement_plan.md`
- Source task: `Preserve default-disabled status`
- Version target: `v0.2.89_complexity_router_limited_default_enablement_contract`

## Problem

Adding limited default contract code can accidentally change normal runtime defaults.

## Boundary

- Keep default settings disabled.
- Make limited default opt-in/config-gated.
- Preserve old classification behavior for default settings.

## Design

- Settings defaults remain `complexity_router_default_mode="disabled"` and `complexity_router_limited_default_enabled=false`.
- Tests instantiate default settings and assert no default routing.

## Acceptance

- Default API classification has `default_router_enabled=false`.
- Default safety remains `default_enabled=false`.

Completed in v0.2.89.
