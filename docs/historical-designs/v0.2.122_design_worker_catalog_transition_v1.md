## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.121_e08_remaining_sidecar_slice_reselection.md`

## Problem

After v0.2.120, `workflow_run`, `test_suite`, `scheduler_trigger`, `scheduler_manual_trigger`, and `draft_patch_preview` are implemented. `benchmark` should now move from deterministic unavailable to implemented, while `builder_build` remains explicit gap behavior.

## Final Scheme

Move `benchmark` into `IMPLEMENTED_WORKER_HANDLERS` with v0.2.122 evidence and register `benchmark_handler()` in `build_platform_worker_handlers()`.

The catalog should then report:

- `benchmark` implemented;
- prior worker handlers implemented;
- `builder_build` unavailable;
- full execution coverage still false.

## Acceptance

- Catalog API shows `benchmark.status == implemented`.
- `builder_build` remains unavailable with deterministic operator action.
- `not_full_sidecar_completion` remains true.
