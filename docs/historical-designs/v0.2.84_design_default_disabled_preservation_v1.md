# design_v0_2_84_default_disabled_preservation

## Source

- Source stage report: `docs/stage-reports/v0.2.83_complexity_router_post_shadow_rollout_decision.md`
- Source task: `Preserve default-disabled status`
- Version target: `v0.2.84_complexity_router_operator_opt_in_rollout`

## Problem

Operator opt-in productization can be misread as default enablement. The rollout must prove opt-in behavior while preserving runtime default-disabled state.

## Boundary

- Keep `default_enabled=false`.
- Record `allowed_to_enable_default` separately from actual default state.
- Treat opt-in routing evidence as productization evidence, not default activation.

## Design

- Pull default safety from `complexity_router_default_safety_gate`.
- Include `default_enabled`, `allowed_to_enable_default`, and accidental default enablement count in the rollout evidence.

## Acceptance

- Evidence records `default_enabled=false`.
- Evidence records zero accidental default enablement events.

## Status

Completed in v0.2.84.
