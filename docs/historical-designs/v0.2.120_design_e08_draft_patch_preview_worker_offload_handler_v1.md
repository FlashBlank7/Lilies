- Current version: `v0.2.120_e08_draft_patch_preview_worker_offload_handler`
- Status: completed

## Problem

`draft_patch_preview` is a required Platform Harness task kind, but the worker catalog still treats it as unavailable. Existing natural-language draft patch preview is API-owned and deterministic, so it can be migrated to a worker-owned handler without model calls or draft mutation.

## Boundary

- Do not mutate the draft.
- Do not replace the existing API `/draft/preview-patch` path.
- Do not add model-backed patch generation.
- Do not claim full Platform Harness sidecar completion.

## Final Scheme

Add a `draft_patch_preview_handler()` that:

- reads `instruction` from queued task metadata;
- fetches the current draft from `workflow_store`;
- delegates to existing `DraftPatchPreviewer.preview()`;
- returns the existing preview response shape in worker result metadata;
- fails unsupported previews deterministically, matching the API's failed task semantics.

## Acceptance

- A queued `draft_patch_preview` task can be claimed and completed by `PlatformHarnessWorkerRunner`.
- Supported preview returns deterministic operations and does not mutate draft revision/hash.
- Existing API preview behavior continues to work.
- Unsupported preview fails deterministically through the worker task.
