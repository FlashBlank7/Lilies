# design_platform_harness_secret_policy_v1

## 1. Goal

Add a Platform Harness hard boundary that blocks explicit secret fields before model/tool workflows execute external actions or record sensitive metadata.

## 2. Module Boundary

In scope:

- `platform/backend/src/agent_platform/config.py`
- `platform/backend/src/agent_platform/api.py`
- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/runtime.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`
- `tests/test_workflow.py`
- `tests/test_runtime.py`
- `tests/test_factory.py`

Out of scope:

- Secret storage service.
- Secret reference injection.
- Secret rotation.
- Egress policy.
- High-recall scanning of arbitrary natural-language strings.

## 3. Control Flow

```text
AgentRuntime._execute_tool()
  -> PlatformHarness.enforce_secret_policy(surface="agent_tool:<tool>", payload=tool_input)
  -> permission flow
  -> tool.started event
  -> tool.execute()

WorkflowRuntime._execute_tool()
  -> resolve tool input
  -> PlatformHarness.enforce_secret_policy(surface="workflow_tool:<tool>", payload=resolved_input)
  -> tool usage accounting
  -> tool.started event
  -> tool.execute()

WorkflowRuntime._http()
  -> resolve headers/query/body
  -> PlatformHarness.enforce_secret_policy(surface="http:<host>", payload={headers, query, body})
  -> httpx request
```

## 4. Implementation Plan

1. Add `platform_harness_secret_policy_enabled`, default `True`.
2. Add secret field markers:
   - `api_key`
   - `secret`
   - `token`
   - `password`
   - `credential`
   - `authorization`
   - `cookie`
3. Add recursive dict/list scanner in `PlatformHarness`.
4. Wire scanner before permission/tool events in `AgentRuntime`.
5. Wire scanner before tool/http external execution in `WorkflowRuntime`.
6. Add regression test with HTTP `Authorization` header.

## 6. Risks

- Field-name scanning can false-positive on benign fields named `token` or `authorization`.
- It does not catch secrets embedded in ordinary strings such as Bash commands.
- A real secret store is still required for production secret injection.

## 7. Acceptance Criteria

- Explicit secret fields are blocked before external execution.
- Failed workflow run reports a clear `secret policy blocked` error.
- Existing runtime/factory tests pass with the new harness dependency.
- Full backend pytest passes.
