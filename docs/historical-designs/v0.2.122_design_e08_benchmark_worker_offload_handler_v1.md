# v0.2.122 E08 Benchmark Worker Offload Handler Design

## Source

- Source stage report: `docs/stage-reports/v0.2.121_e08_remaining_sidecar_slice_reselection.md`
- Source task: `Implement benchmark worker offload handler`
- Current version: `v0.2.122_e08_benchmark_worker_offload_handler`
- Status: completed

## Problem

`benchmark` is a required Platform Harness worker task kind, but the worker catalog still treats it as unavailable. Existing benchmark evaluation is deterministic and already has API/harness task semantics, so it can be migrated into the worker runner without model calls.

## Boundary

- Do not change benchmark scoring semantics.
- Do not remove or replace the API `/builder-benchmark/evaluate` and `/builder-benchmark/suites/evaluate` paths.
- Do not implement `builder_build` worker offload in this slice.
- Do not claim full Platform Harness sidecar completion.

## Final Scheme

Add `benchmark_handler()` that:

- accepts queued `benchmark` tasks with exactly one of `case_payload` or `suite_payload`;
- validates payloads with existing benchmark Pydantic models;
- delegates to existing `BuilderBenchmark.evaluate()` or `evaluate_suite()`;
- records suite `node_execution` usage on the claimed worker task;
- returns the existing report shape in worker result metadata;
- marks failed benchmark reports as failed worker tasks while preserving the report in metadata.

## Acceptance

- A queued passing benchmark case can be claimed and completed by `PlatformHarnessWorkerRunner`.
- A queued failing benchmark suite fails deterministically and preserves report metadata.
- Existing benchmark API paths and history retrieval continue to work.
