## Source

- Final status: completed

## Problem

The adaptive reuse-depth policy existed in backend code after `v0.2.48`, but the canonical E05 experiment runner still lacked an `adaptive` arm. That blocked disciplined live validation and encouraged one-off scripts.

## Boundary

- In scope: canonical runner support for `adaptive`, deterministic test updates, and result JSON fields that explain the adaptive resolution.
- Out of scope: broad experiment framework redesign, benchmark semantics changes, or deadline visibility UI/API work.

## Final Design

- Extend `depth_arms()` with `adaptive`.
- Require the adaptive arm instruction to:
  - call `template_suggestions` with `reuse_depth='adaptive'`,
  - read `effective_reuse_depth` and `policy_reason`,
  - concretize BuildPlan reuse depth before draft mutations.
- Record adaptive-specific evidence in result JSON:
  - `adaptive_resolution`
  - `effective_reuse_depth`
  - `policy_reason`
- Keep `none / shallow / deep` semantics unchanged.

## Acceptance

- Canonical E05 runner accepts `adaptive` without wrappers.
- Deterministic tests cover the four-arm set and adaptive preflight behavior.
- Result JSON is expressive enough for ledgers and reports.

## Evidence

- `scripts/e05_template_reuse_depth_experiment.py`
- `tests/test_e05_template_reuse_depth_experiment.py`
- Verification: `.venv/bin/python -m pytest tests/test_e05_template_reuse_depth_experiment.py -q`

## Remaining Risk

- Runner support alone does not validate the policy; it only enables disciplined live measurement.
