## Archived Design

### 1. Goal

Validate the E05 engineering fix after marketplace templates become Builder-expandable.

The validation must decide whether the E05 result can be marked `已应用`, `验证应用`, or still `未应用`.

### 2. Module Boundary

Primary files:

- `scripts/e05_template_reuse_depth_experiment.py`
- `docs/experiment-status/evidence/`
- `docs/experiment-status/reports/`
- `docs/experiment-status/v0.2_experiment_status.md`

### 3. Data Flow / Control Flow

1. Run deterministic regression tests for marketplace expansion.
2. Run a bounded post-fix E05 validation:
   - ideally rerun the three-arm E05 paid/live comparison;
   - if cost or runtime becomes material, run at least shallow/deep validation with explicit budget and record why full rerun is deferred.
3. Compare against v0.2.38:
   - `template_expand` success count
   - build status
   - benchmark score/pass rate
   - model/tool calls
   - draft node types
4. Generate a concise DOCX validation report if a paid/live rerun executes.
5. Update experiment ledger with `已应用` only if the fix demonstrably resolves the E05 gap; otherwise mark `验证应用` or carry forward.

### 4. Implementation Plan

1. After code tests pass, rerun E05 with a bounded command and a new result path.
2. Summarize before/after metrics.
3. Generate a DOCX report with background, design, result/conclusion, figure/table, evidence chain, and engineering application status.
4. Update the stage report and experiment ledger.

### 5. Acceptance Criteria

- Validation evidence is traceable by path.
- The experiment ledger does not mark E05 `已应用` unless the validation supports it.
- If the validation still fails, the next-stage task is concrete and narrow.
- Full regression tests pass before archive.
