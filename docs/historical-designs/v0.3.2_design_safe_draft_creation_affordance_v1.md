## Problem

v0.3.1 lets users fill the requirement textarea from customer examples, but the primary action still starts the builder team immediately. That is risky for cautious users and awkward for automated usability testing because the create path can trigger model calls through `/builds`.

## Boundary

This design adds a safe front-door action that creates a local application draft through the existing application API but does not call `/api/v1/applications/{id}/builds`. It does not replace the normal builder path and does not claim the workflow is built or validated.

## Solution

Add a secondary action to the existing create form:

- primary action remains `start builder team`,
- secondary action saves the selected/freeform requirement as a local draft only,
- the UI explains that this does not launch the builder team,
- the saved draft navigates to the existing application detail route,
- auth, error, and busy states reuse the existing frontend API path.

## Acceptance Criteria

- Home page exposes a safe draft-only action beside the normal build action.
- The safe action calls only `POST /api/v1/applications`.
- The safe action does not call `POST /builds`.
- The saved application can be opened in the application detail page.
- TypeScript check passes.
- v0.3.2 harness verifies the bounded flow.
