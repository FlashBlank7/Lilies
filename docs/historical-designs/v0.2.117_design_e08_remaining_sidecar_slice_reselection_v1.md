# v0.2.117 E08 Remaining Sidecar Slice Reselection Design

## Source

- Source stage report: `docs/stage-reports/v0.2.116_e08_workflow_run_worker_offload_handler.md`
- Source task: `Re-select remaining E08 sidecar slice`
- Current version: `v0.2.117_e08_remaining_sidecar_slice_reselection`
- Status: completed

## Problem

v0.2.116 closed the core `workflow_run` worker offload handler, but the Platform Harness sidecar still has multiple open worker-owned execution and operations slices. The next version must choose one concrete implementation target without reselecting completed work.

## Boundary

- Do not implement the selected slice in v0.2.117.
- Do not reselect completed workflow_run, scheduler_trigger, heartbeat registry, handler catalog, stdio/container egress, secret rotation, policy controls, Studio controls, or runbook lifecycle.
- Do not claim full Platform Harness sidecar completion.
- Do not use `docs/workingon/` as the source of next tasks.

## Final Scheme

Add a deterministic selector script that:

- records completed E08 sidecar slices with evidence paths;
- lists remaining concrete candidates;
- scores candidates by sidecar criticality, readiness, product value, testability, and scope risk;
- emits JSON and summary evidence for archive;
- selects exactly one next implementation slice and its first design path.

## Acceptance

- The selector chooses a concrete next implementation slice.
- `workflow_run_worker_offload_handler` and prior completed slices are preserved as completed and excluded.
- Full sidecar completion remains explicitly false.
- The next version and first design path are emitted by the selector.

Completed in v0.2.117.
