# v0.2.115 E08 Remaining Sidecar Slice Reselection Design

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.114_e08_scheduler_trigger_worker_offload_handler.md`
- Source task: `Re-select remaining E08 sidecar slice`
- Current version: `v0.2.115_e08_remaining_sidecar_slice_reselection`
- Status: completed

## Problem

v0.2.114 closed the `scheduler_trigger` worker offload handler, but the Platform Harness sidecar still has multiple open slices. The next version must choose one concrete implementation target without reselecting completed work.

## Boundary

- Do not implement the selected slice in v0.2.115.
- Do not reselect completed scheduler_trigger, heartbeat registry, handler catalog, stdio/container egress, secret rotation, policy controls, Studio controls, or runbook lifecycle.
- Do not claim full Platform Harness sidecar completion.
- Do not use `docs/workingon/` as the source of next tasks.

## Final Scheme

Add a deterministic selector script that:

- lists completed E08 sidecar slices with evidence paths;
- lists remaining concrete candidates;
- scores candidates by sidecar criticality, readiness, product value, testability, and scope risk;
- selects exactly one next implementation slice;
- emits JSON and summary evidence for archive.

## Acceptance

- The selector chooses a concrete next implementation slice.
- `scheduler_trigger_worker_offload_handler` is preserved as completed and excluded.
- Full sidecar completion remains explicitly false.
- The next version and first design path are emitted by the selector.

Completed in v0.2.115.
