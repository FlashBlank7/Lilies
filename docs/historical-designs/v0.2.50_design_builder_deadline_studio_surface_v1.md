## Problem

Even after the API exposed deadline data, Studio still had no place to set or inspect whole-build deadline behavior. Operators could not see one of the most important convergence controls created by recent E05 and build-watchdog work.

## Boundary

- In scope: Studio build-panel input for optional build deadline configuration and active deadline status rendering.
- In scope: frontend typing and validation for the normalized deadline payload.
- Out of scope: live countdown timers, editing deadlines on already-running builds, or broader monitor analytics.

## Final Design

- Extend the local `Build` type with raw and normalized deadline fields.
- Add an optional numeric input for `max_elapsed_seconds` in the Studio build tab.
- Validate operator input before build creation and send the value only when present.
- Render a concise deadline status line in the active build status area.
- Add bilingual copy so the UI remains readable in both locales.

## Acceptance

- An operator can start a build with a deadline from Studio.
- The active build status shows whether a deadline is enabled and its configured value.
- Frontend typing remains clean after the UI/API contract change.
