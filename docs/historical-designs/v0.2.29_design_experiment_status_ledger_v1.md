## 1. Problem

Experiment progress has often been mixed with engineering progress. The user explicitly requires that original backlog items be closed only when experiments are truly completed, and that applied experiments carry explicit markers.

## 2. Design Goal

Goal:

- Update `docs/experiment-status/v0.2_experiment_status.md` for v0.2.29.
- Add the new DOCX reports and raw evidence paths.
- Preserve the distinction between partial evidence, applied experiment, verified application, deferred work, and true closure.

Non-goals:

- Do not rewrite the full backlog history.
- Do not move old reports.
- Do not promote ordinary experiment notes to intellectual assets.

## 3. Module Boundary

- `docs/experiment-status/v0.2_experiment_status.md`: authoritative v0.2 experiment ledger.
- `docs/experiment-status/backlogs/experiment_backlog_lilies_inspiration_notes_2026_07_08.md`: original backlog reference.
- `docs/stage-reports/v0.2.29_formal_experiment_tranche.md`: archive summary.

## 4. Data Flow

DOCX report paths + raw evidence paths + result classification -> experiment ledger update -> stage report evidence table.

## 7. Risks

- A ledger that lists a report as completed may be mistaken for backlog closure. The table must make the distinction explicit.
- If reports are not applied to engineering, they should not receive `已应用` labels.

## 8. Acceptance Criteria

- Ledger latest stage is v0.2.29.
- E01/E02/E04/E05/E08 have updated evidence paths and honest status.
- New reports are listed without false `已应用` markers.
- Stage report links back to the ledger.

## 9. No Next-stage Authority

This design expands one accepted v0.2.29 task only. It does not select or prioritize future stages.
