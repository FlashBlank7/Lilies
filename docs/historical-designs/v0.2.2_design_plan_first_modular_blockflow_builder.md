# design_plan_first_modular_blockflow_builder

## 1. Goal

把“复杂问题前先 plan”的工作方式产品化，让 Builder Team 在搭建复杂 BlockFlow 前先形成可审阅 `BuildPlan`，再用受控工具逐步落到 `WorkflowSpec`。

Status: implemented as v1 on 2026-07-08.

## 2. Module Boundary

候选模块：

- `builder.py`：新增 plan-first 指令和工具。
- `workflow_models.py`：可能新增 `BuildPlan` / `BuildModule`。
- `template_store.py`：支持模块级模板建议。
- `workflow_runtime.py`：保持执行语义不变。

## 3. Control Flow

用户需求 -> Builder Team 生成 BuildPlan -> 按模块生成子 BlockFlow -> 每个模块测试 -> 模块封装为可复用子图 -> 组装完整 WorkflowSpec -> 全局测试。

## 4. Implementation Plan

第一阶段已做轻量落地：

1. 增加 `BuildPlan` / `BuildPlanModule`，不改变 draft mutation 工具。
2. Builder prompt 要求复杂需求先创建模块计划。
3. 新增 `build_plan` tool，支持 set/get/update_module。
4. 增加 focused test 验证计划持久化。

第二阶段再考虑新增 plan-to-draft API、模块级测试汇总和自动模块组装。

## 5. Acceptance Criteria

- Builder Team 对复杂需求有显式模块计划。
- 单步 mutation 审计链保留。
- E01 可以比较 plan-first 和当前流程。
