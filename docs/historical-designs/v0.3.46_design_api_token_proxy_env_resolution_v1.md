## Problem

The frontend can appear connected through `/health`, then later ask for an API token when a protected `/api/v1/...` call or EventSource route returns 401. The Next.js proxy currently falls back to `process.env.API_TOKEN` and then `change-me`; if the frontend process does not inherit the root `.env` token, protected requests fail mid-flow.

## Boundary

- Fix the server-side proxy token resolution path only.
- Do not expose `.env` contents to client bundles.
- Preserve browser-provided token priority for explicit overrides.
- Preserve backend token enforcement.

## Proposed Solution

- Add server-side root `.env` discovery to the Next.js proxy.
- Search upward from the frontend process cwd so both repo-root and `platform/frontend` launches work.
- Resolve token priority as browser token, process env token, local `.env` token, then `change-me`.
- Keep `frontend_token` stripped from the forwarded query.

## Acceptance Criteria

- Proxy source contains a local `.env` API token reader.
- Browser token still has priority.
- `frontend_token` is not forwarded to backend query strings.
- No token is introduced into client-side code.
