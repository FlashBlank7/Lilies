## Problem

E08 now has evidence for controls, runbook, stdio/container egress, local and provider-backed secret envelopes, handler coverage, heartbeat, worker offload handlers, supervision, distributed queue semantics, and external process lifecycle. The project must not declare full sidecar completion by momentum; it needs a generated audit that maps every required surface to evidence and separates optional deployment claims.

## Required Evidence Surfaces

- sidecar/passmode comparison
- editable policy-controls API
- Studio editable controls
- operator runbook lifecycle
- stdio/container egress allowlist
- local KMS/rotation-grade envelope
- complete handler catalog
- durable worker heartbeat registry
- required worker task-kind execution coverage
- production worker supervision
- storage-backed distributed queue semantics
- local external worker process manager
- external KMS provider integration contract

## Decision Contract

The audit must return:

- `full_sidecar_completion_claimed=true` only if all required surfaces have versioned evidence.
- `cloud_provider_deployment_claimed=false` because cloud deployment is not proved by current local provider evidence.
- `remaining_required_gaps=[]` if no required surface is missing.
- `optional_followups` for cloud-specific KMS clients or operational hardening that are not blockers.

## Completion Criteria

- Audit script exists and writes JSON/Markdown evidence.
- Tests assert all required evidence exists.
- Tests assert cloud provider deployment remains unclaimed.
- Tests assert E08 can be marked completed with bounded productization.
