## Problem

Recent evolution created many tiny versions with only one historical design. That makes version advancement too cheap and hides incomplete stage scope.

## Boundary

- In scope: version advancement gate and one-design smell check.
- Out of scope: mechanically merging previous versions.

## Final Design

Before archiving, a version must justify why it is a serious closure unit. Valid closure usually requires multiple coordinated designs, a vertical product slice, full experiment closure, a platform boundary slice, or a P0 process/architecture repair. If a version has only one historical design, it must justify the exception. Repeated one-design versions trigger consolidation or process repair.
