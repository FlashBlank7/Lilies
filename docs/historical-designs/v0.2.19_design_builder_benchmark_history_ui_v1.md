# design_builder_benchmark_history_ui_v1

## 1. Goal

Expose existing Builder benchmark history records in Studio so maintainers can inspect benchmark task outcomes without using raw API calls.

## 2. Module Boundary

Frontend:

- `platform/frontend/app/applications/[id]/page.tsx`
- `platform/frontend/lib/platform.ts`
- `platform/frontend/lib/i18n.ts`
- `platform/frontend/app/globals.css`

Backend:

- Reuse existing `GET /api/v1/builder-benchmark/history`.

No benchmark execution changes are included in this version.

## 3. Data Flow / Control Flow

1. Studio loads or refreshes benchmark history from `/builder-benchmark/history?limit=50`.
2. The Monitor tab displays recent benchmark records separately from generic Platform Harness tasks.
3. Each record shows status, owner, resource, score/pass-rate metadata if present, usage counts, timestamps, and errors.

## 4. Implementation Plan

1. Add `BuilderBenchmarkHistoryRecord` frontend type.
2. Add React state and refresh function for benchmark history.
3. Load benchmark history during page initialization and after monitor refresh.
4. Add a benchmark history panel to the Monitor tab.
5. Add i18n strings and CSS.

## 5. Acceptance Criteria

- Studio fetches benchmark history through the existing API. Completed.
- Monitor tab shows an empty state if no benchmark records exist. Completed.
- Records show score/pass-rate metadata when available. Completed.
- TypeScript check passes. Completed.
- No benchmark run is triggered by viewing history. Completed.
