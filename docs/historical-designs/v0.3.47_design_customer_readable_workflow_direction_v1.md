# design_v0347_customer_readable_workflow_direction

Status: completed

## Source

- Source stage report: `docs/stage-report-archives/v0.3.x/v0.3.46_api_token_proxy_env_resolution.md`
- User product correction:
  - Non-technical users need to understand the workflow without inspecting bricks.
  - End users need a customer-facing run interface with simple input, progress, and result.
  - v0.3.x should focus on customer-designed interface.

## Problem

The app still over-emphasizes structure checks, raw bricks, and generic validation. For a user like a Japanese-language student, the primary question is "what does this workflow do, what do I enter, what step is running, and what result did I get?"

## Boundary

- v0.3.47 creates the first readable workflow summary in the edit experience and sets the handoff for a dedicated customer run interface.
- Do not claim the full customer run UI is complete in this slice.

## Proposed Solution

- Add a workflow-readable summary near the workflow edit surface.
- Summarize the workflow requirement and visible step sequence in natural language.
- Add stage-report handoff for a customer-facing run interface as the next stage.

## Acceptance Criteria

- Edit tab contains a non-brick workflow summary section.
- Summary lists workflow purpose and process steps.
- Next-stage task set prioritizes customer-facing workflow run interface.

## Final Evidence

- Implemented first readable workflow summary in `platform/frontend/app/applications/[id]/page.tsx` with `data-workflow-readable-summary="natural-language"`.
- Verified source, i18n, style, and preview behavior in `tests/test_v03_47_natural_language_workflow_edit.py`.
- Full customer-facing run interface remains the explicit next-stage target in `docs/stage-report-archives/v0.3.x/v0.3.47_natural_language_workflow_edit.md`.
