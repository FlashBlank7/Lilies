# design_readable_test_frames_and_feedback_repair

## 1. Goal

让 BlockFlow 测试结果从“难读 JSON”升级为“可读测试框架 + 可定位失败原因 + 可作为后续修复输入”的结构。

Status: implemented on 2026-07-08.

## 2. Module Boundary

涉及模块：

- `platform/backend/src/agent_platform/workflow_models.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`
- `platform/backend/src/agent_platform/builder.py`
- focused tests under `tests/`

不涉及：

- 前端 UI 重构。
- 自动修复算法。
- 发布门禁语义改变。

## 3. Data Flow

`WorkflowTestCase.frame` -> Builder Team 创建测试时写入可读元信息 -> `WorkflowRuntime.run_test_suite()` 执行测试 -> 每个 test result 输出 `frame` 和 `readable_report` -> 后续 UI 或 repair loop 可使用 failure target 和 feedback hints。

## 4. Implementation Plan

1. 新增 `TestFrameSpec`，描述测试标题、类别、目标、审阅指引、参考依据和失败定位目标。
2. 在 `WorkflowTestCase` 增加：
   - `frame`
   - `feedback_hints`
3. 清理 `WorkflowTestCase` 中重复声明的字段。
4. 在 `run_test_suite()` 的单项结果中输出：
   - `frame`
   - `readable_report`
5. 在总报告中输出 `summary`。
6. 更新 Builder prompt 和 `test_add` tool 描述，要求创建测试时写入 frame。
7. 增加 focused tests。

## 5. Acceptance Criteria

- 旧测试格式仍兼容。
- 新测试可以带 `frame`。
- `run_test_suite()` 返回的每个测试结果包含可读字段。
- 总报告包含 summary。
- focused tests 通过。

## 6. Referenced Assets

- `docs/intellectual-assets/asset_blockflow_language_system.md`
- `docs/intellectual-assets/asset_platform_harness_task_monitor_boundary.md`

## 7. Risks

- 这一步只创建修复输入结构，不实现自动修复。
- 如果 UI 仍只展示 raw JSON，用户体验改善需要前端后续接入。
