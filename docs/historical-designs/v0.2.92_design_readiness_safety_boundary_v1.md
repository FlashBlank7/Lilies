## Problem

A readiness decision can overstate product safety if it ignores rollback, unknown bypass, or request override evidence.

## Boundary

- Readiness must explicitly verify rollback value `disabled`.
- Unknown requirements must remain bypassed and counted.
- Request overrides must remain visible before any broader rollout is selected.

## Design

- Readiness gates fail closed.
- The decision summary must distinguish current explicit limited-default availability from broader default rollout.
- The next stage must preserve rollback-to-disabled in its closure target.

## Acceptance

- Gate evidence includes rollback value, unknown count, bypassed count, and request override count.
- The stage report states that normal settings remain disabled in v0.2.92.
