# v0.2.106 E08 Stdio Container Egress Allowlist Contract Design

## Source

- Source task: `Implement stdio/container egress allowlist contract`
- Current version: `v0.2.106_e08_stdio_container_egress_allowlist_contract`

## Problem

Stdio MCP servers previously could not participate in allowlist-grade policy because they did not declare hostnames. The old safe behavior blocked allowlist stdio before process start. The selected E08 slice now needs a real contract that allows sandboxed stdio only when its egress hosts are explicit and covered by allowlists.

## Boundary

- Do not treat a container environment variable as sufficient enforcement by itself.
- Do not allow unsandboxed allowlist stdio.
- Do not allow stdio allowlist when `egress_hosts` is empty.
- Do not claim full Platform Harness sidecar completion.

## Final Scheme

Add `egress_hosts` to `MCPServerSpec`. Platform Harness allows stdio MCP under allowlist policy only when:

- stdio execution is sandboxed;
- agent and sandbox network policies are both `allowlist`;
- declared `egress_hosts` is non-empty;
- every declared host is covered by the agent allowlist;
- if platform policy is `allowlist`, every declared host is also covered by the platform allowlist.

Otherwise the tool is blocked before execution.

## Acceptance

- Sandboxed stdio with covered declared hosts is allowed.
- Sandboxed stdio with unlisted declared host is blocked.
- Sandboxed stdio with missing declared hosts is blocked.
- Policy-controls API reports allowlist stdio support with an allowed sandboxed scenario.
