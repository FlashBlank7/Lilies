## 1. Problem

v0.2.29 paid/live evidence showed a candidate BlockFlow with an `answer` terminal node while the reference benchmark required `end`. Runtime validation already treats both as terminal nodes, but Builder benchmark node-type coverage does not.

The fix must avoid overclaiming: `answer` is terminal-equivalent to `end` for graph-shape coverage, but it is not always output-contract-equivalent because `end` returns named outputs and `answer` returns an `answer` field.

## 2. Design Goal

Goal:

- Treat `answer` as an alias for required `end` in BuilderBenchmark node-type coverage.
- Preserve existing model node equivalence `model_turn -> llm`.
- Add deterministic regression tests that make the equivalence explicit.

Non-goals:

- Do not claim Builder tests are now passing.
- Do not change `WorkflowRuntime` terminal output semantics.
- Do not rewrite Builder prompts in this stage.

## 3. Module Boundary

- `platform/backend/src/agent_platform/builder_benchmark.py`
- `tests/test_workflow.py`

## 4. Control Flow

Benchmark evaluate request -> collect candidate node types -> merge default equivalence map -> required `end` is satisfied by candidate `answer` -> missing node types excludes `end` -> report exposes the equivalence in `metrics.node_type_equivalences`.

## 5. Implementation Plan

1. Add `end: ["answer"]` to `DEFAULT_NODE_TYPE_EQUIVALENCE`.
2. Add a focused API-level test where reference uses `end`, candidate uses `answer`, and required node types include `end`.
3. Assert the report passes, missing node types are empty, node type coverage is `1.0`, and metrics expose `end -> answer`.
4. Run the new test and the existing benchmark equivalence test.

## 7. Risks
