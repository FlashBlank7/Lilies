# design_platform_harness_secret_runtime_injection_v1

## 1. Goal

Resolve secret reference objects only at execution boundary for HTTP and tool payloads.

## 2. Module Boundary

Backend runtime:

- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`
- `platform/backend/src/agent_platform/runtime.py`

Tests:

- `tests/test_workflow.py`

## 3. Data Flow / Control Flow

1. Workflow config contains a secret reference object such as `{"$secret": "api_token"}`.
2. Existing secret policy allows the reference object but still blocks inline secret-looking plaintext values.
3. Runtime resolves references immediately before HTTP/tool execution using the relevant owner id.
4. The raw value is passed only to the actual call.
5. Events use the existing redaction path and should not expose injected values.

## 4. Implementation Plan

1. Add secret-reference detection to Platform Harness.
2. Add async recursive `inject_secret_references(owner_id, payload)` helper.
3. Update workflow HTTP and tool execution to enforce policy before injection, then inject before execution.
4. Update agent tool execution path to support secret references with session agent owner where available.
5. Keep missing references as explicit Platform Harness violations.

## 5. Acceptance Criteria

- HTTP headers can be built from secret references. Completed.
- Tool payloads can be built from secret references. Completed.
- Missing references fail clearly. Completed.
- Inline secret-looking plaintext is still blocked. Completed.
- Redacted event output does not leak values. Completed for tested HTTP path.
