## Problem

v0.2.62 made the stage-report template mandatory going forward, but older reports remained heterogeneous. The project needed an explicit decision rather than silent drift.

## Boundary

This design audits and decides. It does not rewrite historical reports. Any bulk migration must be selected by a future stage report.

## Final Design

- `scripts/audit_stage_report_template_adoption.py` audits recent `docs/stage-reports/v*.md` files.
- The audit reuses the canonical mandatory section validator.
- The recommendation distinguishes:
  - no reports found,
  - latest report failed and a migration/repair plan is needed,
  - latest report conforms while older reports remain historical,
  - all recent reports conform.
- v0.2.63 records `forward_only_keep_historical_reports_as_is` for the recent history audit.

## Acceptance

- Audit script runs without mutating stage reports.
- Tests cover latest-conforming historical mismatch and latest-failing repair-plan cases.
- v0.2.63 records the migration decision in evidence and stage report.

## Remaining Risk

- v0.2.55 through v0.2.61 remain non-template historical artifacts by decision.
- A future migration stage can still be selected if uniform historical reports become operationally necessary.
