# design_v0.2.34_required_mode_rerun_v1

## Goal

Re-run only the complex required-mode arm with a larger, bounded repair budget to test whether v0.2.33 failed because the experiment allowed too little repair.

## Experiment Design

Command:

```bash
LIVE_BUILDER_BENCHMARK_CASE=complex_research_brief \
LIVE_BUILDER_BENCHMARK_PLANNING_MODE=required \
LIVE_BUILDER_BENCHMARK_MAX_TURNS=60 \
LIVE_BUILDER_BENCHMARK_MAX_REPAIR_CYCLES=3 \
LIVE_BUILDER_BENCHMARK_TIMEOUT_SECONDS=1500 \
LIVE_BUILDER_BENCHMARK_RESULT_PATH=docs/experiment-status/evidence/experiment_v0.2.34_e01_complex_required_repair_budget_2026_07_09.json \
.venv/bin/python scripts/live_builder_benchmark_suite.py
```

## Metrics

Compare against v0.2.33 required:

- build status
- build error
- benchmark score/pass_rate
- draft node/edge/test counts
- model/tool calls
- build_plan calls
- max repair cycles
- duration

## Acceptance Criteria

- The rerun produces a raw JSON evidence file.
- A summary JSON compares v0.2.33 required vs v0.2.34 required.
- The experiment ledger is updated without closing E01 unless readiness is actually achieved.
- If readiness improves, mark the experiment infrastructure change as applied to the experiment method, not as a Builder product fix.

## Final Status

- Status: completed as repair-budget experiment slice; original E01 not closed.
- Evidence:

- Engineering application: verified and applied to experiment method only; no Builder product capability was changed from this result.
- Remaining risk: next stage must make required mode satisfy both readiness and required architecture coverage.
