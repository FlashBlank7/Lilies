# design_e05_case_runner_scope_controls

## Problem

`v0.2.46` needed a one-off deep-only wrapper because `scripts/e05_template_reuse_depth_experiment.py` always runs `none` / `shallow` / `deep` together. That makes stage-scoped reruns clumsy and encourages ad hoc scripts outside the canonical experiment path.

## Boundary

- In scope: runner-level scope control for E05 arms, deterministic tests, and keeping result semantics compatible with existing ledgers/summaries.
- In scope: selecting a subset of `none` / `shallow` / `deep` without changing the meaning of each arm.
- Out of scope: changing the benchmark scoring model, result schema rewrite, or broad experiment framework generalization.

## Solution

Add first-class arm scoping to `scripts/e05_template_reuse_depth_experiment.py` so the canonical runner can execute only the requested subset, for example `deep` only or `none,shallow`.

## Implementation Plan

1. Add environment-based arm filtering with explicit validation of allowed values.
2. Keep the default behavior unchanged when no scope is provided.
3. Ensure preflight, budget metadata, summaries, and result JSON reflect the selected arm set.
4. Add deterministic tests for:
   - default full-arm behavior,
   - filtered deep-only behavior,
   - invalid arm values.

## Acceptance

- The E05 runner can execute `deep` only without an external wrapper.
- Existing full-run behavior remains unchanged by default.
- Script tests cover the new scope-control behavior.
