## Problem

Failed runs may expose an error in raw JSON, but users need a short error summary and a clear connection to the existing recovery guidance.

## Boundary

- Display only.
- No retry, resume, cancel, run, build, test, version, draft, or model calls.
- Do not hide the raw error payload.

## Solution

- Add `tryResultErrorPreview`.
- Render an error preview when `run.error` exists or status is `failed`.
- Pair the preview with existing `tryResultNextAction`.
- Use `data-try-result-error-preview`.

## Acceptance Criteria

- Failed runs show an error preview before raw JSON.
- Missing error text shows a fallback unknown-error message.
- Recovery next action remains visible.
- Harness verifies no mutation behavior.

## Final State

- Implemented `tryResultErrorPreview`.
- Added `data-try-result-error-preview`.
- Added readable error summary and unknown-error fallback before raw JSON.
- Preserved existing recovery next action and raw payload visibility.
