## Problem

Worker handlers and heartbeat evidence are complete, but there is no product-level supervision surface that can start, observe, and stop worker execution. Operators still have low-level runner and heartbeat primitives rather than an explicit supervised lifecycle.

## Proposed Slice

Add an in-process Platform Harness worker supervisor that owns a `PlatformHarnessWorkerRunner` loop, records lifecycle heartbeats, exposes a deterministic snapshot, and supports start/stop without claiming external process management.

## Acceptance

- Supervisor can start a worker loop.
- Supervisor can observe desired state, task state, heartbeat/liveness, and recent run results.
- Supervisor can stop the worker loop and return to idle evidence.
- Supervisor records that this is in-process supervision, not a distributed queue or external process manager.
