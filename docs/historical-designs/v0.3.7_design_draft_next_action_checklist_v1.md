## Problem

Users need to know whether they should inspect, edit, test, try, publish, or monitor. The existing readiness cards show state, but they do not turn state into immediate actions.

## Boundary

Do not introduce a new workflow state machine. Derive actions from existing local variables: draft presence, canvas node/edge counts, tested hash, published version, run input validity, and monitor summary.

## Solution

Add a next-action checklist that:

- derives status from existing draft/test/run/publish data,
- gives each item a direct target tab,
- highlights the next unfinished action,
- keeps no-build behavior unless the user explicitly chooses the build tab and starts the team.

## Acceptance Criteria

- Checklist exists in the detail view with stable `data-next-action` markers.
- Items navigate to existing tabs rather than new pages.
- Checklist covers inspect, build/edit, acceptance, try-run, publish, and monitor states.
- Focused tests verify markers and no-build boundaries.

- Frontend source diff.
- Source marker tests.
- Persona harness evidence.
