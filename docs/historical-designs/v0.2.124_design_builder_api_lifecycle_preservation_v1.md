## Problem

Existing API build lifecycle evidence must remain valid. The new worker path should not change API-created build status transitions, harness task id, deadline metadata, events, or publish behavior.

## Boundary

- `Builder.start()` continues to schedule an internal async build.
- `_run(..., manage_harness_task=True)` remains the API-owned default.
- Worker-owned builds use `_run(..., manage_harness_task=False)` only after an external worker task has been queued and claimed.

## Acceptance

- API build smoke test still publishes.
- Worker build task does not call `harness.start_task()` a second time.
- Worker-created build events remain visible under the build id stream.
