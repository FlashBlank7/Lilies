## Problem

v0.2.61 provided manual adaptive monitoring refresh and append-only history, but it did not provide a scheduler hook or deterministic operator surface for scheduled/manual-run refreshes.

## Boundary

The hook records the existing deterministic monitoring snapshot only. It does not regenerate paid/live benchmark evidence, call providers, mutate templates, or select future tasks.

## Final Design

- `adaptive_monitoring_refresh_interval_seconds` controls automatic refresh scheduling and defaults to `0.0`.
- FastAPI lifespan starts a named `adaptive-monitoring-refresh-loop` background task only when the interval is positive.
- Refresh history records include `trigger`, distinguishing `manual`, `manual_schedule_run`, and `scheduled`.
- Operators can inspect schedule state with `GET /api/v1/templates/adaptive-monitoring/schedule`.
- Operators can deterministically append one scheduled-style record with `POST /api/v1/templates/adaptive-monitoring/schedule/run-once`.

## Acceptance

- Default settings do not start background adaptive monitoring refresh work.
- Manual scheduled run appends history with `trigger=manual_schedule_run`.
- Direct manual refresh remains backward compatible and records `trigger=manual`.
- Positive interval starts a named background task in API lifespan.
- Focused backend tests pass.

## Remaining Risk

- Automatic scheduling is default-off and requires operator configuration.
- The scheduled hook stores current deterministic snapshot status; paid/live evidence regeneration remains out of scope.
