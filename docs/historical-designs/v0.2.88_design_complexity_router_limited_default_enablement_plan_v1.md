# design_complexity_router_limited_default_enablement_plan

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.87_complexity_router_default_enablement_review_decision.md`
- Source task: `Create complexity-router limited default enablement plan`
- Version target: `v0.2.88_complexity_router_limited_default_enablement_plan`

## Problem

v0.2.87 selected default enablement review, but runtime defaults must not be changed until a limited default scope, controls, rollback, API/config contract, and verification gates are explicit.

## Boundary

- Define the implementation plan only.
- Do not enable complexity-router defaults in this version.
- Keep unknown/underspecified requirements conservative.
- Require a later stage report to implement and verify any runtime default change.

## Design

- Define limited default scope: simple/medium/complex classification may provide default builder policy, while unknown remains complex-equivalent.
- Define config contract with a disabled default mode and explicit limited-default mode.
- Define API contract for surfacing current default mode and rollback status.
- Define operator rollback controls that can immediately return to disabled/shadow behavior.
- Define verification gates for safety, rollout metrics, frontend verification, and fallback handling.

## Acceptance

- Generated plan records scope, config/API contract, rollback, and verification gates.
- Tests verify default remains disabled in the plan version.
- Tests verify limited default implementation is carried to a later version.

## Status

Completed in v0.2.88.
