## Source

- Source stage report: `docs/stage-reports/v0.3.9_build_action_cost_guard.md`
- Source tasks:
  - `Extend regression to cover i18n key completeness for new UI states`

## Problem

Recent frontend usability work adds many UI states and bilingual copy. Missing keys would break non-technical user paths, especially when TypeScript checks are blocked.

## Boundary

Use a focused static check over current frontend pages and the i18n catalog. Do not attempt full TypeScript parsing in this stage.

## Solution

- Extract `t.<key>` references from home and detail pages.
- Extract top-level keys from the `zh` and `en` message catalogs.
- Fail if any referenced key is missing from either locale.
- Fail if `zh` and `en` top-level key sets drift.

## Acceptance Criteria

- Guard-related keys are present in both locales.
- Current home/detail references resolve in both locales.
- The check can run without Node/npm.

## Evidence Requirements

- v0.3.10 JSON evidence.
- Focused tests.
