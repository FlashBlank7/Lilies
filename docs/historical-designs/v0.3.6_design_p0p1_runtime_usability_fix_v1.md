## Problem

v0.3.x is a usability buffer version. A triage stage should not stop at auditing; it must convert the first severe runtime or usability issue into a concrete product fix.

## Candidate Bug

Initial code inspection found that `create_app()` still exposes FastAPI version `0.2.0`. For a project now in v0.3.x, this is a P1 runtime observability bug because operators and automated scripts cannot tell whether they are interacting with the current product surface.

## Boundary

Fix one P0/P1 issue well. Do not bundle unrelated UI rewrites or broad versioning infrastructure into this stage.

## Solution

- Promote runtime identity to a dedicated backend version constant.
- Report product phase and runtime version from `/health`.
- Update tests and evidence so stale runtime labels fail visibly.

## Acceptance Criteria

- The selected P0/P1 bug is fixed.
- Focused tests prove the fix.
- Stage report records the bug, root cause, and evidence.

## Evidence Requirements

- Code diff.
- Focused tests.
- v0.3.6 workingon bug ledger or runtime evidence JSON.
