## Problem

After landing in a safe draft, users need concrete next steps without accidentally starting builder/model work.

## Boundary

- Actions may switch to existing studio tabs only.
- No action may call `/builds`, `/runs`, `/tests/run`, `/versions`, `/restore`, or `/draft`.
- The build-later action may open the build tab, where the existing guard remains in force.

## Solution

- Add safe-draft action buttons for inspect, acceptance, try, and build later.
- Use `setStudioTab` so URL state remains consistent.
- Keep every button `type="button"`.

## Acceptance Criteria

- Handoff actions route only to existing tabs.
- Build-later action does not start build.
- Source markers expose each action target.

## Final State

- Added inspect, acceptance, try, and build-later handoff actions.
- Each action uses `setStudioTab` and `type="button"`.
- Build-later opens the guarded build tab only; it does not call `/builds`.
- Verification is archived in `docs/workingon-archives/v0.3.27/safe_draft_landing_v0.3.27.json`.
