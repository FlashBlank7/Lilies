# v0.2.104 Productization Lane Reselection Design

## Source

- Source stage report: `docs/stage-reports/v0.2.103_e05_scheduled_monitoring_hook.md`
- Source task: `Perform productization lane reselection`
- Current version: `v0.2.104_productization_lane_reselection`

## Problem

After v0.2.103, E05 scheduled monitoring is verified as already productized. The next lane selection must exclude completed/productized lanes and select only genuinely open, unblocked work.

## Boundary

- E05 scheduled monitoring cannot win as open work.
- E07 guarded default cannot win as open work.
- E02/E10 cannot win while blocked.
- E08 full sidecar completion must not be claimed by selection alone.

## Final Scheme

Use a deterministic selector that separates `completed`, `blocked`, and `open` lanes before scoring. Select the highest-scoring open lane and hand off a concrete scope-decomposition version when the lane is too broad for direct implementation.

## Acceptance

- Generated evidence selects an open lane.
- Tests prove completed E05 scheduled monitoring is visible but non-winning.
- Tests prove blocked E02/E10 are visible but non-winning.
- Tests prove E08 full sidecar is not claimed complete.
