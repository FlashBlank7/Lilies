# design_complexity_router_post_operator_opt_in_decision

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.84_complexity_router_operator_opt_in_rollout.md`
- Source task: `Decide post-operator-opt-in rollout path`
- Version target: `v0.2.85_complexity_router_post_operator_opt_in_decision`

## Problem

v0.2.84 completed stage-1 operator opt-in rollout, but default enablement is still unsafe to review while executable frontend verification remains blocked. The next stage must choose whether to repair frontend verification, continue opt-in observation, or begin default enablement review.

## Boundary

- Decide the next productization path only.
- Do not repair Node/npm in this version.
- Do not enable default routing.
- Treat frontend verification as a productization gate, not an incidental blocker.

## Design

- Load v0.2.84 operator opt-in evidence.
- Score options by productization value, safety, evidence readiness, verification readiness, and behavior-change risk.
- Select `repair_frontend_verification_environment` because stage-0 and stage-1 rollout evidence are complete, but default review still lacks frontend verification.
- Reject continued opt-in observation as lower value until the verification blocker is addressed.
- Reject immediate default enablement review because frontend verification remains blocked.

## Acceptance

- Decision evidence selects `repair_frontend_verification_environment`.
- Tests verify selected and rejected alternatives.
- Next stage points to frontend verification environment repair.

## Status

Completed in v0.2.85.
