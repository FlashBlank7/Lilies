## Problem

The policy controls API exposed generic Platform Harness settings, but it did not surface E08's key conclusion: workflow-internal passmode is soft and configurable, while Platform Harness policy is a hard boundary before external actions.

## Boundary

This stage added read-only API visibility. It did not add editable policy controls, new enforcement mechanisms, or full Platform Harness sidecar completion.

## Final Design

- `PlatformHarness.policy_controls()` returns `e08_boundary`.
- `e08_boundary` includes current slice, source evidence, comparison evidence, soft passmode, hard boundary, not-full-sidecar marker, remaining full-boundary items, and current control statuses.
- Existing policy-control fields remain backward compatible.

## Acceptance

- `/api/v1/platform/harness/policy-controls` returns `e08_boundary`.
- The response distinguishes `soft_configurable` passmode from `hard_boundary` Platform Harness policy.
- The response names source evidence and current slice.
- Existing policy-control regression still passes.
