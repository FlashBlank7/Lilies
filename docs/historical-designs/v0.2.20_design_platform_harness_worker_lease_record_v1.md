# design_platform_harness_worker_lease_record_v1

## 1. Goal

Add durable worker lease state to Platform Harness task records and make lease expiry a first-class reconciliation path.

## 2. Module Boundary

Backend:

- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/storage.py`
- `platform/backend/src/agent_platform/config.py`
- `platform/backend/src/agent_platform/api.py`

Tests:

- `tests/test_workflow.py`

## 3. Data Flow / Control Flow

1. A Platform Harness task starts as before.
2. If lease mode is configured or a caller explicitly claims a lease, the task record stores:
   - `worker_id`
   - `lease_expires_at`
   - `lease_version`
3. A worker can renew its lease before expiry.
4. A conflicting worker cannot claim or renew while the existing lease is still valid.
5. Reconciliation scans active task records with expired lease deadlines and marks them failed with lease-expiry metadata.
6. A late success finish after lease expiry is rejected by converting the task to failed instead of succeeded.

## 4. Implementation Plan

1. Extend `PlatformTaskRecord` with lease fields.
2. Add worker lease settings with safe default-off behavior.
3. Add Harness helpers for lease assignment, expiry parsing, conflict detection, and expiry error construction.
4. Add `claim_task_lease()`, `renew_task_lease()`, `release_task_lease()`, and `reconcile_expired_task_leases()`.
5. Add storage support for failing expired lease records by reading persisted JSON records.
6. Ensure `start_task()`, `list_tasks()`, and late `finish_task()` honor expired leases.

## 5. Acceptance Criteria

- Lease fields persist in `platform_harness_tasks.record_json`. Completed.
- A second worker is blocked while an unexpired lease exists. Completed.
- Expired leases are reconciled into failed task records. Completed.
- Late success after expiry does not mark the task succeeded. Completed.
- Existing no-lease Platform Harness tests keep passing. Completed.
