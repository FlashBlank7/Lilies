## Problem

The runner is currently accessible through CLI-like primitives and heartbeat APIs, but operators need a product surface to inspect and control the supervised worker lifecycle.

## API Surface

- `GET /api/v1/platform/harness/worker-supervision`
- `POST /api/v1/platform/harness/worker-supervision/start`
- `POST /api/v1/platform/harness/worker-supervision/stop`

## Acceptance

- Snapshot exposes `desired_state`, `loop_running`, `worker_id`, heartbeat liveness, `run_count`, recent results, and boundary flags.
- Start endpoint idempotently starts an in-process supervised worker loop.
- Stop endpoint idempotently stops the loop and records stop evidence.
