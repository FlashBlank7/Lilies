## Problem

`WorkflowRuntime.run_test_suite()` already owns validation, test iteration, run creation, assertion checks, tool evidence checks, and summary generation. Worker offload must preserve that contract.

## Boundary

- Worker handler starts a test-suite run; it does not synchronously implement assertion evaluation itself.
- The queued worker task remains the test-suite Platform Harness boundary.
- Per-test workflow runs still use existing `origin="test_suite"` semantics.

## Acceptance

- API-created test-suite tasks continue to be managed by `run_test_suite()`.
- Worker-created test-suite tasks use the queued task id as the parent for workflow runs.
- Heartbeat registry records worker lifecycle around the handler.
