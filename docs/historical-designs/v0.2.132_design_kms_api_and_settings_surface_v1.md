## Settings Contract

Add settings that can configure a deterministic local KMS provider:

- `platform_harness_secret_kms_provider`
- `platform_harness_secret_kms_provider_id`
- `platform_harness_secret_kms_key_id`
- `platform_harness_secret_kms_key`
- `platform_harness_secret_kms_previous_keys`

The first provider implementation is local and deterministic because the current codebase has no cloud provider client boundary. This still closes the provider integration architecture slice because Platform Harness no longer owns the wrapping operation directly when provider mode is enabled.

## API Contract

Existing secret APIs remain unchanged:

- `POST /api/v1/platform/secrets`
- `GET /api/v1/platform/secrets`
- secret reference injection via runtime paths

The operator-visible status is exposed through existing policy controls and public secret metadata:

- `policy_controls().secret_storage.kms_provider_configured`
- `policy_controls().secret_storage.external_kms_provider_integration`
- `storage_mode=encrypted_v3:<provider_id>:<key_id>`

## Completion Criteria

- `build_services()` constructs the provider from settings.
- API secret creation stores v3 envelopes under provider configuration.
- No new plaintext leak appears in public API responses.
