## Problem

v0.3.4 indexed smoke applications but could not clean them up. Automatic evolution will keep creating local evidence apps, so the project needs a bounded cleanup mechanism. A generic delete API would be too dangerous.

## Boundary

This design adds only a smoke-cleanup endpoint. It must require an explicit `v0.3.x-smoke` marker, default to dry-run, and reject non-matching applications. It should not delete arbitrary applications.

## Solution

Add `POST /api/v1/applications/{application_id}/smoke-cleanup`:

- request body includes `smoke_marker` and `dry_run`,
- `smoke_marker` must match `v0.3.<n>-smoke`,
- endpoint checks marker in application name/description/requirement,
- dry-run returns the affected related row counts without deleting,
- non-dry-run deletes the application and manually removes draft idempotency records,
- foreign-key cascade handles drafts, versions, builds, runs, and schedule fires.

## Acceptance Criteria

- Dry-run on a matching smoke app reports `deleted: false`.
- Delete on a matching smoke app removes the application.
- Non-matching applications are rejected.
- Focused API tests pass.
- No build/model path is called.
