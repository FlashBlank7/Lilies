## Problem

The platform now has in-process supervision and storage-backed queue semantics, but worker process lifecycle is still not managed as an external process. Operators need spawn/observe/stop/restart semantics for a worker process, not only an in-process coroutine loop.

## Proposed Slice

Add an external worker process manager that owns a configured command and provides deterministic process lifecycle operations:

- start a worker subprocess
- observe pid, running/exited state, return code, timestamps, and command
- stop the worker subprocess gracefully with kill fallback
- restart by stop then start

## Acceptance

- Manager can start/observe/stop/restart a subprocess.
- API exposes process manager snapshot/start/stop/restart.
- Process manager boundary flags keep external KMS and full sidecar completion false.
