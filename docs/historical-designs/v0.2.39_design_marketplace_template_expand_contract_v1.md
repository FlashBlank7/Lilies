## Archived Design

### 1. Goal

Make Builder-facing Template suggestions expandable. If `template_suggestions` recommends a marketplace Template such as `code_reviewer`, then Builder `template_expand` must be able to expand that template into the editable draft.

### 2. Module Boundary

Primary files:

- `platform/backend/src/agent_platform/builder.py`
- `tests/test_workflow.py`

Read-only dependencies:

- `platform/backend/src/agent_platform/template_store.py`
- `platform/backend/src/agent_platform/blocks.py`
- `templates/code_reviewer.json`

### 3. Data Flow / Control Flow

Current failure chain:

1. `template_suggestions` searches `TemplateStore` and recommends marketplace templates like `code_reviewer`.
2. Builder receives an action such as `expand_template`.
3. `template_expand` calls `BlockRegistry.expand_template()`.
4. `BlockRegistry.expand_template()` only knows server-defined templates like `claude_like_coding_agent`.
5. Marketplace template expansion fails or causes the model to work around the gap through expensive delete/rebuild loops.

Target chain:

1. `template_suggestions` recommends marketplace templates.
2. `template_list` exposes both server-defined and marketplace templates with a `source` field.
3. `template_expand` first tries `TemplateStore.expand_into_workflow()` when `name` is a marketplace template.
4. If no marketplace template matches, `template_expand` falls back to `BlockRegistry.expand_template()`.
5. The expanded workflow nodes and edges are inserted through the same draft operation path as before.

### 4. Implementation Plan

1. Update `template_list` in `WorkflowBuilder._execute()`:
   - include `BlockRegistry.template_names()` entries with `source="server_defined"`;
   - include `TemplateStore.list()` entries with `source="marketplace"`;
   - include metadata useful to the model: title, category, tags, confidence.
2. Update `template_expand`:
   - detect marketplace template names through `self.template_store.names()`;
   - expand marketplace templates using `TemplateStore.expand_into_workflow()`;
   - preserve server-defined fallback for `claude_like_coding_agent`;
   - return `source`, template name, revision, nodes, and edges.
3. Keep planning-mode enforcement unchanged.
4. Add regression tests:
   - Builder can expand `code_reviewer` into an editable draft using a scripted provider;
   - Builder can still expand `claude_like_coding_agent`;
   - `template_list` includes marketplace and server-defined entries.

### 5. Acceptance Criteria

- `template_expand(name="code_reviewer")` succeeds inside Builder and adds nodes/edges from `TemplateStore`.
- `template_expand(name="claude_like_coding_agent")` still succeeds.
- Expanded marketplace templates remain editable draft nodes and pass validation.
- Tests prove the contract without paid model calls.
