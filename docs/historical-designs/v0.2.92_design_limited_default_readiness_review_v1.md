# v0.2.92 design: limited default readiness review

## Source

- Source stage report: `docs/stage-reports/v0.2.91_complexity_router_runtime_activation_observability.md`
- Source task: `Perform limited-default product readiness review`
- Version target: `v0.2.92_complexity_router_limited_default_readiness_review`

## Problem

E07 now has runtime activation and observability, but broader product rollout must be selected through an explicit readiness decision instead of silently changing defaults.

## Boundary

- This stage decides the next productization path; it does not change default runtime settings.
- The decision must be evidence-backed by v0.2.90/v0.2.91 runtime activation and metrics evidence.
- The decision must record the next version and first design source.

## Design

- Add a readiness decision generator that reads v0.2.91 metrics evidence.
- Evaluate gates for runtime activation, observability coverage, disabled-default safety, unknown bypass safety, request override visibility, rollback value, and frontend verification.
- Select one of:
  - `enter_guarded_default_rollout`
  - `stay_explicit_only`
  - `collect_more_runtime_evidence`

## Acceptance

- Readiness evidence records every gate and its source.
- If all gates pass, the selected next stage is guarded default rollout.
- If any gate fails, the decision must not broaden default enablement.

## Status

Completed in v0.2.92.
