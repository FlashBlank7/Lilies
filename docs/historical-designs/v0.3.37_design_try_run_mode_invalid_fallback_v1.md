# design_v0337_try_run_mode_invalid_fallback

状态：completed

## Source

- Source stage report: `docs/stage-report-archives/v0.3.x/v0.3.36_try_run_mode_visibility.md`
- Source tasks:
  - `Add persistence fallback safety`

## Problem

localStorage can contain invalid, stale, or manually edited values. Invalid values must not mislabel a result.

## Boundary

- Only `draft` and `published` may be restored.
- Invalid values become `unknown`.
- Storage read/write failures must not break the Try tab.

## Solution

- Add `isRunMode`.
- Wrap localStorage read/write in `try/catch`.
- Keep `unknown` fallback copy visible.

## Acceptance Criteria

- Invalid stored values resolve to `unknown`.
- Storage failures resolve safely.
- Published/draft values remain accepted.

## Final State

- Added `isRunMode`.
- `readStoredRunMode` accepts only `draft` and `published`; invalid, missing, empty, or `unknown` stored values resolve to `unknown`.
- localStorage read/write failures are caught and do not break the Try tab.
