## Problem

Application cards now expose readiness, but demo reviewers and returning consultants still have to scan every card to find drafts, apps needing acceptance, ready-to-publish apps, or published apps.

## Boundary

- Use only existing application list fields.
- No backend endpoint changes.
- Keep filtering compact and source-testable without browser tooling.

## Solution

- Add a status filter state to the home application list.
- Provide filters for all, needs acceptance, ready to publish, and published.
- Show counts and filtered empty state.

## Acceptance Criteria

- Users can filter app cards by readiness state.
- Filtering derives from `tested_hash` and `active_version`.
- Stable `data-app-list-filter` markers exist.
