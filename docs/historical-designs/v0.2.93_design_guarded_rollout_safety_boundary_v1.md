# v0.2.93 design: guarded rollout safety boundary

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.92_complexity_router_limited_default_readiness_review.md`
- Source task: `Preserve rollback-to-disabled and conservative unknown handling`
- Version target: `v0.2.93_complexity_router_guarded_default_rollout`

## Problem

The first broader default rollout can become unsafe if rollback, unknown bypass, or request override behavior is weakened.

## Boundary

- Rollback value remains `disabled`.
- Unknown requirements remain bypassed.
- Request planning-mode overrides remain visible in activation metadata.

## Design

- Keep existing `runtime_activation_for_build()` gate semantics.
- Add tests for explicit disabled rollback and unknown bypass under default rollout settings.
- Keep metrics categories intact.

## Acceptance

- Rollback settings produce `active=false`.
- Unknown input produces `active=false`, `effective_class=complex`, and no runtime builder policy.
- Request override produces `planning_mode_source=request_override`.

## Status

Completed in v0.2.93.
