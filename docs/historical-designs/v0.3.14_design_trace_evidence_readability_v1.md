## Problem

The Run tab shows raw node/tool trace JSON after a run. This is useful for engineers, but customer success, operators, and evaluators need a quick reading guide before inspecting event records.

## Boundary

- Do not hide the raw trace.
- Do not change run execution semantics.
- Do not introduce a browser-dependent verification path while the frontend runtime lacks Node tooling.

## Solution

- Summarize visible trace event count, workflow/node events, permission events, and failure evidence.
- Add a concise trace guidance line for no evidence, pending permission, failures, or normal evidence.
- Render the summary immediately before the raw trace JSON.
- Keep stable `data-trace-guidance` markers for automated checks.

## Acceptance Criteria

- Trace section has a readable summary before JSON.
- Permission and failure evidence are called out without parsing the raw log.
- The implementation is bilingual.
- Raw trace JSON remains available.
