## Problem

E07 complexity-router remained a policy hypothesis with `router_ready_for_default=false`. The platform needed an executable default-safety gate so router defaults could not be enabled without required evidence and guardrails.

## Boundary

This design added a read-only backend/API gate. It did not enable complexity-router defaults, change builder default routing behavior, or run paid/live model tests.

## Final Design

- `platform/backend/src/agent_platform/complexity_router.py` evaluates default-safety prerequisites.
- `/api/v1/platform/complexity-router/default-safety` exposes the current authenticated gate status.
- Current source evidence is satisfied, but requirement classification, operator override plan, and rollout metrics prerequisites are missing.
- `default_enabled=false`, `allowed_to_enable_default=false`, and `router_ready_for_default=false` remain true for the current state.

## Acceptance

- API returns the current disabled gate.
- Tests prove the current state remains disabled.
- Tests prove the gate allows default enablement only when all prerequisites are satisfied.
