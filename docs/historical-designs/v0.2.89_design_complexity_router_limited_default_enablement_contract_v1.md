# v0.2.89 design: complexity-router limited default enablement contract

## Source

- Source stage report: `docs/stage-reports/v0.2.88_complexity_router_limited_default_enablement_plan.md`
- Source task: `Implement complexity-router limited default enablement contract`
- Version target: `v0.2.89_complexity_router_limited_default_enablement_contract`

## Problem

v0.2.88 defined the limited default contract, but backend settings, API/status surface, and classification response fields did not yet expose or enforce that contract.

## Boundary

- Implement config/API/classification contract.
- Keep normal runtime default mode `disabled`.
- Do not globally enable limited default without explicit configuration.
- Preserve conservative unknown handling.

## Design

- Add settings fields for default mode, limited default enabled flag, and minimum confidence.
- Add a status function and API endpoint for the limited default plan/current contract.
- Extend classification output with configured default mode, limited-default eligibility, and default policy only when explicitly configured.
- Add rollback-to-disabled behavior in the status surface.

## Acceptance

- Default settings report mode `disabled` and `default_router_enabled=false`.
- Explicit limited-default settings allow eligible classifications to surface a default builder policy.
- Unknown requirements remain conservative complex-equivalent.
- API tests cover disabled and explicitly enabled modes.

## Status

Completed in v0.2.89.
