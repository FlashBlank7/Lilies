## Problem

v0.3.40 makes cancellation safe, but after confirming stop the visible feedback is still mainly a toast and background polling. Users need to see that the stop request was submitted and the system is still checking the run status.

## Boundary

- Frontend status/copy only.
- No polling interval change.
- No backend API change.

## Solution

- Track the run id after a confirmed cancel request.
- Show a cancel-requested progress strip while that run remains queued/running.
- Explain that status will continue refreshing until cancelled or otherwise resolved.

## Acceptance Criteria

- Progress strip appears only after the second explicit stop action.
- Progress strip is bound to the current run id.
- Progress strip clears for unrelated runs and non-cancelled terminal states.
