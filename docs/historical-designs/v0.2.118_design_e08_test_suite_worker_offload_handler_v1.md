## Problem

`test_suite` is a required Platform Harness task kind, but the worker catalog still treats it as unavailable. Existing test execution is API/runtime-owned, so validation cannot yet run through a worker-owned handler.

## Boundary

- Do not duplicate assertion, required-tool, citation, or structural-test logic in the worker handler.
- Do not replace the existing API `/tests/run` path.
- Do not claim full Platform Harness sidecar completion.
- Do not implement builder, benchmark, draft-preview, production supervision, or distributed queue slices.

## Final Scheme

Add a `test_suite_handler()` that delegates to `WorkflowRuntime.run_test_suite()` using the queued worker task id as the test-suite Platform Harness boundary.

Extend `run_test_suite()` with optional parameters:

- `harness_task_id`;
- `manage_harness_task`;
- `origin`.

The default API path keeps the current behavior. The worker handler passes `manage_harness_task=False`, so the worker runner owns completion of the queued worker task while the existing runtime still owns per-test workflow runs and assertions.

## Acceptance

- A queued `test_suite` task can be claimed and completed by `PlatformHarnessWorkerRunner`.
- The handler returns the existing test-suite report shape.
- Per-test workflow runs remain parented to the queued test-suite worker task.
- Existing API test-suite behavior continues to work.
