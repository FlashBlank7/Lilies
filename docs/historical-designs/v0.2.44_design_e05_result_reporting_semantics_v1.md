## 1. Goal

Make E05 result JSON distinguish Builder terminal status, benchmark suite pass, and benchmark case pass.

## 2. Module Boundary

Primary files:

- `scripts/e05_template_reuse_depth_experiment.py`
- `tests/test_e05_template_reuse_depth_experiment.py`

- `docs/experiment-status/evidence/experiment_v0.2.43_e05_customer_support_2026_07_09.json`

## 3. Implementation Plan

1. Add a small benchmark outcome summarizer for a suite report.
2. Include `benchmark_outcome` in each E05 arm result.
3. Set future E05 suite `minimum_pass_rate` to `1.0`, so a single failed case cannot be hidden by suite-level thresholds.
4. Keep raw `benchmark_report` unchanged for compatibility.
5. Add deterministic tests for case-fail/suite-pass legacy report interpretation.

## 4. Acceptance Criteria

- Tests prove `benchmark_outcome.case_passed=false` even when old suite `passed=true`: `test_e05_benchmark_outcome_preserves_case_failure_when_suite_passes`.
- E05 arm result includes `benchmark_outcome`: implemented in `run_arm()`.
- Future E05 suite evaluation requires pass rate `1.0`: `BENCHMARK_MINIMUM_PASS_RATE` defaults to `1.0`, configurable with `E05_BENCHMARK_MINIMUM_PASS_RATE`.
