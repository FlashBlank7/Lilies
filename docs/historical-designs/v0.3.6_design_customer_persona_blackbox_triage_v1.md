## Problem

The user explicitly asked for simulation of different customer behaviors. Existing v0.3.x tests cover customer examples and safe draft creation, but they do not yet behave like separate customer personas with different intent, confusion level, and return paths.

## Boundary

Persona tests must stay no-build unless a later stage explicitly budgets model calls. They may create bounded smoke applications and must clean up their own `v0.3.6-smoke` artifacts.

## Solution

Add a v0.3.6 black-box harness with at least three personas:

- confused first-time business owner: checks that home copy, customer examples, and safe draft path are visible enough to start without technical vocabulary,
- concrete workflow builder: creates a smoke safe draft from a detailed requirement and verifies Start to Answer skeleton exists,
- returning implementation consultant: lists existing applications, opens a draft, and verifies detail-route guidance and revision metadata are visible.

The harness should record:

- called endpoints,
- smoke marker and cleanup status,
- no-build safety,
- customer-facing friction found during the run.

## Acceptance Criteria

- At least three personas are represented in test data.
- Harness avoids `/builds`.
- Created smoke artifacts are cleaned up through the v0.3.5 boundary.
- Focused tests can run without live model calls.

## Evidence Requirements

- Persona harness script or test fixture.
- JSON evidence in `workingon/`.
- Bug ledger entries for any P0/P1 issue discovered.
