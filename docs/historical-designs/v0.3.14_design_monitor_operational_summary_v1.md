## Problem

The Monitor tab exposes task counts and raw task cards, but a non-technical operator still has to infer whether the current app is healthy, stalled, or blocked by failed platform tasks.

## Boundary

- Do not start builds, tests, benchmarks, or workflow runs.
- Do not replace detailed task cards; add readable interpretation before them.
- Use the existing `monitorSummary`, related task filtering, and i18n system.

## Solution

- Add a monitor guidance panel near the task counters.
- Explain related, running, failed, and total task counts in plain language.
- Add a next-action sentence for empty, failed, running, and healthy states.
- Keep stable `data-monitor-guidance` markers for automated checks.

## Acceptance Criteria

- Monitor tab has a summary panel before raw task lists.
- The panel contains count-level items and a next-action line.
- The implementation is bilingual.
- Existing task card behavior remains unchanged.
