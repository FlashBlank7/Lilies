## Problem

The Try tab currently shows run status and raw JSON. Non-technical users still need to know whether the result is useful, empty, failed, paused, or still running before they inspect implementation details.

## Boundary

- Frontend-only result interpretation.
- No automatic retry.
- No mutation endpoint.
- Keep raw JSON visible for technical users.

## Solution

- Add `tryResultOutcomeItems` beside the existing run result panel.
- Summarize:
  - current run status,
  - output key count,
  - error presence,
  - visible trace event count.
- Add a short status meaning via `tryResultStatusMeaning`.
- Render a compact panel with `data-try-result-outcome="summary"`.

## Acceptance Criteria

- Succeeded, failed, paused, running, cancelled, and queued states have readable meanings.
- Output/error/trace counts are visible before the raw JSON.
- Raw JSON remains available.
- Source, i18n, style, and manifest markers are covered by v0.3.33 tests.

## Final State

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` as `tryResultOutcomeItems`.
- Added `data-try-result-outcome="summary"` inside the existing run result panel.
- Added status meaning copy via `tryResultStatusMeaning`.
- Summarizes status, output count, error state, and trace event count before raw JSON.
- Verified by `scripts/v03_33_try_run_result_interpretation.py` and `tests/test_v03_33_try_run_result_interpretation.py`.
