# v0.2.118 Worker Catalog Transition Design

## Source

- Source stage report: `docs/stage-reports/v0.2.117_e08_remaining_sidecar_slice_reselection.md`
- Source task: `Implement test_suite worker offload handler`
- Current version: `v0.2.118_e08_test_suite_worker_offload_handler`
- Status: completed

## Problem

After v0.2.116, `workflow_run`, `scheduler_trigger`, and `scheduler_manual_trigger` are implemented. `test_suite` should now move from deterministic unavailable to implemented, while remaining task kinds keep explicit gap behavior.

## Final Scheme

Move `test_suite` into `IMPLEMENTED_WORKER_HANDLERS` with v0.2.118 evidence and register `test_suite_handler()` in `build_platform_worker_handlers()`.

The catalog should then report:

- `workflow_run` implemented;
- `test_suite` implemented;
- `scheduler_trigger` implemented;
- `scheduler_manual_trigger` implemented;
- `builder_build`, `benchmark`, and `draft_patch_preview` unavailable;
- full execution coverage still false.

## Acceptance

- Catalog API shows `test_suite.status == implemented`.
- Remaining unavailable handlers still fail deterministically.
- `not_full_sidecar_completion` remains true.

Completed in v0.2.118.
