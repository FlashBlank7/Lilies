## 1. Goal

Add a deterministic hard boundary around model stream collection.

If a provider stream stalls or exceeds the configured timeout, `AgentRuntime._collect_stream()` should emit a timeout event and raise a retryable `ProviderError` with a clear message.

## 2. Module Boundary

Primary files:

- `platform/backend/src/agent_platform/runtime.py`
- `tests/test_runtime.py`

Read-only dependencies:

- `platform/backend/src/agent_platform/providers/base.py`
- `platform/backend/src/agent_platform/config.py`

## 3. Data Flow / Control Flow

Current chain:

1. Runtime calls `provider.stream(...)`.
2. `_collect_stream()` awaits the async iterator.
3. If the stream stalls, the boundary depends only on provider internals.
4. Runtime events do not reliably record a model-stream timeout point.

Target chain:

1. Runtime calls `provider.stream(...)`.
2. `_collect_stream()` wraps collection in an `asyncio.timeout()` boundary.
3. On timeout, runtime emits `<event_prefix>.timeout`.
4. Runtime raises `ProviderError("model stream timed out after ...", retryable=True)`.
5. Existing callers either retry or fail their task with explicit evidence.

## 4. Implementation Plan

1. Add optional `timeout_seconds` parameter to `AgentRuntime._collect_stream()`.
2. Default timeout to `self.settings.deepseek_timeout_seconds` when the caller does not pass a value.
3. Move the current async-for collection into a private helper or inner block so the timeout wrapper is small and testable.
4. Emit:
   - `<event_prefix>.timeout` on `asyncio.TimeoutError`;
   - `<event_prefix>.failed` on `ProviderError`.
5. Add a deterministic runtime test using a provider that sleeps beyond a tiny timeout.

## 5. Acceptance Criteria

- Slow provider stream causes `ProviderError` within the configured timeout.
- Timeout error is retryable.
- Event stream contains `<event_prefix>.timeout`.
- Normal scripted provider behavior still passes existing runtime tests.
