## Problem

v0.3.43 shows parser errors inline, but the Try draft and published run buttons still look actionable. Repeated clicks then bounce through `startRun(...)` and toast feedback, which feels broken to non-technical users.

## Boundary

- Frontend guard only.
- Keep `startRun(...)` parser validation as the final safety boundary.
- Do not call run APIs when the current input parser has an error.

## Solution

- Derive `tryInputErrorBlockingRun` from `runInputParsed.error`.
- Disable run action buttons while parser errors exist.
- Add data markers so the blocked state is testable.

## Acceptance Criteria

- Draft and published run actions are blocked when parser error exists.
- Existing active-run duplicate-start guard remains intact.
- Valid inputs keep current run action behavior.
