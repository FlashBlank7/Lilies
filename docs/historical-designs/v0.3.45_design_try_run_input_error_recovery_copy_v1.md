## Problem

Button re-enablement alone does not explain why the corrected state is trustworthy. Users need a short confidence cue that ties the restored state to valid inputs and to the payload preview they can inspect before running.

## Boundary

- Bilingual copy and local focus action only.
- Do not introduce explanatory onboarding text outside the relevant Try control area.
- Keep the payload preview as the visible source of truth.

## Proposed Solution

- Add bilingual recovery-ready title, detail, and action copy.
- Add a local action that focuses the payload preview instead of triggering a run.
- Use copy that says inputs are valid again and asks the user to review the JSON that will be sent.

## Acceptance Criteria

- Chinese and English copy exist for the recovered-ready state.
- Recovery copy references valid inputs and the payload preview.
- The local action focuses the payload preview and does not call run APIs.
