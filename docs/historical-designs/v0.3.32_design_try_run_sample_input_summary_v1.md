## Problem

Non-technical users can see a Try form and a JSON preview, but before clicking `填入样例输入` they cannot tell which fields will be filled, whether the values come from acceptance samples or defaults, or whether the draft is ready to run.

## Boundary

- Frontend-only visibility improvement.
- No automatic run.
- No backend mutation.
- Summary must remain compact enough for the left panel.

## Solution

- Derive a sample-input summary from the same source used by `applySampleRunInputs`: `firstMandatoryInputs(draft)` plus `defaultInputValue(...)`.
- Show field count, required count, and sample-backed count.
- Show up to three field rows with type, required/optional status, and a short value preview.
- Use stable markers for automated harness coverage:
  - `data-try-sample-input="summary"`
  - `trySampleSummaryItems`

## Acceptance Criteria

- A user can inspect sample values before applying them.
- Empty-input workflows show an explicit no-input state.
- The summary does not call run/build/test/version APIs.
- Source, i18n, style, and manifest markers are covered by v0.3.32 tests.

## Final State

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` as `trySampleSummaryItems`.
- Added `data-try-sample-input="summary"` with compact field, required, and acceptance-sample counts.
- Added field-level sample source labels and short previews.
- Verified by `scripts/v03_32_try_run_sample_input.py` and `tests/test_v03_32_try_run_sample_input.py`.
