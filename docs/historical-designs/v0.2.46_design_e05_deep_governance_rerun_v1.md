# design_e05_deep_governance_rerun

## Problem

After the Builder teammate governance change lands, we still need a real paid/live answer: did deep customer-support reuse become a bounded stop with clearer evidence, or did it actually become `ready`/`published` under the same budget?

## Boundary

- In scope: the existing E05 customer-support case, bounded paid/live rerun, raw JSON, chart, concise DOCX report, experiment ledger update, and stage report.
- In scope: comparing new deep behavior against `v0.2.45`.
- Out of scope: broadening E05 to more task families in the same version, or closing original E05 globally.

## Solution

Reuse the existing E05 experiment runner and rerun the customer-support case with the same budget envelope after the governance fix. Focus the analysis on deep-arm behavior, but keep none/shallow/deep evidence structure compatible with existing ledgers and summaries.

## Implementation Plan

1. Run deterministic tests first.
2. Run bounded paid/live E05 customer-support rerun with the same budget family:
   - `E05_REUSE_DEPTH_CASE=customer_support_router`
   - `E05_REUSE_DEPTH_MAX_TURNS=42`
   - `E05_REUSE_DEPTH_MAX_REPAIR_CYCLES=2`
   - `E05_REUSE_DEPTH_MAX_ELAPSED_SECONDS=600`
3. Generate raw JSON and summary/chart.
4. Write a concise DOCX report with background, design, result, and conclusion.
5. Update `docs/experiment-status/ledgers/E05_template_reuse.md` and `docs/experiment-status/v0.2_experiment_status.md`.
6. Archive the stage with historical designs and workingon evidence.

## Acceptance

- A new bounded paid/live result exists for the post-governance customer-support rerun.
- Raw JSON, summary evidence, and DOCX report exist and are mutually traceable.
- The report clearly states whether deep is now successful, bounded-stopped, or still times out.
- Experiment ledger and stage report reflect `已应用` or `验证应用` correctly.
