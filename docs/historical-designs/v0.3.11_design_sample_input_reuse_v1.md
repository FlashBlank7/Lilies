## Problem

Acceptance tests often already contain good example inputs, but the Try tab does not explain or expose that reuse as a user action.

## Boundary

Use existing Start input schema and first mandatory acceptance inputs. Do not invent a new sample store.

## Solution

- Add an `applySampleRunInputs` action that fills Try fields from the first mandatory acceptance input or defaults.
- Add confirmation notice when sample values are applied.
- Disable the action when there are no declared run fields.

## Acceptance Criteria

- Users can repopulate Try inputs from sample/default values.
- The action does not start builds or runs.
- Harness verifies the marker and source behavior.

## Evidence Requirements

- Frontend source diff.
- v0.3.11 harness JSON.
- Focused tests.
