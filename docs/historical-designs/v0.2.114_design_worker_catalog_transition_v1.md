# v0.2.114 Worker Catalog Transition Design

## Source

- Source stage report: `docs/stage-reports/v0.2.113_e08_remaining_sidecar_slice_reselection.md`
- Source task: `Implement scheduler_trigger worker offload handler`
- Current version: `v0.2.114_e08_scheduler_trigger_worker_offload_handler`
- Status: completed

## Problem

v0.2.110 made the worker handler catalog complete by registering deterministic unavailable handlers. That was correct for coverage, but `scheduler_trigger` must now move from unavailable to implemented without weakening the remaining unavailable gaps.

## Boundary

- Keep all required `TaskKind` entries cataloged.
- Keep deterministic unavailable handlers for task kinds that still lack real worker-owned execution.
- Do not mark `full_execution_coverage` true while workflow run, builder build, test suite, benchmark, and draft patch preview handlers remain unavailable.

## Final Scheme

Move `scheduler_trigger` into `IMPLEMENTED_WORKER_HANDLERS` with v0.2.114 evidence and register `scheduler_trigger_handler()` in `build_platform_worker_handlers()`.

The catalog should then report:

- `scheduler_manual_trigger` implemented;
- `scheduler_trigger` implemented;
- remaining non-scheduler worker task kinds unavailable;
- full catalog coverage still true;
- full execution coverage still false;
- not full sidecar completion still true.

## Acceptance

- Catalog API shows `scheduler_trigger.status == implemented`.
- Catalog API still reports `full_execution_coverage == false`.
- Unavailable handlers still fail deterministically for the remaining unsupported kinds.

Completed in v0.2.114.
