# design_v0348_customer_run_surface_overview

Status: completed

## Source

- Source stage report: `docs/stage-reports/v0.3.47_natural_language_workflow_edit.md`
- Source task: Add run-page workflow explanation.
- User product correction: ordinary users should understand what the workflow does before looking at bricks, tests, or JSON.

## Problem

The Run tab still begins like a technical try-run surface. It shows readiness, sample inputs, raw payload preview, and trace concepts before giving the user a simple answer to: "what does this workflow do for me?"

## Boundary

- Improve the existing Run tab; do not create a separate route yet.
- Keep technical JSON and Trace available, but move the first read toward a customer mental model.
- Do not change workflow runtime semantics in this stage.

## Proposed Solution

- Add a customer-facing run overview at the top of Run.
- Show workflow name, purpose, input count, step count, run mode, and latest status.
- Summarize the visible workflow step sequence in natural language.
- Use stable `data-customer-run-interface` markers for regression.

## Acceptance Criteria

- Run tab has a first-screen customer run overview.
- Overview explains purpose and step sequence without requiring brick inspection.
- Existing readiness and technical detail surfaces remain available below.
