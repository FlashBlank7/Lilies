# design_platform_harness_worker_lease_api_v1

## 1. Goal

Expose worker lease operations through bounded Platform Harness API endpoints so operators and future worker processes can use the durable lease primitive.

## 2. Module Boundary

Backend API:

- `platform/backend/src/agent_platform/api.py`
- `platform/backend/src/agent_platform/platform_harness.py`

Tests:

- `tests/test_workflow.py`

## 3. Data Flow / Control Flow

1. Client calls a lease endpoint for an existing Platform Harness task.
2. API delegates to the Harness lease method.
3. Harness persists the updated task record and emits audit events.
4. API returns the full updated `PlatformTaskRecord` JSON.
5. Conflicts return a clear HTTP error rather than mutating state.

## 4. Implementation Plan

1. Add request models for lease claim/renew/release.
2. Add endpoints:
   - `POST /api/v1/platform/harness/tasks/{task_id}/lease`
   - `POST /api/v1/platform/harness/tasks/{task_id}/lease/renew`
   - `POST /api/v1/platform/harness/tasks/{task_id}/lease/release`
   - `POST /api/v1/platform/harness/leases/reconcile`
3. Map missing tasks to 404 and lease conflicts to 409.
4. Keep response shape aligned with existing task JSON.

## 5. Acceptance Criteria

- API can claim, renew, and release a task lease. Completed.
- API can reconcile expired leases and returns affected task records. Completed.
- Conflict errors are explicit and do not silently overwrite another worker lease. Completed.
- Existing task list/get endpoints continue to work. Completed.
