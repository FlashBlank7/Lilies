## Problem

v0.3.33 explains what users should do after a run result, but it still makes them find the relevant area manually. A non-technical user should be able to jump to the input form, run controls, result panel, permission card, human-input card, Trace, or acceptance tab without triggering a mutation.

## Boundary

- Focus/scroll/tab navigation only.
- No automatic run, retry, resume, cancel, build, test, version, restore, draft mutation, or model call.
- Existing explicit buttons remain the only mutating controls.

## Solution

- Add focus refs for run inputs, run controls, result panel, permission card, human input, and Trace.
- Add a `target` field to `tryResultNextAction`.
- Add `focusTryResultRecoveryTarget`.
- Render `data-try-result-focus-target` on a safe focus button.

## Acceptance Criteria

- Each result next-action state maps to a deterministic focus target.
- Focus button can switch to acceptance tab for successful runs.
- Focus button never calls run/resume/cancel/build APIs.
- Source, i18n, style, and manifest markers are covered by v0.3.34 tests.
