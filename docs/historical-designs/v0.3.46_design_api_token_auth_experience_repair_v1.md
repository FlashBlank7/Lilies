## Problem

The UI reports authentication only after a protected request fails. That makes the product feel like it randomly interrupts work, even when the real issue is a proxy token mismatch.

## Boundary

- This slice removes the common local-development mismatch.
- It does not redesign account auth, RBAC, or production login.
- It does not disable backend authorization.

## Proposed Solution

- Make the proxy use the same `.env API_TOKEN` as the backend during local development.
- Keep the existing auth card as a fallback when the token is truly missing or invalid.
- Record the resolved behavior in deterministic evidence so future frontend startup changes do not regress it.

## Acceptance Criteria

- Local development no longer requires manual token entry when root `.env` has `API_TOKEN`.
- The fallback auth card still works for explicit manual tokens.
- Health-only success is no longer the only startup signal for auth readiness.
