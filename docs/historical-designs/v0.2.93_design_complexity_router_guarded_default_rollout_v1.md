# v0.2.93 design: complexity-router guarded default rollout

## Source

- Source stage report: `docs/stage-reports/v0.2.92_complexity_router_limited_default_readiness_review.md`
- Source task: `Implement complexity-router guarded default rollout`
- Version target: `v0.2.93_complexity_router_guarded_default_rollout`

## Problem

Readiness gates passed in v0.2.92, but normal settings still keep complexity routing disabled. The productization lane now needs a guarded default rollout that makes limited-default routing active by default while remaining reversible.

## Boundary

- Change normal settings to guarded limited-default routing.
- Preserve rollback-to-disabled through explicit settings.
- Preserve conservative unknown bypass.
- Do not remove operator/request override visibility.

## Design

- Change `Settings` defaults to `complexity_router_default_mode="limited_default"` and `complexity_router_limited_default_enabled=true`.
- Update default-safety and limited-default status tests to reflect guarded rollout instead of pre-rollout disabled defaults.
- Keep `default_mode="disabled"` as the rollback path.
- Add v0.2.93 tests proving default simple builds activate, default unknown builds bypass, and explicit disabled settings roll back.

## Acceptance

- Default settings classify eligible simple requirements with `default_router_enabled=true`.
- Default build creation persists active runtime builder policy for eligible simple requirements.
- Unknown requirements remain inactive and complex-equivalent.
- Explicit disabled settings restore inactive routing.

## Status

Completed in v0.2.93.
