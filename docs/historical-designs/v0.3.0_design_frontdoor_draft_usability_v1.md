## Problem

The frontend currently exposes powerful build, edit, test, run, and monitor surfaces, but the first screen and concrete draft/canvas view require too much prior context. A non-technical user can land on the app or open a generated workflow and still not know:

- what object they are looking at,
- what the safest next action is,
- whether the draft is ready, testing, published, or blocked,
- which customer scenario the product is meant to support,
- where to report or classify bugs.

## Boundary

This design improves the existing Next.js frontend without changing backend APIs or workflow semantics. It adds UI guidance, status summarization, scenario cues, and bug triage visibility. It does not redesign the entire app shell, add a separate onboarding wizard, or replace the canvas engine.

## Solution

Improve the first-use and draft/canvas experience with:

- a compact customer-scenario strip on the home page,
- explicit step cards for create, inspect, test, and run,
- better empty-state copy,
- a draft readiness summary in the application header area,
- a canvas help rail explaining what the user is seeing and what to do next,
- a bug triage panel for observable product issues and next checks,
- copy that speaks in product actions instead of internal implementation terms.

## Acceptance Criteria

- Home page tells at least four customer types what they can do.
- Home page shows a clear create/open/test/run path.
- Empty application state gives a concrete next action.
- Draft view shows a readiness summary with draft, test, publish, run, and monitor state.
- Canvas area explains what the graph is and how to interact with it.
- Bug triage surface is visible in the product.
- TypeScript check passes.
- Customer journey audit passes.
