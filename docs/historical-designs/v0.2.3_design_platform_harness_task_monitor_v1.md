# design_platform_harness_task_monitor_v1

## 1. Goal

实现 Platform Harness v1：在工作流内 soft harness blocks 之外，建立平台级 task monitor boundary，记录和观测所有资源消耗行为。

## 2. Module Boundary

涉及：

- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/api.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`
- `platform/backend/src/agent_platform/builder.py`
- `platform/backend/src/agent_platform/scheduler.py`
- `platform/backend/src/agent_platform/config.py`
- `tests/test_workflow.py`

不涉及：

- 大型队列系统。
- 多租户计费。
- 真正的 Docker/egress/secret policy 拦截器。
- Temporal 级 durable execution。

## 3. Control Flow

API / scheduler / runtime 创建资源消耗任务 -> PlatformHarness `start_task()` -> 运行过程中 `record_usage()` -> 完成、失败、暂停、取消时 `finish_task()` -> API 查询 `/api/v1/platform/harness/tasks`。

资源事件包括：

- workflow run
- builder build
- test suite
- scheduler trigger
- workflow node
- model call
- tool call
- nested workflow call

## 4. Implementation Plan

1. 新增轻量 `PlatformHarness`，保存在内存中，并通过事件流发出 `platform_harness.*` 事件。
2. 新增 `PlatformTaskRecord` / `PlatformUsageRecord`。
3. 配置预算：
   - max active tasks
   - max model calls per task
   - max tool calls per task
   - max node executions per task
4. 接入：
   - workflow run lifecycle
   - Builder build lifecycle
   - test suite lifecycle
   - scheduler trigger/manual trigger
   - model/tool/node usage
5. 新增 API：
   - `GET /api/v1/platform/harness/tasks`
   - `GET /api/v1/platform/harness/tasks/{task_id}`
6. focused tests 验证任务登记、资源计数和超限失败。

## 5. Acceptance Criteria

- 每个 workflow run 有 `workflow_run` task record。
- 每个 build 有 `builder_build` task record。
- `run_test_suite()` 有 `test_suite` task record。
- scheduler 触发有 `scheduler_trigger` / `scheduler_manual_trigger` task record。
- model/tool/node usage 被计数。
- 超过预算时任务失败并发出 harness violation。
- API 能查询 task monitor 记录。

## 7. Risk

这是 Platform Harness v1，不是完整生产级治理。它先提供统一任务边界、事件、预算计数和查询接口；真正的多进程持久化、账号预算、网络 egress、secret policy 和队列恢复是下一阶段。
