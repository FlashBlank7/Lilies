- Final status: implemented

## Problem

v0.2.73 left rollout metrics as the final missing default-safety prerequisite. The platform needed required metric definitions and an API-visible empty-state status before any enablement review.

## Boundary

This design implemented metric prerequisites only. It did not enable complexity-router defaults.

## Final Design

- Required metrics are classification distribution, override rate, override reason coverage, fallback unknown rate, success rate by class, and cost/latency by class.
- Initial status is `ready_empty_state`.
- Default-safety now has no missing prerequisites and returns `allowed_to_enable_default=true`.
- `default_enabled=false` remains unchanged.

## Acceptance

- Tests cover metric definitions and empty-state status.
- API exposes rollout metrics prerequisites.
- Default-safety allows enablement review without enabling defaults.
