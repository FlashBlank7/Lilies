## Problem

Invalid Try inputs are blocked by `startRun(...)`, but the most direct feedback is still a toast/notice. Users need to see the current parse or required-field error near the run form and JSON preview.

## Boundary

- Frontend visibility only.
- Do not change input parsing semantics.
- Do not add backend validation APIs.

## Solution

- Derive `tryInputErrorVisible` from `runInputParsed.error`.
- Show an inline error panel near the input preview when an error exists.
- Keep the existing `startRun(...)` guard as the final safety boundary.

## Acceptance Criteria

- Inline panel appears whenever `runInputParsed.error` exists.
- Panel uses the current parser error text.
- Panel does not appear when inputs parse successfully.
