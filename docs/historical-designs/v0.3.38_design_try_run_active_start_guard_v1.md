## Problem

Try run buttons can still be clicked while a run is queued or running. That can create duplicate runs, extra cost, and confusing status changes for non-technical users.

## Boundary

- Frontend guard only.
- Do not disable cancel while a run is active.
- Do not block retry after failed, succeeded, paused, or cancelled states.

## Solution

- Add `isActiveRunStatus`.
- Add `tryRunActive`.
- Early-return from `startRun(...)` if the current run is active.
- Disable draft and published run buttons while `tryRunActive`.
- Keep the existing cancel button enabled for active runs.

## Acceptance Criteria

- Queued and running states block new start attempts.
- Failed, succeeded, paused, cancelled, and no-run states do not block new explicit starts.
- Published button still respects `activeVersion`.
- Source, i18n, style, and manifest markers are covered by v0.3.38 tests.

## Final State

- Added `isActiveRunStatus`.
- Added `tryRunActive`.
- `startRun(...)` now returns early with `tryRunActiveGuardNotice` while queued/running.
- Draft and published run buttons are disabled while active.
- Published button still respects `activeVersion`.
