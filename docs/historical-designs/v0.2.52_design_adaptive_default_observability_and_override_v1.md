## Problem

If adaptive became the default silently, callers and event traces would lose the distinction between explicit `adaptive` and policy-defaulted `adaptive`, weakening rollback and debugging.

## Boundary

- In scope: metadata that reveals defaulted vs explicit suggestion mode and preserves override semantics.
- In scope: API and Builder result contracts plus focused tests.
- Out of scope: full analytics dashboards or operator UI work.

## Final Design

- Add metadata fields:
  - `reuse_depth_source`
  - `defaulted_by_policy`
  - `default_policy_version`
  - `available_overrides`
- Return them in both API template suggestions and Builder tool results.
- Keep rollback simple by preserving explicit fixed-depth overrides.

## Acceptance

- Callers can distinguish policy-defaulted adaptive from explicit adaptive.
- Builder event traces preserve the same distinction.
- Rollback remains explicit and simple.
