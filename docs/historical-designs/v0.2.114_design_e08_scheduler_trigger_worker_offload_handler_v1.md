# v0.2.114 E08 Scheduler Trigger Worker Offload Handler Design

## Source

- Source stage report: `docs/stage-reports/v0.2.113_e08_remaining_sidecar_slice_reselection.md`
- Source task: `Implement scheduler_trigger worker offload handler`
- Current version: `v0.2.114_e08_scheduler_trigger_worker_offload_handler`
- Status: completed

## Problem

`scheduler_trigger` is a required Platform Harness task kind, but the worker catalog still marks it as unavailable. Automatic schedule fires can be recorded as Platform Harness tasks, yet no built-in worker handler can execute a queued `scheduler_trigger` task.

## Boundary

- Do not claim full Platform Harness sidecar completion.
- Do not replace the existing direct scheduler tick path by default.
- Do not implement process supervision, external alerting, or a distributed queue backend.
- Do not reimplement completed heartbeat registry, complete handler catalog, stdio/container egress, secret rotation, policy controls, Studio controls, or runbook lifecycle slices.

## Final Scheme

Add a real `scheduler_trigger_handler()` in `worker_runner.py` that:

- reads `version`, `node_id`, `local_date`, and optional `triggered_at` from the queued Platform Harness task metadata;
- delegates schedule-fire execution to a scheduler method instead of duplicating workflow-run creation logic;
- uses the queued task id as the parent Platform Harness boundary;
- returns `application_id`, `run_id`, `version`, `node_id`, and `local_date` in worker result metadata.

Add scheduler support for executing an already-claimed schedule fire so the direct scheduler path and worker handler share the same run creation, schedule-fire completion, audit event, and failure-release semantics.

## Acceptance

- A queued `scheduler_trigger` task is claimed and completed by `PlatformHarnessWorkerRunner`.
- The handler starts a real workflow run through existing scheduler/runtime behavior.
- The resulting workflow run has `origin="scheduler"` semantics and receives the existing schedule inputs.
- Failed handler execution releases the claimed schedule fire for retry.
- Heartbeat evidence still shows the worker running and returning to idle.
