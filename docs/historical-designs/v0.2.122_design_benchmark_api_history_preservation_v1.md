## Problem

The benchmark API already creates durable Platform Harness `benchmark` task records and history. Worker offload must add a worker-owned path without breaking existing API-owned evidence.

## Boundary

- API benchmark evaluation keeps creating and finishing its own task records.
- Benchmark history continues reading `kind=benchmark` from Platform Harness.
- Worker-owned benchmark tasks use queued task payloads and do not depend on API request bodies.

## Acceptance

- API single-case benchmark still returns a task id and report.
- API suite benchmark still records suite usage counts.
- History includes both API-created and worker-created benchmark task records.
