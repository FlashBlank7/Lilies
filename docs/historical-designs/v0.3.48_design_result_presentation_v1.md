# design_v0348_result_presentation

Status: completed

## Source

- Source stage report: `docs/stage-reports/v0.3.47_natural_language_workflow_edit.md`
- Source task: Add final-result presentation.
- User product correction: final output should read as the workflow deliverable, not only raw JSON.

## Problem

The existing output preview helps, but it still lives inside a technical run-result block and ends with raw JSON. The customer needs a clear result card and an error/waiting explanation.

## Boundary

- Reuse existing run output preview extraction.
- Keep full JSON secondary for debugging.
- Do not reinterpret outputs with a model.

## Proposed Solution

- Add a customer result panel with status, readable output preview, error preview, and next action.
- Make raw JSON explicitly secondary.
- Add stable markers for result state, output count, and raw-detail boundary.

## Acceptance Criteria

- Run tab has a customer result card independent of raw JSON.
- Successful outputs appear before raw JSON.
- Errors and waiting states have readable customer guidance.

## Final Evidence

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` with `data-customer-run-interface="result-card"` and `customerResultState`.
- Result preview appears before the existing technical run detail block.
- Verified by `tests/test_v03_48_customer_facing_workflow_run_interface.py`.
