# design_complexity_router_shadow_only_rollout

## Source

- Source stage report: `docs/stage-reports/v0.2.81_complexity_router_staged_rollout_execution_decision.md`
- Source task: `Execute complexity-router shadow-only rollout`
- Version target: `v0.2.82_complexity_router_shadow_only_rollout`

## Problem

v0.2.81 selected `execute_shadow_only_rollout`, but no stage-0 rollout evidence exists yet. The project needs a shadow-only execution that records classifier outputs and rollout metrics without changing behavior.

## Boundary

- Execute only `stage_0_shadow_only` from the v0.2.80 rollout plan.
- Use existing local classification logic.
- Produce rollout metrics and raw evidence.
- Do not enable runtime defaults.
- Do not route or mutate user-facing behavior.

## Design

- Load the v0.2.80 staged rollout plan and the v0.2.78 bounded validation cases.
- Classify each case using `classify_requirement` in shadow mode.
- Record expected class, predicted class, effective class, confidence, and signals for each sample.
- Compute classification distribution, fallback unknown rate, unexpected classification rate, and default-enabled accident count.
- Mark stage-0 exit criteria satisfied only when classification distribution is recorded and default remains disabled.

## Acceptance

- Generated evidence records `stage_0_shadow_only`.
- Metrics include classification distribution and accidental default enablement count.
- `behavior_change=false`.
- Tests verify the rollout executes without enabling defaults.

## Status

Completed in v0.2.82.
