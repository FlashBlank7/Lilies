## Problem

Lilies had an adaptive policy and one positive live slice, but no explicit rule for when adaptive was safe to treat as the default Builder suggestion mode.

## Boundary

- In scope: define and record a reusable defaultization gate from multi-family live evidence.
- In scope: update ledger/index and create one intellectual asset if the conclusion is sufficiently stable.
- Out of scope: flipping Builder runtime defaults in code during this stage.

## Final Design

- Require at least two bounded paid/live families:
  - one shallow-resolving,
  - one deep-resolving.
- Require adaptive to resolve correctly, stay benchmark-clean, and not underperform the strongest fixed arm on final operational outcome.
- If the gate passes, treat adaptive as ready for default suggestion-mode productization while preserving fixed-depth explicit controls.
- Record the rule in both operational docs and a reusable intellectual asset.

## Acceptance

- The adaptive defaultization rule is explicit rather than implied.
- E05 ledger and experiment index point to the same verdict.
- A high-value intellectual asset captures the stable rule and its limits.
