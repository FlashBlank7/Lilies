## Problem

Lilies had enough evidence to justify adaptive as the default suggestion mode, but live product behavior still defaulted omitted `reuse_depth` to `shallow`.

## Boundary

- In scope: API and Builder omitted-depth default behavior.
- In scope: preserving explicit `none / shallow / deep / adaptive` overrides.
- Out of scope: deleting fixed-depth modes or redesigning adaptive heuristics.

## Final Design

- Add a shared helper that chooses default suggestion depth centrally.
- Default omitted-depth API requests to `adaptive`.
- Default omitted-depth Builder tool requests to:
  - BuildPlan depth when already concrete,
  - otherwise policy-default `adaptive`.
- Update Builder prompt so adaptive is the preferred default suggestion mode unless an experiment or requirement explicitly calls for fixed depth.

## Acceptance

- API no longer defaults omitted `reuse_depth` to `shallow`.
- Builder no longer defaults omitted `reuse_depth` to `shallow` before a concrete plan exists.
- Explicit overrides still behave as before.
