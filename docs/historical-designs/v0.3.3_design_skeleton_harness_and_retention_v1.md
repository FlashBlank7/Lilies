## Problem

The v0.3.2 harness verified that a local application could be created and opened, but it expected an empty draft. v0.3.3 must verify a useful non-model skeleton and address the growing smoke-app retention issue.

## Boundary

The live harness may create local `v0.3.3-smoke` applications and mutate their drafts through existing APIs. It must not call `/builds`, publish, run, or delete data. Because no application delete/archive API exists yet, retention is a documented local evidence policy rather than a cleanup implementation.

## Solution

Add a versioned harness that:

- creates a local smoke app,
- applies the same Start/Answer/edge/test skeleton operations used by the frontend,
- verifies node count, edge count, test count, revision, and no build call,
- records smoke-app retention policy in JSON,
- keeps browser-click evidence deferred until there is a first-class browser harness.

## Acceptance Criteria

- Live harness passes against local services.
- Static tests pass without live services.
- Evidence records created app id, revision, node count, edge count, test count, and no build call.
- P0/P1 bug ledger has no open P0/P1 in the covered scope.
- Retention policy is explicit.

## Evidence Requirements

- Live harness command and JSON path.
- Focused pytest command.
- Retention policy in workingon and stage report.
