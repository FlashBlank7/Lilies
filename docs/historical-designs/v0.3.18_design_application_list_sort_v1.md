## Problem

Demo reviewers need a predictable order after filtering or searching. The app list currently depends on backend order.

## Boundary

- Use existing fields: active version, tested hash, draft revision, and name.
- No date assumptions because the list payload does not include timestamps.

## Solution

- Add sort options for readiness, revision, and name.
- Default to readiness-first ordering for demo review.

## Acceptance Criteria

- Sort behavior is deterministic.
- Sort control stays compact.
- Fixture tests cover readiness, revision, and name ordering.
