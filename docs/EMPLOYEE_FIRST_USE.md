# 员工首次使用问题修复 · 2026-10-03

这批改动针对独立体验暴露的三类问题，在 `fix/employee-first-use-1003` 独立工作区实现，不替换正在服务员工的代码。

## 连接状态与恢复

官方智能体遇到明确的登录失效、非订阅账号或不可用的模型配置时，任务结束并保留原因。对话和工作流生成使用相同处理；其他排队任务发现连接已失败也会结束等待。额度未知、额度恢复和正常并发排队仍保留原有等待行为。

页面分别显示未检查、需要处理和最近检查有效，不再把非排队状态一概显示为“已连接”。管理员可从项目页面进入现有官方智能体管理页；员工看到联系管理员的提示。管理员检查成功后可重新发送，旧对话和错误记录保留。连接检查只持久化状态、说明和检查时间，不复制账号信息。

## 示例与运行准备

示例目录优先排列基础资源检查通过的项目。创建前、项目使用说明及运行表单展示已知缺项和配置入口，包括工作流模型、模型出口、计算环境、预测模型绑定及知识索引。模型用途区分文本、视觉和 Embedding；官方智能体连接不会被算作工作流模型连接。

检查只读取配置并检查本机 Docker 镜像；不调用模型、不执行工作流、不限制草稿保存。计算环境检查短暂缓存 10 秒。检查范围是基础资源，输入文件有效性、额外依赖和服务连接是否有效仍在实际运行时检查。包含条件分支的流程可能显示非本次分支的配置提示；提示不禁止运行。

## 项目与结果

项目自己的工作流和文件放在公共目录之前；文件默认显示名称，完整路径放在展开区。运行表单默认用一个文件选择框，手动路径放入高级区域，清空输入继续正确传给运行时。相同文件名的选择项保留目录用于区分。

费用结果默认显示疑似重复的数量、记录、来源文件及行号。重复记录即使不在普通的前 20 行预览中也会列出；最多展示 100 条，更多记录在明细下载中。金额汇总不自动去重，原始资料不修改。历史结果缺少专门明细时使用已有预览，并说明未展示的数量。

## 真实连接恢复与补充验证

10月3日继续检查员工服务：驻留连接的 `account/read` 返回空账号，而独立新进程读取同一份服务登录材料能识别订阅账号。因此此前页面的 API Key 提示并不能证明员工配置了 API Key；源码已将未登录与非订阅登录分别说明。账号为空、API Key 登录时均结束等待，不启动模型线程；检查恢复后可以重新发送。

确认没有活动任务后，通过现有管理员“连接服务器已有登录”接口重新连接，未更改服务程序、模型、思考强度、额度或计费来源。真实账号、模型目录及额度读取均恢复正常。此次定位到驻留连接与磁盘登录不一致，尚未复现底层连接何时失去登录状态，不把重连成功当作这一原因已经查明。

- **现有员工服务**：在独立体验项目的新会话中，Luna/max 完成自编会议纪要，端到端约22.3秒，官方任务记录6,778报告token。正确保留未定负责人、期限及是否全员推广的待确认状态；没有调用工具或工作流。这是连接可用性复验，不是降耗对照。
- **修复分支隔离服务**：独立模拟员工创建会议示例，未配置时显示模型缺项；绑定已有获准的 DeepSeek 原始API连接后显示已配置。一次真实工作流执行约4.1秒，报告输入292、输出402 token，生成带原文行号的纪要、行动项与待确认事项。两份产物通过下载接口返回200，字节与保存文件一致。沿用此前验证的业务模型关闭思考配置；未将官方智能体用于LLM积木。
- **离线回归**：补充空账号和非订阅账号的区分、失败终态及恢复重发，相关后端57项通过；自动测试仍关闭两种模型出口。前端本轮没有修改，沿用上节263项测试及构建结果。

本轮仅上述官方请求和业务工作流使用真实模型，没有遍历其余示例调用模型。官方报告token与原始API用量属于不同计量，不能相加当作订阅扣费。详细自编验证数据保存在本地 `data/employee-first-use-1003/real-recovery/`。
