# 从主题查找公开资料

员工可以在项目对话中提出“查找数据泄漏和分组验证的公开资料”。智能体通过 `project_search` 查找网页或学术索引，再用 `project_web` 读取选中的原文；已有材料比较、知识和报告能力继续使用这些项目文件。没有固定研究阶段，也不要求先搭建工作流。

检索词会发送给部署配置的 SearXNG 及其上游搜索引擎。配套研究 Skill 要求使用公开主题，不发送公司原始文档、账号信息或私人内容。搜索本身不调用模型；通过对话自主选择和使用工具仍需要配置可用的项目智能体。

## 部署

可连接已有的可信 SearXNG，设置 `SEARXNG_URL` 为服务根地址。服务需要开启 JSON 格式；未配置、限流、格式不支持或连接失败会返回具体原因，不自动切换供应商或生成假结果。[SearXNG Search API](https://docs.searxng.org/dev/search_api.html)

仓库提供可选的独立搜索容器，不影响主平台启动：

```sh
SEARXNG_SECRET="$(openssl rand -hex 32)" docker compose -f compose.search.yaml up -d
```

本地运行后端时，在 `.env` 设置 `SEARXNG_URL=http://127.0.0.1:8088` 并重启后端。同一 Compose 项目的容器后端可设为 `http://search:8080`。搜索端口只监听本机；不要把这个没有员工登录检查的搜索服务直接暴露到局域网或公网。

镜像固定在 SearXNG `2026.9.23-3cd69d30e` 对应摘要。示例配置只启用 Bing、DuckDuckGo、Brave、Wikipedia、Crossref 和 arXiv；管理员可以按实际网络和资料范围调整。固定镜像不保证上游搜索一直可用。配置合并和引擎选择沿用 [SearXNG settings.yml](https://docs.searxng.org/admin/settings/settings.html) 的机制。

平台沿用部署网络权限。这里访问的是负责人配置的搜索服务，允许使用容器内网地址；员工和模型不能指定或替换该地址。搜索结果中的网址不会自动访问，后续 `project_web` 仍逐次执行公开地址及重定向检查。

## 输入和结果

`project_search` 接受 `query`、`category`（`general` 或 `science`）、`language` 和 `max_results`（默认5、最多10）。只查询一页，单次连接及读取最多25秒、响应最多2 MB。

每次在独立的 `results/source-search-…/` 目录保存：

- `sources.md`：员工可阅读的标题、摘要、原文入口及失败提示。
- `results.json`：结构化结果、搜索时间、来源引擎及原响应哈希。
- `search-response.json`：实际收到的服务响应，便于核对。

在“项目空间”的文件列表点击“查看”，即可预览或下载，也能勾选带入对话。查看不会选中文件、发送消息或启动任务。搜索改词后生成新副本，旧文件保留。

索引摘要是查找线索，不是已核对的正文；论文命中也不表示已经取得全文。部分引擎失败会保留具体信息，零结果不能推断没有相关研究。搜索、原文读取和模型解释各自记录实际验证范围。

## 2026-09-25 实测

本机实际部署固定版本搜索服务。普通查询得到24条服务结果，学术查询27条，两个查询均无引擎错误；平台员工接口各保存前5条，约1.05秒和1.95秒。随后从实际结果选择 scikit-learn 官方数据泄漏说明，提取25,747字符；9份结果与原文文件下载及原响应哈希核对通过。资料都是公开检索词和公开网页，没有新增模型调用，也没有工作流运行。

新增13项行为测试覆盖真实响应形状、去重、无效链接、空结果、部分失败、服务配置、网络权限、失败清理、换查询及账号隔离；相关后端65项通过、3项额外计算环境跳过，另28项官方会话、模型会话和分享回归通过。前端209项、类型检查及生产构建通过。浏览器操作及后续状态记录在本周开发记录；不把直接工具测试称为真实智能体已自主完成研究。
