# 产品北极星 · v0.6

2026-09-20，依据用户确认的重构计划；旧产品约束由本说明替代。

平台由管理员配置的项目助手、人工装配或加入预设的项目能力，以及可视化可编辑的工作流组成。2026-10-20：按用户确认，区分搭建目录与项目可调用能力。

- 助手可以查看全局积木目录并协助搭建草稿；业务执行只调用人已加入项目的工作流和特定任务智能体。搭建目录不代表执行授权。
- 人工和 AI 随时创建或修改工作流，包括训练未完成、资源未绑定时。保存草稿不要求业务已经成功运行。
- 用户决定何时运行。运行时检查必需输入和资源，指出实际失败并保留已完成结果；禁止悄悄换模型。
- 项目助手与生成服务由管理员后台配置，项目使用者不选择模型来源或服务账号。项目空间管理可调用工作流和任务智能体；助手新建或修改的草稿需由人加入后才能调用。
- 项目统一管理智能体、工作流、资料、知识、变量、模型和结果。共享资源按需读取，不自动混合全部会话。
- 工作流编辑以人能操作为标准：表单、下拉框、输出选择器是默认，JSON 是高级入口。
- AI 直接生成或原子修改草稿，可撤销；不强制先查手册、确认计划、调用固定角色或通过自测。
- 保留数据隔离、预算、用户停止和项目能力权限。完整智能体积木默认禁用；禁用时手册、目录、保存和执行一致限制。原始 LLM 不得伪装为 Codex/Claude/Kimi 会话。

## 能力边界（2026-10-23 用户确认）

“面对任意陌生系统，无需业务澄清、环境准备或适配迭代，一次自主完成可靠交付”明确不属于产品目标，也不作为未来路线或验收要求。不得将它描述为仅仅证据不足、后续仍需实现的能力。

- 平台面向范围明确的任务：利用已加入的项目能力，依据可获取的接口资料、数据样例及业务规则完成工作。缺少的信息可以在沟通与搭建中补齐；资源尚未就绪不阻止草稿保存。
- 低代码允许助手编写和修正适配代码，处理字段转换、标识匹配和业务计算。新系统首次接入允许配置、澄清、测试与迭代，必要时由技术人员协助；不要求业务用户自行编写代码，也不要求智能体第一版就全部正确。
- 已确认的业务含义与接口约定应由工作流和配置保留，后续使用不应要求业务人员反复纠正相同错误。未知含义、缺少接口或无法确认的操作状态应明确说明，保留进度，等待补充或修复。
- 平台负责执行、权限、进度和结果的一致性；外部服务负责其实际功能。新业务需求不自动转化为新增积木或平台功能，应先判断现有积木、适配代码及工作流组合是否足够。
- “零技术救援”的验收仅适用于约定配置、输入范围和故障场景下的重复使用，不扩展到陌生系统的首次接入，也不要求任何故障都必须自动完成。

工作流搭建的默认方法是：分析问题与能力边界 → 按可独立验证的业务目标拆分工作流并明确输入输出 → 用假服务和合成输入逐个调试 → 按依赖关系串联验证 → 在约定范围内接入真实服务。有先后依赖的下游流程可先使用模拟上游输出独立调试。该方法不增加草稿保存或编辑的前置条件，详见 [业务结构中的搭建与调试方法](BUSINESS_LOGIC.md#工作流搭建与调试方法)。

近期以机器学习路径验证上述能力；后续扩展真正的语义 RAG、研究及内容交付 Skill。工作流是可复用成果，也是项目助手执行业务的已装配能力；普通解释与沟通无需运行工作流。
