# 旋转设备预测性维护、人工复核与 ThingsBoard 告警

我们用 ThingsBoard Community Edition 接收旋转泵的设备遥测。请搭建一条生产
增强工作流：读取设备的温度、振动、电流、压力和转速，确认字段、单位、时间
和事件身份有效后，调用当前已批准部署的故障风险模型。

生产工作流不能训练模型。模型准备由单独的 Builder 管理任务完成，可以从客户
模型库导入兼容模型、在客户授权数据上微调兼容模型，或在没有合适候选时训练
新模型。任何路线都必须保存来源与基础版本血缘，在独立验证集上评估，生成
模型卡，经明确批准后才能提升为带版本的部署；必须能够回滚。漂移监控只产生
报告，不得触发在线学习。

生产决策规则如下：

- 明确高风险且置信度足够时，为对应 ThingsBoard 设备创建或更新
  `PREDICTIVE_MAINTENANCE_RISK` 告警；
- 风险位于不确定区间或置信度不足时，暂停给可靠性工程师复核；批准后才写
  告警，拒绝则记录理由且不写；
- 明确低风险、缺字段、单位冲突、数值越界、过旧、乱序或重复事件不得产生
  错误告警；
- 相同设备的同一活动告警应更新而不是复制，相同事件重放不得重复产生业务
  副作用；
- ThingsBoard 临时错误只允许有界重试，身份或权限错误必须停止并明确归类；
- 全程禁止 Device RPC，不能因为预测结果去控制设备。

最终交付逐事件机器可读结果、ThingsBoard 告警回执、推理轨迹、模型卡引用、
验证报告和漂移报告。每条结果必须能追溯到设备事件、工作流发布版本、模型 ID、
模型版本、模型摘要、部署修订、人工决定和宿主回执。

Builder 只能使用本包的公开材料、公开积木手册、公开 schema 和 Lilies 平台
公开 API。不得读取受保护 Seed、标准答案、平台数据库或平台实现源码来寻找
答案。工作流必须使用通用 OpenAPI 连接器发现和调用 ThingsBoard 官方接口；
禁止增加 ThingsBoard 或本项目专用适配器。

本题验证模型生命周期治理和已部署模型的工作流编排，不证明合成数据模型在
真实工厂上的统计精度，也不验证长期在线稳定性或在线学习。
