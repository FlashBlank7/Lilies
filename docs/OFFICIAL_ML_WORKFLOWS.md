# 官方机器学习工作流 · 首批实现与使用

2026-09-22。基于现有公司项目资料、已归档工程和 [方法调研](ML_WORKFLOW_RESEARCH_2026-09-21.md)。本页记录通用实现；公司项目清单、代码、原始数据和实际运行明细保存在本地 `data/real-projects/wechat-2026-09/validation/`，不进入公开仓库。

## 使用入口

项目「空间」中选择「公共工作流市场」，点击「加入项目」。平台建立独立可编辑副本，并添加对应项目 Skill。安装不会训练或调用模型，也不要求已有数据或模型。

| 流程 | 输入 | 可调整项 | 产物与边界 |
|---|---|---|---|
| 按当时已知信息制备数据 | 样本表、记录与历史版本表 | 字段映射、时区、指标、最长历史时长 | 样本CSV、匹配原因与来源；排除尚未发布和后来修订的信息，见[使用说明](POINT_IN_TIME_WORKFLOW.md) |
| 数据摸底与分析建议 | 项目表格、员工的问题、可选业务说明 | 问题、工作表、可编辑检查代码与解释提示词 | 数据事实、分析报告、后续建议；必要时表单补充，不知道也可继续；[使用说明](DATA_GUIDANCE.md) |
| 表格分类训练 | 项目 CSV/TSV/XLSX、标签列、可选分组列 | 字段、划分、候选模型、预算 | 质量分析、特征、逐折评价、简单基线、独立测试、模型包；不自动推断标签语义 |
| 模型与规则批量预测 | 新数据、真实分类模型、业务验证确定的概率阈值 | 模型绑定、规则代码、阈值 | 带模型版本的预测和采纳／复核 CSV；通用示例只按预测类别概率判断，不等同于任何客户的完整继承规则 |
| 表格数值预测训练 | 一行一个样本、连续目标 | 同上，指标选择 MAE/RMSE/R² | 候选比较、独立测试和可复用模型 |
| 工业过程窗口质量预测 | 过程测量表、样本标签／预测时点表、炉次与时间字段 | 预测窗口、特征、分组或时间划分、隔离间隔 | 按预测时点提取过程特征；不替代未来价格多步预测或现场实时部署 |
| 已训练模型批量预测 | 新文件与项目模型引用 | 模型版本、字段语义 | 使用固定预处理和环境预测，不重训；CSV 可下载并交给后续代码节点 |
| 已有预测的规则重算 | 前次规则重算输入 JSON | 新阈值、规则代码 | 复用固定预测，只生成新决策和报告 |

训练图按「文件与目标 → 数据质量 → 样本与特征 → 模型比较 → 独立测试 → 结果」组织。每个节点可直接编辑。数据和配置都通过原有项目任务、建模计算服务执行，没有独立模板训练引擎。

## 员工操作

1. 在项目空间上传数据，然后加入所需流程。
2. 进入画布。「数据分析」可选择项目文件或已有数据集，填写标签、样本标识、分组与时间字段；XLSX 默认读取第 0 张表。
3. 「特征提取」填写需要使用／排除的字段，每行一个。留空表示使用除标签和声明的元数据外的字段。缺失值填充、编码和筛选在训练折内拟合。高级转换代码应提供 `build_transformer`，不能预先在全量数据上拟合。
4. 「训练评估」选择任务、指标、划分、折数与小规模候选。默认比较线性、随机森林、梯度提升三种候选，并计算简单基线；这些是起始对照，不是预定赢家。试验预算可以改。
5. 保存后在项目「直接运行」填写本次文件和目标。通过运行步骤查看实际输入、输出和错误；详细试验在项目建模记录中，模型包、训练说明和预测 CSV 可下载。
6. 在项目模型页面把完成的试验绑定为逻辑模型。加入预测流程，选择该引用，上传新数据即可预测。仅更改报告或规则时使用已有预测 CSV，不运行训练图。
7. 智能体可通过项目 Skill 找到这些流程，查看输入后用 `workflow_run` 调用同一个副本。调用过程不需要再生成流程。

已有模型不必重训：先把包含预处理和预测器的 sklearn Pipeline（`.joblib`／`.pkl`）上传到项目资料，在「模型 → 导入已有模型包」选择文件和与原训练匹配的本地环境，点击「验证并绑定」。平台在隔离计算环境加载并核对字段，保存独立模型版本、内容哈希及实际环境。环境缺失、依赖不兼容、字段错误或模型内容改变时返回具体错误，不自动下载环境或替换模型。重新绑定只影响后续运行；旧运行仍引用原版本。首版不支持任意裸模型或任意训练压缩包。

「继续」复用原任务数据快照和候选；「重新运行」创建新的数据和试验。新上传的同名文件不会覆盖旧结果。若修改了划分、标签或特征，应创建新运行。

## 方法口径

样本单位、预测时点和标签来源必须由任务确定。普通随机划分适合相互独立的表格样本；存在重复设备、晶棒或批次时需要分组；面向未来的使用场景采用时间向前验证。过程窗口还要考虑重叠窗口、标签延迟和数据实际发布日期。

预处理与特征选择只在相应训练折拟合，验证数据用于比较少量候选，保留测试集用于已固定方案的评价。阈值选择也是训练决策：在验证结果上选择后，需要独立评价，不能把阈值搜索的最优成绩直接当泛化成绩。参见 [scikit-learn 数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html) 和 [分类决策阈值说明](https://scikit-learn.org/stable/modules/classification_threshold.html)。

类别不平衡应同时查看每类样本量、召回率、精确率和混淆矩阵。少量稀有类别不足以证明稳定性；整体准确率高也可能遗漏关键缺陷。回归同时报告误差单位、简单基线及按时间／批次的表现。方向、极值、排序、区间覆盖是不同目标，不能用普通回归单个指标替代。

异常值、缺失值和重复样本的处理应保留数量与理由，不能通过删除难预测样本改善成绩。关联重复、空窗口或字段语义不明确应返回具体错误。当前通用模板不自动补造标签，不执行过采样，不决定客户的放行代价。分类训练可选自动采纳阈值：在训练评估表单填写最低验证准确率和最少样本数（留空不启用），从折外预测选择满足条件且覆盖样本最多的统一置信度阈值，同分样本一起处理。无解则全部复核。阈值随模型版本保存，独立测试和后续预测固定使用；模型包内 acceptance.json 提供完整选择曲线。它决定是否采纳分类建议，不替代逐类别工艺放行规则。

参考范围覆盖本地清单中的 15 个项目／线索，8 个直接相关项目深入检查。完整对照表在本地 `data/real-projects/wechat-2026-09/validation/全项目流程参考清单.md` 和 JSON 中。参考范围大于本轮可复现范围。

- 分类工程具备实际清洗、工艺特征、训练和概率阈值代码。检查发现划分前全表标准化、同一 OOF 上选阈值并评价，以及极少数类别样本等限制。通用版本复用流程结构，不继承专有标签／阈值；实际案例使用原清洗代码，并显式排除全表统计和标签派生特征。
- 模型与规则工程包含真实模型包、规则、候选优先级和返回测量行为。同时存在缺模型时启发式回退的示例逻辑。交付要求真实模型后端；官方流程缺模型直接失败。已有包与当前环境存在版本不匹配；在匹配的旧版环境中复现后，已通过平台绑定五个原模型，运行原字段制备、硬规则和优先级。原示例与尾盘变体的决策一致，各候选概率差小于 1e-10；这不等同于生产批量效果验证。
- 过程质量资料包含字段字典、少量样例与预测比较。当前材料不足以独立复现完整训练，不能把字段设计表当训练数据。过程模板提供可配置方法路径，公司案例效果仍待足量数据。
- 发布时点／修订历史、价格方向／极值／排序、视觉复核、优化排产与实测反馈分别保留适用边界。视觉训练、优化闭环和金融多步滚动回测不混入基础表格训练。

## 本轮验证与限制

真实分类案例由平台 Docker 执行，比较 3 个候选，按重复样本分组隔离并评价保留测试集。样本分布与实际指标见本地私有报告。稀有类别不足、测试 ROC-AUC 不可计算时具体说明，不伪造分数。计算与方法链可复现不等同于达到客户工艺上线条件。

模型包、预处理、依赖环境和数据版本随试验保存；独立预测和模型＋规则流程均实际执行成功。上述预测输入由原数据截取并去除标签，用于验证调用一致性，不能称为外部未见数据效果验证。前次手工规则阈值仅为操作验收参数，尚未业务标定。本次补充以最低验证准确率和样本数为条件的阈值选择及固定阈值独立测试，具体私有案例结果另存，不能据此宣称生产目标达成。

页面已验证加入独立副本、未绑定模型报错、表单绑定后同输入修复、模型包导入和结果下载入口。独立模拟员工账号复用与真实员工参与分别记录；原生文件选择窗口已打开，但扩展未开启本地文件读取权限，选文件时返回 Not allowed，上传仍未验收；HTTP 上传、下载字节及计算产物已验证。项目智能体工具完成发现、读取 Skill、查看输入和调用原流程；后续真实大模型验收见文末，接口测试与真实模型调用分别记录。

完整过程数据验证、光纤生产批量效果、专有阈值／优先级标定、逐类别工艺阈值标定及真实员工反馈尚未完成。表格回归和过程窗口流程通过合成数据真实计算，不能替代公司案例验收。9 月 27 日按实际成熟程度交付，不把可安装模板数量视为业务验收数量。

更新计算环境后使用 `lilies-modeling:20260922-feature-tables`；部署时由当前 Dockerfile.modeling 构建。旧模型继续使用保存的原镜像，不自动迁移。已有项目中的工作流副本不会被目录更新覆盖；要使用保存的阈值，可加入新版模型与规则流程并将手动阈值留空。

## 只改规则和报告

新版「模型与规则批量预测」输出「规则重算输入 JSON」。把「已有预测的规则重算」加入同一项目，选择此文件，在表单修改阈值或编辑规则节点，再运行即可。此流程只有文件读取与规则代码，没有训练或预测节点；原预测文件内容改变时拒绝复用，旧报告独立保存。现有项目副本保留原配置，需要加入新版才能取得重算输入。

这条流程通过明确选择已有产物完成阶段重算。此外，当前草稿已增加保守的步骤复用入口，适用范围见下文；尚不支持任意工作流的完全自动增量执行。

私有模型与规则案例另外提供批量版本与规则重算版本，使用原五模型、硬规则及优先级。一次批量模型计算后按输入序号关联，逐条格式错误不挤掉有效结果；完整CSV不依赖页面预览行数。当前36条示例组合已验证批量与修复路径，不能称为带标签生产批次准确率验证。

## 修改当前工作流后复用已完成步骤

在历史结果中选择「按当前配置重算」，确认自动带入的原输入后启动。平台创建使用当前草稿的新任务，原任务的配置、结果和模型版本保留。「再次运行此工作流」执行完整新运行；「继续原运行」沿原快照接续，含义不同。

按节点配置、依赖关系、每个节点实际读取的输入、已声明文件内容和计算镜像判断复用。修改报告节点时，可以保留数据分析、特征、训练和独立测试结果；修改训练配置则重跑训练及下游。代码默认执行，只有通过配置表单开启「允许复用已完成结果」才参与：所有读取文件必须通过输入字段声明，所有产物文件必须通过输出返回路径；有隐藏依赖、外部操作或每次都需要执行的代码不能开启。

这是一条保守的首版路径：只复用顶层输入、文本模板、输出、数据分析、特征、训练节点和主动声明的代码。预测仍调用原预测服务；循环、子流程、模型对话及其他有副作用的节点重新执行，其下游也重跑。运行到每个步骤时比较解析后的实际参数，不再因某个项目输入或资源绑定改变就全图失效。只改报告标题可保留数据分析、特征、训练和测试；换输入文件会重算读取该文件的步骤。模型预测及其下游继续执行以使用本次固定的新版本，不依赖该绑定的训练可复用。旧运行没有新版参数与文件校验记录、依赖文件变化或消失、镜像不可用时不假定缓存有效；旧记录自动退回正常计算，保留原结果。不会自动替换模型或恢复被删除的客户原文件。

实际公司分类案例：完整计算约9.41秒；只修改报告后重算约0.51秒，保留六个步骤及相同模型编号。此为同机单次功能对照，不是通用加速比例或业务效果改进。


## 样本与特征的检查和内部试用判断

结果页提供前12行特征预览，可下载完整特征CSV、标识与标签CSV、特征定义JSON。两个CSV按同一原始样本序号对应，缺标签排除数量单独说明；标签不会混进特征表。导出表与训练的确定性特征缓存一致，缺失填补、编码、标准化和筛选仍在各训练折中拟合。

用户确认没有更多生产数据，本阶段依据现有材料与方法验收自行评估，不再等待额外数据后才判断内部试用。

| 工作流 | 当前判断 | 依据与边界 |
|---|---|---|
| 表格分类 | 可内部试用 | 公司原始记录完成清洗、特征、三候选、独立测试、绑定预测和下载；稀有类别不能据整体分数保证可靠 |
| 模型与规则批量预测 | 可内部试用 | 五个真实模型、原规则的示例对照和批量错误处理已验证；不能外推生产准确率 |
| 表格回归 | 可内部试算 | 构造数据实际训练、基线比较和特征导出通过；没有公司连续目标训练集，不宣称公司效果 |
| 过程窗口质量预测 | 可内部试算 | 验证未来测量／延迟可用记录不进入特征、缺标签处理、分组训练与空窗口修复；实际任务仍需正确设置预测时点和划分方式 |
| 已有模型预测、规则重算 | 可复用 | 使用固定模型和预处理；预测、改规则与重新训练分开 |

过程验收使用明确标识的构造数据：37条样本中1条缺标签，36条有效样本生成10个特征；短窗口报错，改正窗口后训练成功。逐值检查窗口特征，不能把构造数据上的回归分数解释为工业生产效果。模拟员工账号通过页面选择文件和字段、完整重跑并下载，未填写JSON。

真实员工反馈尚未取得，已有的是独立账号模拟操作。实际大模型发现和调用已有流程的结果见下节；不把模拟员工操作描述为真实员工反馈。


## 对话调用已有流程：真实模型与失败修复

模拟员工账号在项目页面用自然语言要求处理项目中的两份过程样例文件，没有提供工作流编号或工具调用参数。沿用已授权的原始 DeepSeek API 连接，智能体从项目上下文发现已安装的流程，读取输入和已保存配置，调用原流程成功。296条测量、37条样本经处理保留36条，完成三候选比较与8条独立测试，生成模型包、特征和标签表。没有新建工作流，也没有用外部智能体模块执行业务。

本次硬上限4次模型调用，每次最多输出1024 token。实际4次，提供方报告非缓存输入合计32257 token、缓存读取76544 token、输出897 token；调用累计约6.07秒，请求观测约16.19秒。成本字段不支持，不能把记录中的0解释为免费。这是单次观测，没有以此推算一般用量或加速比例。

本轮同时暴露一个问题：模型在计算成功后又读取产物，达到调用上限，未生成最终说明。平台已补充独立于模型回复的结果卡片：任务完成、失败、等待输入或停止时显示实际结果入口；同一请求的同一任务不重复展示。员工可以直接打开结果、下载文件，不必为取得入口继续调用模型。额度上限和停止机制仍生效。

修复复测回放该次保存的4条模型回复，模型出口关闭；平台实际执行工具，同一请求标识复用原成功任务，任务数不变、没有重复训练。浏览器中确认额度错误仍显示，同时可以从结果卡片打开训练比较、特征预览，点击下载特征CSV和模型包。HTTP核对完整特征CSV为36行。这是离线回放修复验证，不能表述为第二次真实模型成功总结。

当前可交付的是可编辑、可运行、可在项目内由对话调用的内部试用流程。真实任务的生产精度、稀有类工艺阈值与员工使用反馈继续按各任务评估；任意子流程缓存、行业专用多步预测及优化反馈不属于这批通用流程已验证能力。


## 最终对话实测与输入级重算补验
