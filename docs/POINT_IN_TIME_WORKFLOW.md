# 按当时已知信息制备数据

2026-09-25。公共工作流市场中的可编辑流程，也可从示例项目创建独立副本。由读取检查、时点匹配和输出积木组成；使用实际代码计算，不需要大模型、模型训练或新的服务。

## 什么时候使用

员工有一份「在什么时间预测哪个对象」的样本表，另一份来自多个日期或不同发布频率的指标表，希望整理出每个样本当时能够使用的特征。适用于迟到发布、测量延迟、历史修订的表格数据。只知道今天最新值、没有历史版本及真实发布时间的资料，不能据此还原过去。

来源是现有多源数据项目的数据准备方案：保留发布日期、历史修订和来源，不把缺失填成0。原项目没有可复现训练实现及完整历史数据，本轮实现的是其中可迁移的数据制备方法；自编边界案例验证不代表原项目预测效果。私有源文件及定位保存在本地项目资料目录。

按样本时刻向过去查找特征是常见的数据准备方法，可参考 [Feast 的时点连接说明](https://docs.feast.dev/getting-started/concepts/point-in-time-joins)。本实现另外明确约束**该版本实际可用时间**，而不是只检查测量时间；没有引入 Feast 依赖。

## 输入与操作

1. 进入项目空间的「公共工作流市场」，加入本流程；或从「从示例创建」选择同名项目。加入不运行任务。
2. 选择样本表与历史记录表。CSV、TSV、XLSX均可，单表10 MB、10万条记录以内；多工作表Excel需指定名称。
3. 默认样本字段是 `sample_id, entity, prediction_time`，可带自己的标签和已知特征。记录表字段是 `entity, feature, observed_time, available_time, value`；不同表头在普通表单中映射。
4. `entity`必须在两表含义一致；留空表示所有样本使用同一套指标。每个样本标识唯一，每个实体、指标、所属时间、可用时间的版本唯一。
5. 时间使用ISO格式。预测时点和可用时间必须精确到时分；未知时不能擅自补成当天零点。已带时区的时间按自身时区处理，无时区时间按表单明确显示的UTC偏移处理，示例为+08:00。
6. 可限定指标和最长历史时长；期限相对于每个样本预测时点、从所属时间起算。0表示不设时限，不代表数据永远有效。

匹配顺序：两个时间均不得晚于预测时点 → 选择最新所属时间 → 选择该期当时最新可用版本。较旧月份的迟来修订不会遮盖更新月份。最新期值为空时保留缺失；不自动退到更早期、不填0、不删样本。不包含对未来已知协变量的特殊处理。

## 结果与下一步

- 页面显示匹配概况、方法和样本预览；原样本顺序及已有字段保留，新字段以 `asof_` 开头。
- 样本CSV供数据摸底或训练直接选择，工作流输出为 `result.source_path`。
- 匹配明细CSV单独记录每个样本/指标的来源文件、记录号、所属时间、可用时间、年龄和原因。记录号包括表头，从1开始，不等于含换行CSV的物理文本行号。
- 汇总JSON保存原文件内容哈希与时间参数，Markdown说明可以下载。
- `matched`为匹配成功；`no_available_record`为当时无记录；`stale`为过期；`missing_value`为来源值缺失。真正的数字0仍保留。

本流程不判断原样本自带字段是否泄漏，也不替员工定义标签。开始训练时仍需按任务选择特征、标签和数据划分。缺少字段或时间、重复版本时修正对应资料再运行；新的文件或参数生成新结果，旧结果不覆盖。

## 自编练习

示例的四个样本应分别得到：空、11、12、20。第一个样本对应的记录还未发布；第二个已知道修订值；第三个不能被旧月份的99覆盖；第四个使用另一个实体的数据。

换为第二份记录表后应得到空、110、120、200。将最长历史时长改为24小时，检查过期原因。所有资料是自编测试数据，标签只演示后续接口。

验证包含上述人工可核算结果、乱序稀疏历史与独立逐项查找的对照、发布时间精确边界、实体隔离、缺失、过期、重复版本、Excel、换输入、平台执行、下载及下游数据体检调用。尚无原项目完整历史数据用于生产回测。
