## Stage Answer

`v0.2.47` gives a clear answer to the carry-forward policy question: `shallow` is not a stable fixed default candidate across families.

For the new `data_analyzer` family:

- `none` failed with an invalid draft / unreachable-node runtime path,
- `shallow` reached benchmark-clean structure but still timed out at the 600s build boundary,
- `deep` published in `461.068s` with fewer model/tool calls than `shallow`.

The right next step is no longer “collect one more shallow/default case.” It is “define and validate an adaptive reuse-depth policy.”
