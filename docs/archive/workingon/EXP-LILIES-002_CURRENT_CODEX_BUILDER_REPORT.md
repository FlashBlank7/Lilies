## 二、题目和真实业务场景

客户是一家把作业规程、安全手册、财务制度、人事说明和公共联系人放在
BookStack 的传统企业。现场运营人员会询问设备隔离步骤，安全人员会询问事故
响应规则，财务或人事问题则只允许相应岗位读取。知识管理员还会持续修改或
删除页面。

客户授权 Builder 使用：

- 一个受控本地 BookStack v26.05.2；
- 只读的 BookStack API 身份，用于读取客户已经授权的页面；
- 页面身份、修订时间、正文和岗位访问范围；
- 提问者的岗位身份；
- 对敏感回答的人工批准或拒绝。

Builder 可以把授权页面同步进平台索引、按当前用户岗位检索、生成带引用的回答
或明确拒答。它不能修改客户知识页；公开调试中唯一的页面更新和删除由测试管理
身份完成，用于验证客户自己改动知识后的同步效果。低证据问题和越权问题必须
拒答。财务、人事等敏感内容即使检索到了，也必须先等待人工决定。

最终交付包含三类相互对应的结果：

1. 回答或拒答、引用、人工决定及所用模型版本；
2. 哪些来源有权参与检索、哪些来源被权限过滤，以及禁止片段计数；
3. 本轮知识同步插入、更新、删除或重放了什么，以及索引修订。

本题不验证生成式大模型的文风，也不验证复杂 OCR、表格或图片理解。当前回答是
从授权原文中抽取依据，重点验证“该不该答、依据来自哪里、知识变化后是否正确”。

## 三、工作流是怎么搭建的

Builder 先确定四条业务原则：权限必须早于相关性计算；没有充分依据就拒答；
敏感内容先复核后交付；客户知识变化必须可追踪且不能倒退。顺序不能颠倒。
如果先搜索再做权限过滤，越权文本已经进入候选集合；如果先生成答案再让人拒绝，
敏感内容可能已经泄漏；如果接受旧修订覆盖新修订，用户会再次收到过期规程。

一次完整运行按下面的业务过程执行：

1. 工作流先使用平台保管的只读凭据，逐页读取本轮被授权的 BookStack 页面。
   每页正文只从客户系统公开接口取得，不相信调用者伪造的正文。
2. 它把不同页面整理成统一知识记录：保存来源身份、修订、标题、正文、岗位
   范围和客户链接。多页读取彼此隔离，一页结果不会覆盖另一页。
3. 同步阶段比较来源身份、修订和内容摘要。新页面插入，较新修订更新，明确
   删除的来源移出索引；相同事件重放返回同一结果，不产生第二份内容；旧修订
   试图覆盖新修订时以冲突停止。
4. 收到问题后，工作流先按提问者岗位排除无权访问的来源，再在剩余来源中比较
   具体业务词和语义相似度。常见虚词不会单独构成“有依据”。
5. 没有足够相关来源时直接拒答，并交付空引用。这样既覆盖真正不知道的问题，
   也覆盖“答案存在但当前岗位没有权限”的问题。
6. 找到授权依据后，从原文抽取可以回答问题的内容，并保存来源身份、页面链接和
   修订。回答不能引用权限过滤掉的页面。
7. 普通运营、安全和公共信息可以直接交付。财务、人事等敏感问题暂停，向复核人
   展示授权来源和拟交付内容；批准后回答，拒绝后清空引用并交付人工拒绝结论。
   暂停绑定当前运行，恢复另一条运行不会串线。
8. 所有分支最后都形成回答记录、权限检索轨迹和同步回执三份工件。一次拒答也
   是完整业务结果，不会被伪装成运行失败。

BookStack 只负责保存真实客户知识和权限背景。项目脚本负责建立受控测试页面、
通过公开 API 搭建和运行工作流，并核对 BookStack 的页面状态；问题回答、权限
过滤、人工分流、引用和拒答由发布工作流完成。

| 业务场景 | 输入如何设计 | 应做出的决定 | 允许的外部影响 | 实际结果 |
|---|---|---|---|---|
| 运营人员查询设备隔离 | 运营岗位询问一台设备的断电和上锁步骤 | 从运营规程回答并引用该页 | 只读 BookStack，不写客户系统 | 正确回答，引用运营来源 |
| 安全人员查询泄漏响应 | 安全岗位询问事故隔离距离 | 从安全手册回答并引用该页 | 无写入 | 正确回答，引用安全来源 |
| 访客查询公共联系人 | 无内部岗位的访客询问公开联系人 | 只使用公开页面 | 无写入 | 正确回答，未带入内部内容 |
| 财务敏感问题获批准 | 财务岗位询问付款审批规则，复核人批准 | 暂停一次，批准后交付授权来源 | 只保存人工决定 | 正确回答并引用财务页 |
| 人事敏感问题被拒绝 | 人事岗位有权检索，但复核人拒绝交付 | 保留复核前检索证据，最终不交付引用 | 只保存拒绝意见 | 返回人工拒绝，最终引用为空 |
| 越权查询财务规则 | 运营岗位询问只对财务开放的内容 | 在评分前过滤财务页并拒答 | 无 | 零候选、零禁止片段、明确拒答 |
| 完全不相关问题 | 询问知识库没有记录的事项 | 不借用弱相关公共页面拼答案 | 无 | 明确拒答 |
| 同一同步事件重放 | 使用相同事件身份和相同页面修订再次同步 | 返回已重放，不增加索引修订 | 无 | 索引修订不变，标记 replayed |
| 页面正常更新 | 管理员修改检查间隔并产生新修订 | 新内容替换旧内容，回答引用新修订 | 测试管理员写 BookStack 一次 | 旧值消失，新值和新修订被引用 |
| 旧修订倒灌 | 新修订生效后再次提交旧修订 | 以冲突拒绝，不能覆盖新内容 | 无 | HTTP 409，新内容保留 |
| 页面删除 | 管理员删除页面并发出删除同步 | 从索引移除，旧问题随后拒答 | 测试管理员删除 BookStack 一页 | 宿主返回 404，索引删除回执正确 |

本项目没有连接器写回失败场景，因为生产工作流对 BookStack 的权限明确是只读。
403 写入验证发生在环境准备阶段：只读身份尝试创建内容被 BookStack 拒绝，
证明工作流凭据本身没有修改客户知识的能力。

## 五、中间处理结果和最终输出

中间状态可以按一条问题逐步审查：

- 来源读取阶段保存 BookStack 页面身份、客户链接和读取成功状态；
- 标准化阶段形成统一的文档记录、岗位范围、修订和内容摘要；
- 同步阶段形成插入、更新、删除、未变化和重放计数，以及新的索引修订；
- 权限阶段形成授权文档数和被过滤来源身份，越权正文不会进入评分结果；
- 检索阶段形成候选来源、相关分数和 `forbidden_chunk_count`；
- 回答阶段形成回答或拒答、证据充分性、引用来源和所用检索/回答模型版本；
- 人工阶段保存批准或拒绝。拒绝后最终交付引用为空，复核前检索轨迹仍可审计。

最终三份 JSON 工件分别是：

1. **回答记录**：问题、回答或拒答、引用、人工决定、索引修订和模型版本；
2. **检索与权限轨迹**：调用者岗位、允许与过滤的来源、实际候选和禁止片段计数；
3. **同步回执**：事件身份、插入/更新/删除/重放结果、索引修订和内容摘要。

工件带有运行和生成节点来源。发布后 smoke run 直接指定 version 1，得到一个正确
运营回答、正确来源和三份工件，因此结果绑定的是客户实际可运行的发布版本。

## 七、Seed 设计和验收含义

公开案例会暴露岗位名、页面主题和答案位置，只通过公开问题无法排除 Builder
写死来源或依赖固定顺序。因此项目另有三个可重复伪随机 Seed。每个 Seed 从编号
确定业务分布，但每次尝试加入新的 nonce，保证失败重试不会复用来源或事件身份。

每个 Seed 新建一个 BookStack 书籍和六个真实页面，变化设备名、岗位身份、
安全距离、付款阈值、公共联系方式、检查周期、修订后的周期、敏感标记和人工
批准/拒绝。它包含 7 类问题：三个授权回答、一个敏感批准、两个不同原因的拒答、
一个敏感拒绝。随后再检查同步重放、页面更新、旧修订冲突和页面删除。

Builder 在工作流搭建和公开调试时看不到逐条 Seed 值、标准答案或 expected/actual
差异。受保护值只在同一验收进程内送入 BookStack 和公开工作流 API；证据文件
只保存场景类别、计数和布尔结论，不保存密封正文。每个 Seed 的来源、事件和
工作区都不同，可以发现固定 ID、固定答案、顺序依赖和跨运行状态污染。

“进程成功”只说明工作流没有崩溃；“7 个问题都有结果”也可能包含错误引用。
一个 Seed 真正通过，需要同时满足状态正确、来源正确、人工暂停次数正确、三份
工件齐全、禁止片段和受保护词命中均为零，以及四项知识生命周期结果和
BookStack 最终状态正确。

| Seed | 输入规模 | 关键场景 | 人工暂停 | 交付物 | 工作流结果 | 宿主验收 | 最终结论 |
|---|---:|---|---:|---:|---|---|---|
| 2201 | 7 个问题 + 4 项生命周期 | 授权、越权、无依据、批准、拒绝、重放、更新、删除 | 2 | 33 | 7/7 问题，4/4 生命周期 | 新书和页面状态正确 | 通过 |
| 2202 | 7 个问题 + 4 项生命周期 | 全部身份、业务值和事件位置重新变化 | 2 | 33 | 7/7 问题，4/4 生命周期 | 新书和页面状态正确 | 通过 |
| 2203 | 7 个问题 + 4 项生命周期 | 再次变化来源、修订、人工决定和受保护值 | 2 | 33 | 7/7 问题，4/4 生命周期 | 新书和页面状态正确 | 通过 |

三个 Seed 全绿证明工作流没有依赖公开页面 ID、固定答案或固定事件身份，并且在
本题冻结的岗位、更新和删除变化范围内没有可见状态串线。Seed 生成器和验收器
仍由同一仓库上下文编写，所以它是受控密封回归，不是第三方独立黑盒认证。

## 八、失败、偏差和剩余差异

本项目保留了全部主要失败，没有用最终 7/7 抹掉调试过程：

1. 前两个空应用搭建失败。第一次把循环的输出当成输入集合；第二次漏了嵌套终点，
   且 Builder 的断言错误地要求嵌套 HTTP 调用出现在顶层。这些是 Builder 图设计
   和测试边界错误，没有业务运行。
2. 第三个应用的强制测试已经通过，但 Builder 脚本读错公开返回字段，误认为没
   有测试结果。只修正客户端解析，没有修改工作流。
3. 第一次公开 debug 因工作区未先创建而被入口拒绝，业务运行数为零。修正环境
   初始化后再测试。
4. 第一轮完整公开测试只有 4/7。常见英文虚词让无关公共页获得了弱匹配；同时
   验收器错误地要求人工拒绝后仍交付引用。直接证据显示权限内容没有进入候选，
   知识更新、删除和重放均正确。修复的是通用相关性排序和验收语义，随后相同
   工作流 7/7。
5. 第一次 Seed 2201 为 5/7。Seed 把受保护标记本身放进用户问题，又让“无依据”
   问题复用真实公共页中的站点标记，制造了两个错误标准。只修 Seed，没有改
   工作流或平台。
6. 第二次 Seed 2201 重试复用了来源和事件身份，平台正确触发幂等冲突。修复是
   为每次尝试加入 nonce；没有删除平台账本，也没有削弱项目幂等键。

最终没有未解释的业务差异。剩余证据债务是没有大规模多语言语料性能测试、
没有外部独立审计，以及密封 Seed 与实现处在同一仓库控制边界。

## 九、平台补能与膨胀控制

公开积木目录和公开 OpenAPI 在项目开始时只有“调用一个已嵌入工作流”的
embedding 接口，不能表达持续知识库所需的文档同步、修订冲突、删除、检索前
ACL、依据引用和明确拒答。这是工作流搭建者在正常真实业务中就会遇到的通用
能力缺口，不是从隐藏题目或源码答案反推出来的。

最小补能放在一个可选的 `enterprise_rag` 领域模块中：

- 一项宿主无关的持久知识索引服务；
- 三项面向业务阶段的能力：同步知识、按权限检索、依据检索结果回答或拒答；
- 六个公开管理/调用接口，用于创建和查看索引、同步、检索和回答。

为什么不是项目专用硬编码：

- 平台代码没有 BookStack 页面字段、端点、页面 ID、岗位值或本题答案；
- BookStack 到统一文档合同的映射只存在于工作流配置；
- 通用测试使用仓库安全手册、财务手册、公共应急信息和人事材料等另一组来源，
  验证权限、更新、删除、重放和无依据拒答；
- 同一能力可以连接 Confluence、SharePoint、文件库或数据库，只要 Builder
  将客户来源转换为统一文档记录。

本项目净增加 **1 个可选领域服务、3 个工作流能力、0 个 BookStack 专用积木**。
不建议再拆成“插入一页、更新一页、删除一页、算一个分数、拼一个引用”等大量
原子积木，那会把生命周期一致性转嫁给 Builder 并膨胀目录。同步、权限检索、
依据回答应作为一个可安装领域模块共同演进；未使用 RAG 的客户不需要加载它。

聚焦回归为 4/4，另有最终项目重跑、公开生命周期和三个 Seed。严格能力登记制度
要求的 fresh-context 独立复核尚未运行，因为当前任务没有获得子智能体委派授权；
这限制通用能力登记的证据等级，但不抹掉已经完成的客户业务运行。

## 十、Builder 表现和经验

本次 Builder 是当前 Codex，通过公开平台 API 从空应用搭建；没有启动外部 Codex
Builder，也没有让 Lilies 模型代跑。Lilies 模型调用次数为 0，Lilies token 为
0，因此“单次 Lilies 运行最多 1,000,000 token”的硬停没有触发。当前 Codex
会话的账户 token 不在 Lilies 平台账本中，不能伪造为 Lilies 消耗。

最有效的收敛方式是先完整检查七类问题和四类知识生命周期，再按共同根因一次性
修正相关性，而不是对每条问题疯狂迭代。导致无效工作的主要原因是嵌套图边界
判断错误、客户端字段假设和 Seed 设计把测试数据本身变成了答案线索。

应沉淀到后续 Prompt、Skill 和测试框架的经验：

- 先核对业务回答、权限过滤和客户系统状态，最后看图结构；
- 人工拒绝必须区分“复核前可以看到的授权证据”和“最终允许交付的内容”；
- 密封 Seed 的问题文本不能包含要检查是否泄漏的受保护值；
- 重试 Seed 必须轮换尝试身份，不能清空真实幂等状态来刷通过；
- 只有重复出现在不同业务来源上的能力，才进入可选领域模块；项目映射留在工作流。
