## Problem

v0.3.4 intended to add browser-click evidence now that safe drafts have visible skeletons. The Browser plugin was initialized according to its skill, but `agent.browsers.list()` returned an empty list. The project must record this truth and use an honest fallback instead of claiming browser interaction.

## Boundary

This design does not add Playwright or a new browser dependency. It records browser unavailability and collects rendered HTTP evidence for home/detail routes plus API evidence from existing harnesses. It does not call `/builds`.

## Solution

Add a v0.3.4 evidence script that:

- records browser availability status as an input/evidence field,
- fetches the home page and latest smoke detail route as rendered HTML,
- verifies the safe draft UI markers are present in the rendered home page,
- verifies detail route renders for the latest smoke app,
- emits JSON explaining that this is fallback rendered-route evidence, not browser-click evidence.

## Acceptance Criteria

- Evidence explicitly says Browser was unavailable.
- Fallback rendered-route checks pass.
- No build endpoint is called.
- Focused pytest passes.
- Stage report does not claim browser-click completion.

## Evidence Requirements

- Browser setup attempt summary from workingon.
- v0.3.4 JSON evidence.
- Focused pytest command.
