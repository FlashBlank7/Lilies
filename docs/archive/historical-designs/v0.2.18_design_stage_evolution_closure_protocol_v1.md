# design_stage_evolution_closure_protocol_v1

## 1. Goal

把版本推进从“选择一个下一步任务并做一个切片”改成严肃的 stage-level delivery：

- stage report 是唯一下一步指导来源。
- 一个小版本要承接上一份 stage report 的完整 next-task set。
- next-task set 中每个 accepted task 都要展开成 design。
- 每个 design 必须切实完成或明确 blocked/deferred/superseded。
- 工程任务和实验任务都必须完成 closure gate，不能半吊子归档。

## 2. Module Boundary

本设计只修改项目演进 skill 和模板，不修改后端运行时代码。

涉及文件：

- `skills/lilies-evolution-development/SKILL.md`
- `skills/lilies-evolution-development/references/templates.md`

## 3. Control Flow

1. 从最新 stage report 读取完整 next-stage task set。
2. 将每个 accepted task 展开为 current-design。
3. 按 design 顺序实施。
4. 每个 design 通过工程 closure gate。
5. stage report 记录下一阶段任务，是唯一下一步指导来源。

## 4. Implementation Plan

- 增加 `Stage Authority Model`。
- 修改 Automatic Evolution Mode 的 next-stage 选择规则。
- 增加 `Engineering Capability Closure Gate`。
- 强化 `Minor Version Completion Gate`。
- 修改 stage report / workingon / current-design 模板字段。

## 5. Acceptance Criteria

- Skill 明确禁止随便挑一个 next-stage task。
- Skill 明确 current-design 不具备 next-stage 指导权。
- Skill 明确 workingon 不具备 next-stage 指导权。
- Skill 明确工程能力必须声明 closure level。
- 模板要求 stage report 记录 next-task set、closure level、design 展开情况。
- `quick_validate.py` 通过。
