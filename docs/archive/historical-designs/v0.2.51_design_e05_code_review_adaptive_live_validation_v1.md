## Problem

After `v0.2.49`, Lilies had only one adaptive live-validation family and could not tell whether adaptive also worked on a contrasting shallow-resolving family.

## Boundary

- In scope: one bounded paid/live `code_review` slice using the canonical E05 runner.
- In scope: raw JSON, summary Markdown, concise DOCX, and ledger/index updates.
- Out of scope: Builder default-switch code, broad E05 framework redesign, or E08 Harness comparison work.

## Final Design

- Use `code_review` as the contrasting family because existing deterministic evidence predicts `adaptive -> shallow`.
- Run `shallow / deep / adaptive` under the same bounded budget.
- Judge success by operational outcome, benchmark cleanliness, and adaptive resolution readability rather than benchmark score alone.

## Acceptance

- A second-family adaptive live result exists and is readable from summary artifacts.
- The report states whether adaptive resolves to `shallow` and how it compares to fixed-depth arms.
- E05 ledger/index can be read without opening raw JSON.
