# design_platform_harness_network_egress_policy_v1

## 1. Goal

Add Platform Harness network egress policy for WorkflowRuntime HTTP blocks, so a workflow-internal `http_request` block cannot bypass platform-level outbound network rules.

## 2. Module Boundary

In scope:

- `platform/backend/src/agent_platform/config.py`
- `platform/backend/src/agent_platform/api.py`
- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`
- `tests/test_workflow.py`

Out of scope:

- Tool-level WebSearch and MCP network policy.
- Sandbox/container firewall.
- DNS/IP egress enforcement.
- UI controls.

## 3. Control Flow

```text
WorkflowRuntime._http()
  -> resolve URL
  -> validate scheme/hostname
  -> PlatformHarness.enforce_network_egress_policy(surface="http_request", hostname=parsed.hostname)
  -> resolve headers/query/body
  -> secret policy check
  -> httpx request
```

## 4. Implementation Plan

1. Add config:
   - `platform_harness_network_egress_policy`
   - `platform_harness_network_egress_allowlist`
2. Add `PlatformHarness.enforce_network_egress_policy()`.
3. Support:
   - `full`: allow
   - `none`: block all
   - `allowlist`: allow exact host or subdomain of allowlist entry
4. Wire into `WorkflowRuntime._http()`.
5. Add regression test for `none` policy.

## 5. Referenced Intellectual Assets

- `docs/intellectual-assets/asset_platform_harness_task_monitor_boundary.md`

## 6. Risks

- HTTP block only; tool-level egress remains future work.
- Allowlist host matching is hostname-based, not DNS/IP firewall enforcement.
- Overly strict policy can block legitimate integrations.

## 7. Acceptance Criteria

- HTTP block egress can be blocked by platform config.
- Default behavior remains unchanged.
- Full backend regression passes.
