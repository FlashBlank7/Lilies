## Problem

v0.2.71 default-safety gate identified `requirement_classification_contract` as a missing prerequisite. The platform needed executable simple / medium / complex classes before override plans or rollout metrics could be meaningful.

## Boundary

This design defined and exposed the classification contract. It did not enable complexity-router defaults or implement override/metrics guardrails.

## Final Design

- `simple`, `medium`, `complex`, and `unknown` requirement classes are defined in backend policy code.
- `unknown` is handled conservatively with effective class `complex`.
- API surfaces expose contract status and one-off classification.
- Default-safety now marks `requirement_classification_contract=true`.
- Default-safety still returns `allowed_to_enable_default=false` because override and metrics are missing.

## Acceptance

- Tests cover simple, medium, complex, and unknown classifications.
- API exposes classification contract and classification output.
- Default-safety no longer lists classification as missing.
- Router defaults remain disabled.

- Backend: `platform/backend/src/agent_platform/complexity_router.py`

## Remaining Risk

Operator override plan and rollout metrics remain required before defaults can be allowed.
