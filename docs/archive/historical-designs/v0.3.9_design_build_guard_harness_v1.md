## Problem

The regression suite must fail if v0.3.9 evidence accidentally starts `/builds`. The stage also must preserve runtime status and cleanup behavior from earlier v0.3.x work.

## Boundary

The harness should not test the actual second-click build path because that would intentionally trigger model/team work. It only verifies that rendered/source guard markers exist and that the evidence flow stays no-build.

## Solution

Add a v0.3.9 harness that:

- checks runtime health,
- verifies home/detail build guard markers,
- verifies safe draft markers remain,
- creates and deletes a `v0.3.9-smoke` app without builds,
- records the endpoint call ledger.

## Acceptance Criteria

- Source and rendered guard markers pass.
- No `/builds` call occurs.
- Smoke app is cleaned.
- Runtime status markers are preserved.

## Evidence Requirements

- `scripts/v03_9_build_action_guard.py`.
- `tests/test_v03_9_build_action_guard.py`.
- v0.3.9 JSON evidence in `workingon/`.
