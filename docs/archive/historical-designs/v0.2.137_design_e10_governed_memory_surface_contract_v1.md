## Problem

v0.2.136 accepted the E10 governance boundary, but there is still no product-facing surface contract for governed memory operations. Without a contract, future implementation can drift into unrestricted assistant memory, background filesystem indexing, missing audit, or non-revocable records.

## Contract

The surface must provide permission-scoped operations for:

- create
- read
- update
- revoke
- expire

Every operation must enforce the same governance controls:

- explicit permission scope
- audit log with actor, source, reason, timestamp
- revoke exclusion from retrieval
- retention class and expiry
- source attribution
- no unrestricted filesystem memory

## Implementation Shape

- Add a backend `GovernedMemorySurface` service under `agent_platform`.
- Persist records through `Storage` rather than process memory.
- Emit append-only audit events through the existing event store.
- Expose minimal API endpoints so the contract is product-visible and testable.

## Completion Criteria

- Focused tests prove create/read/update/revoke/expire.
- Focused tests prove audit fields for each operation.
- Focused tests prove unscoped permission and filesystem memory rejection.
- Evidence script summarizes contract coverage.

## Final State

The governed memory surface contract is implemented in backend code with persistent storage, append-only audit events, and product-visible API routes. It remains a governed surface contract slice, not a claim that runtime assistant retrieval or Studio UI has been completed.
