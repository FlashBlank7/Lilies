# v0.2.120 Worker Catalog Transition Design

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.119_e08_remaining_sidecar_slice_reselection.md`

## Problem

After v0.2.118, `workflow_run`, `test_suite`, `scheduler_trigger`, and `scheduler_manual_trigger` are implemented. `draft_patch_preview` should now move from deterministic unavailable to implemented, while remaining task kinds keep explicit gap behavior.

## Final Scheme

Move `draft_patch_preview` into `IMPLEMENTED_WORKER_HANDLERS` with v0.2.120 evidence and register `draft_patch_preview_handler()` in `build_platform_worker_handlers()`.

The catalog should then report:

- `draft_patch_preview` implemented;
- `workflow_run` implemented;
- `test_suite` implemented;
- scheduler handlers implemented;
- `builder_build` and `benchmark` unavailable;
- full execution coverage still false.

## Acceptance

- Catalog API shows `draft_patch_preview.status == implemented`.
- Remaining unavailable handlers still fail deterministically.
- `not_full_sidecar_completion` remains true.
