## Problem

Disabling run buttons without explanation can look like a bug. Users need to know that a run is already active and that they can wait or cancel explicitly.

## Boundary

- Guidance only.
- No automatic cancel.
- No automatic retry.

## Solution

- Add a compact active-run guard strip when `tryRunActive` is true.
- Add `data-try-run-start-guard="active"` marker.
- Add copy that points users to wait or cancel.

## Acceptance Criteria

- Active guard text appears only for queued/running states.
- Copy clearly says wait or use the cancel button.
- The explicit cancel button remains visible in the result panel.

## Final State

- Added `data-try-run-start-guard="active"`.
- Added `tryRunActiveGuardTitle`, `tryRunActiveGuardDetail`, and `tryRunActiveGuardNotice`.
- Added `.try-run-start-guard` styling.
- Existing cancel button remains enabled for queued/running and disabled only for terminal/paused states.
