# design_harness_sidecar_passmode_task_monitor

## 1. Goal

明确 Harness 在工作流中的表达方式：工作流内 soft harness block 负责业务可见约束，平台外 sidecar / task monitor boundary 负责不可绕过的硬治理。

Status: implemented as event interface v1 on 2026-07-08.

## 2. Module Boundary

候选模块：

- `workflow_runtime.py`
- `runtime.py`
- `scheduler.py`
- `api.py`
- future task monitor service

## 3. Control Flow

BlockFlow 执行到关键节点 -> soft harness block 记录意图和状态 -> sidecar monitor 接收事件 -> 根据权限、预算、passmode、取消和审计规则决定是否继续、暂停或失败。

## 4. Implementation Plan

1. 已在 `WorkflowRuntime` 中新增统一 `harness.signal` 事件接口。
2. soft harness block 继续在工作流内表达业务可见约束。
3. passmode 仍应作为平台治理策略，不作为 prompt-only 约束。
4. 所有模型调用、测试套件、Builder build、Scheduler 触发进入 task monitor boundary。

## 5. Acceptance Criteria

- 不再把 `budget_gate` 误称为平台硬边界。
- E08 能比较 workflow-internal gate 和 sidecar monitor 表达。
- 后续代码设计能定位取消、预算、重试和恢复责任。
