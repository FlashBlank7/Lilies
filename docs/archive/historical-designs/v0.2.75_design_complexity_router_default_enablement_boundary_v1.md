## Problem

Default-safety prerequisites were satisfied, but default router behavior was still disabled. The project needed an explicit decision before any default change.

## Boundary

This design made an enablement-boundary decision only. It did not enable complexity-router defaults or change builder behavior.

## Final Design

- Decision selected `require_live_validation_before_default_change`.
- Immediate enablement review was deferred.
- `default_enabled=false` remains unchanged.
- `allowed_to_enable_default=true` is treated as readiness for review, not activation.

## Acceptance

- Decision evidence selects one option.
- Tests verify the selected option and reject immediate enablement review.
- Next stage is a live validation plan.
