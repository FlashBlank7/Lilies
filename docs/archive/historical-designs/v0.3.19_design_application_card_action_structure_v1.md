## Problem

Search and sort help users find the right application, but the card still behaves mainly as one large link. Non-technical users need explicit safe next actions after finding an app.

## Boundary

- Do not call `/builds`, `/tests/run`, `/runs`, or publish endpoints from home-card quick actions.
- Avoid nested interactive elements inside a `Link`.
- Use existing application readiness fields only.

## Solution

- Refactor each app card into an `article` with a primary detail link and a separate action strip.
- Add readiness-dependent actions that route to existing detail surfaces.
- Preserve card readiness chips, next-action copy, and meta information.

## Acceptance Criteria

- App cards no longer nest action controls inside a link.
- Quick actions are visible, accessible, and state-dependent.
- All quick actions are navigation-only.
