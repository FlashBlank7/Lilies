## Problem

v0.2.72 default-safety gate identified `operator_override_plan` as a missing prerequisite. Operators needed an API-visible override plan with allowed modes and reasons before defaults could ever be considered.

## Boundary

This design defined and exposed the override plan. It did not enable complexity-router defaults or implement rollout metrics.

## Final Design

- Allowed modes are `disabled`, `force_simple`, `force_medium`, and `force_complex`.
- Force modes require a non-empty operator-visible reason.
- Unsupported modes are rejected.
- Default-safety now marks `operator_override_plan=true`.
- Default-safety still returns `allowed_to_enable_default=false` because rollout metrics are missing.

## Acceptance

- Tests cover allowed modes, reason-required rejection, and unsupported-mode rejection.
- API exposes override plan status and validation.
- Default-safety no longer lists override plan as missing.
- Router defaults remain disabled.

## Remaining Risk
