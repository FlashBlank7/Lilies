## Problem

v0.3.0 added deterministic source checks and curl evidence, but the project still lacks an owned customer-flow harness and a reproducible P0/P1 bug ledger. Without that, bug self-check can drift back into ad hoc observation.

## Boundary

The first v0.3.1 harness should be lightweight and deterministic. It should avoid triggering paid model calls or mutating application data by default. Live HTTP checks are allowed for home and health endpoints, but the build POST path should remain a later bounded test.

## Solution

Add a versioned audit script that:

- defines customer requirement fixtures as testable data,
- checks fixture quality and persona coverage,
- checks frontend source markers for the intake panel,
- optionally checks local live frontend and backend health endpoints,
- emits machine-readable JSON to `docs/workingon/`,
- includes a P0/P1 bug ledger with reproduction class, severity, fix/defer disposition, and verification status.

## Implementation Plan

1. Create `scripts/v03_1_customer_flow_blackbox_audit.py`.
2. Add deterministic fixture, source-marker, and bug-ledger checks.
3. Add optional `--live` checks for `http://127.0.0.1:3000/` and `http://127.0.0.1:8001/health`.
4. Add focused pytest coverage.
5. Run the script with live checks while local servers are available and archive the JSON evidence.

## Acceptance Criteria

- Audit exits non-zero if fixture quality, UI markers, or bug ledger gates fail.
- Audit covers at least four customer personas.
- Audit records no open P0/P1 in the covered scope.
- Optional live checks pass when local services are running.
- Focused pytest passes.
- Evidence is archived with the stage.

## Evidence Requirements

- Audit command and generated JSON path.
- Pytest command.
- Frontend TypeScript/build command if UI changed.
- Remaining limits recorded in workingon and stage report.
