## 1. Goal

Make the E05 runner support multiple Template-friendly task families and pass v0.2.42 build-level watchdog settings to Builder builds.

## 2. Module Boundary

Primary files:

- `scripts/e05_template_reuse_depth_experiment.py`
- `tests/test_e05_template_reuse_depth_experiment.py`

Read-only dependencies:

- `templates/customer_support_router.json`
- `platform/backend/src/agent_platform/workflow_models.py`
- `platform/backend/src/agent_platform/builder.py`

## 3. Data Flow / Control Flow

Current chain:

1. E05 runner hardcodes code-review requirement and benchmark reference.
2. It passes `max_turns` and `max_repair_cycles` to Builder.
3. It does not pass `max_elapsed_seconds`.

Target chain:

1. E05 runner selects a case from `E05_REUSE_DEPTH_CASE`.
2. Default case remains `code_review`.
3. New case `customer_support_router` uses a routing/classification requirement and benchmark reference.
4. Runner passes `E05_REUSE_DEPTH_MAX_ELAPSED_SECONDS` to Builder when configured.
5. Result JSON records selected case and build-level budget.

## 4. Implementation Plan

1. Add `ExperimentCase` dataclass.
2. Add `experiment_case(name)` with `code_review` and `customer_support_router`.
3. Keep existing public helpers compatible by defaulting to `code_review`.
4. Update `run_template_preflight()`, `run_arm()`, and benchmark payloads to use the selected case.
5. Add optional `MAX_ELAPSED_SECONDS` env parsing and build payload field.
6. Add deterministic tests for customer-support case selection and build payload deadline.

## 5. Acceptance Criteria

- Existing E05 tests still pass: `.venv/bin/python -m pytest tests/test_e05_template_reuse_depth_experiment.py -q` -> `6 passed`.
- New tests prove customer-support requirement/reference differ from code-review case: `test_e05_customer_support_case_has_distinct_requirement_and_reference`.
- Runner budget includes `max_elapsed_seconds`: raw result `budget.max_elapsed_seconds_per_arm=600.0`.
- Builder payload includes `max_elapsed_seconds` when configured: `test_e05_build_payload_includes_optional_build_deadline`; paid/live builder task metadata records `max_elapsed_seconds=600.0` for all arms.
