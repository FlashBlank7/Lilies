## Problem

Returning users and demo reviewers see application cards with name, description, revision, and version/hash metadata, but not whether an application is ready to demo, needs acceptance, or should be published.

## Boundary

- Use only fields already available on the application list.
- Do not add new backend endpoints.
- Keep cards compact and mobile-safe.

## Solution

- Derive app-card readiness from draft revision, tested hash, and active version.
- Add card-level readiness chips and a next-action sentence.
- Add stable `data-app-card-guidance` markers for harness checks.

## Acceptance Criteria

- Application cards show draft, acceptance, and publish/readiness state.
- Application cards show a next action for draft-only, tested-unpublished, and published cases.
- The new copy is bilingual and does not require raw metadata interpretation.
