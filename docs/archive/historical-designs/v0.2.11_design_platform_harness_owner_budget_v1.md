# design_platform_harness_owner_budget_v1

## 1. Goal

Add a Platform Harness hard boundary for owner/account-level usage budgets. This builds on v0.2.10 durable task usage records and prevents separate tasks under the same `owner_id` from bypassing per-task limits by spreading work across many tasks.

## 2. Module Boundary

In scope:

- `platform/backend/src/agent_platform/config.py`
- `platform/backend/src/agent_platform/storage.py`
- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/api.py`
- `tests/test_workflow.py`

Out of scope:

- User/account database schema.
- Billing integration.
- Time-window reset policy.
- UI visualization.
- Secret policy and network egress policy.

## 3. Control Flow

```text
PlatformHarness.record_usage(task_id, usage_type, amount)
  -> hydrate task from durable storage if needed
  -> read owner_id from PlatformTaskRecord
  -> Storage.sum_platform_usage_count(owner_id, usage_type)
  -> compare prior owner usage + amount with configured owner budget
  -> if exceeded, mark current task failed and raise PlatformHarnessViolation
  -> persist failed task record before emitting violation event
```

## 4. Implementation Plan

1. Add config fields:
   - `platform_harness_max_model_calls_per_owner`
   - `platform_harness_max_tool_calls_per_owner`
   - `platform_harness_max_node_executions_per_owner`
2. Default all owner budgets to `0`, meaning disabled.
3. Add `Storage.sum_platform_usage_count(owner_id, usage_type)`.
4. Extend `PlatformHarness.__init__()` and `build_services()`.
5. Add owner violation messages:
   - `owner model call budget exceeded`
   - `owner tool call budget exceeded`
   - `owner node execution budget exceeded`
6. Add a regression test that:
   - starts task A for owner X
   - records usage within budget
   - finishes task A
   - starts task B for owner X
   - records usage that exceeds owner cumulative budget
   - verifies task B fails with owner budget error

## 6. Risks

- Lifetime owner budget can be too strict without reset windows. Default disabled avoids changing existing behavior.
- `owner_id` is currently a task owner string, not a formal billing account ID.
- This is a hard Platform Harness boundary, but not yet a complete account governance system.

## 7. Acceptance Criteria

- Owner budgets are configurable.
- Default config preserves current tests.
- Owner budget can block cross-task usage deterministically.
- The failure is persisted in the task record and visible through API/Platform Harness queries.
