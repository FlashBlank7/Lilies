# design_platform_harness_stdio_mcp_egress_guard_v1

## 1. Goal

Add a hard Platform Harness guard for stdio MCP servers under restricted network policies.

## 2. Module Boundary

Backend:

- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/runtime.py`
- `platform/backend/src/agent_platform/workflow_runtime.py`

## 3. Data Flow / Control Flow

1. Runtime prepares to execute MCP tool input with `server`.
2. Runtime finds the configured MCP server.
3. If server transport is HTTP, existing hostname egress policy remains in effect.
4. If server transport is stdio, Platform Harness checks platform policy and agent policy.
5. If either policy is not `full`, runtime raises a Platform Harness violation before starting the stdio process.

## 4. Implementation Plan

1. Add `enforce_stdio_mcp_policy()` to Platform Harness.
2. Wire AgentRuntime MCP policy enforcement to call it for stdio servers.
3. Wire WorkflowRuntime MCP policy enforcement to call it where server metadata exists.
4. Keep the error message explicit: stdio MCP has no declared hostname and requires sandbox/container boundary before restricted egress can be honored.

## 5. Acceptance Criteria

- Restricted agent policy blocks stdio MCP. Completed.
- Restricted platform policy blocks stdio MCP. Completed.
- Full/full policy does not block stdio MCP at the guard. Completed.
- HTTP MCP policy is unchanged. Completed.
