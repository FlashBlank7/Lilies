# v0.2.116 Worker Catalog Transition Design

## Source

- Source stage report: `docs/stage-report-archives/v0.2.x/v0.2.115_e08_remaining_sidecar_slice_reselection.md`
- Source task: `Implement workflow_run worker offload handler`
- Current version: `v0.2.116_e08_workflow_run_worker_offload_handler`
- Status: completed

## Problem

After v0.2.114, `scheduler_trigger` and `scheduler_manual_trigger` are implemented. `workflow_run` should now move from deterministic unavailable to implemented, while remaining task kinds keep explicit gap behavior.

## Final Scheme

Move `workflow_run` into `IMPLEMENTED_WORKER_HANDLERS` with v0.2.116 evidence and register `workflow_run_handler()` in `build_platform_worker_handlers()`.

The catalog should then report:

- `workflow_run` implemented;
- `scheduler_trigger` implemented;
- `scheduler_manual_trigger` implemented;
- `builder_build`, `test_suite`, `benchmark`, and `draft_patch_preview` unavailable;
- full execution coverage still false.

## Acceptance

- Catalog API shows `workflow_run.status == implemented`.
- Remaining unavailable handlers still fail deterministically.
- `not_full_sidecar_completion` remains true.

## Final Status

Completed in v0.2.116.
