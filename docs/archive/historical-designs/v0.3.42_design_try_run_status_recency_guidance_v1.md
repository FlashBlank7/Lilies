## Problem

A last-checked timestamp can be misread as the backend finishing time. The UI must explain that it is local UI refresh recency and that final truth still comes from the run status.

## Boundary

- Copy only.
- Do not claim real backend completion time.
- Do not infer stale failure from age.

## Solution

- Add concise recency copy beside the last-checked value.
- Say that the page is checking status, while final status still comes from the run result.
- Keep the copy distinct from cancellation progress and output preview.

## Acceptance Criteria

- Copy distinguishes UI refresh recency from final run status.
- Copy does not tell users to start another run while active.
- Copy works for active and terminal statuses.
