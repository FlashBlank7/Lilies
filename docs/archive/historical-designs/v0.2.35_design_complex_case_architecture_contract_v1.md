# design_v0.2.35_complex_case_architecture_contract_v1

## Goal

Strengthen the `complex_research_brief` benchmark case so the Builder-facing requirement explicitly requires the same visible architecture that the benchmark checks.

## Module Boundary

- In scope:
  - `scripts/live_builder_benchmark_suite.py`
  - deterministic case-registry tests
- Out of scope:
  - Builder prompt rewrite
  - benchmark scoring changes
  - product UI changes

## Design

Update `complex_requirement` to explicitly state that the BlockFlow must include these node types and that `context_assembler` must not be replaced by `variable_aggregator` or direct LLM prompt wiring:

- `start`
- `parameter_extractor`
- `question_classifier`
- `context_assembler`
- `llm` or `model_turn`
- `template_transform`
- `event_recorder`
- `end`

Also require tests to include the same `required_node_types` list.

## Acceptance Criteria

- Deterministic test asserts the complex requirement contains `context_assembler`.
- Deterministic test asserts the required node list remains a subset of the reference workflow.
- No paid call is made by deterministic tests.

## Final Status

Completed.

Implementation:

- `scripts/live_builder_benchmark_suite.py` now explicitly requires `context_assembler` and the visible architecture node list in the `complex_research_brief` requirement.
- `tests/test_workflow.py::test_live_builder_benchmark_case_registry_supports_complex_case` asserts the requirement contains the `context_assembler` contract and the `variable_aggregator` prohibition.

Verification:

- Focused deterministic tests: `3 passed, 1 warning` after the runtime continuation slice.
- Paid/live evidence: v0.2.35 first and retry runs both included `context_assembler` and benchmark passed, proving the architecture contract repaired the v0.2.34 coverage gap.

Remaining risk:

- This design fixes the single complex benchmark case contract. It does not prove all complex requirements will preserve visible architecture without additional benchmark cases.
