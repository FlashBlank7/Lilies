## Problem

The worker runner currently lists queued tasks and then claims a task by id. That is not a strong distributed queue ownership primitive because multiple workers can observe the same queued task before one claims it. The harness also has lease expiry failure behavior, but no queue-specific requeue semantics for recoverable worker loss.

## Proposed Slice

Add storage-backed queue ownership primitives:

- atomic claim-next for queued tasks
- requeue-expired lease semantics that clears worker ownership and returns tasks to `queued`
- queue snapshot showing counts, leased workers, and boundary flags
- worker runner consumption through claim-next rather than list-then-claim

## Acceptance

- Concurrent claim-next calls produce single-owner task claims.
- Expired leased tasks can be requeued without marking them failed.
- Worker runner consumes queue tasks via claim-next.
- Queue semantics snapshot is exposed and keeps external process/KMS/full-sidecar boundaries false.
