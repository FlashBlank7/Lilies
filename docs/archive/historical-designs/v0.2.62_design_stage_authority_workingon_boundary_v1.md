## Problem

The skill incorrectly made `workingon` responsible for task decomposition. That violated the project hierarchy where stage reports are the only next-stage authority.

## Boundary

- In scope: skill, operating gates, project strategy, docs index.
- Out of scope: rewriting historical workingon archives.

## Final Design

Next-stage tasks come only from the latest stage report's `Next-stage Task Set`. `workingon` is optional and only stores intermediate evidence, implementation notes, experiment traces, and temporary investigation records. Current designs must cite the source stage report and task.

## Acceptance

- Main skill no longer tells the agent to split tasks in workingon.
- Operating gates remove workingon task authority.
- Project strategy and docs index state the corrected boundary.
