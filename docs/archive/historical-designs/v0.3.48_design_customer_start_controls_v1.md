# design_v0348_customer_start_controls

Status: completed

## Source

- Source stage report: `docs/stage-report-archives/v0.3.x/v0.3.47_natural_language_workflow_edit.md`
- Source task: Add customer-facing start controls.
- User product correction: a user should see a prompt or a start button, not an engineering harness.

## Problem

The current Run tab exposes form fields and raw payload first. A non-technical user needs a small "what should I enter" area and one obvious start action.

## Boundary

- Reuse current Start/User Input node field parsing.
- Preserve draft and published mode buttons for control.
- Do not auto-start model/runtime work without an explicit button click.

## Proposed Solution

- Wrap the input form and start buttons in a customer start panel.
- Label the panel as the user-facing input/start area.
- Explain the next action in customer terms.
- Keep sample-fill and raw payload preview as secondary controls.

## Acceptance Criteria

- Run tab exposes a customer start panel before raw payload details.
- Primary action is obvious and guarded by existing input validation.
- Start controls remain explicit and do not call run APIs until clicked.

## Final Evidence

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` with `data-customer-run-interface="start-controls"`.
- Raw payload preview is now a secondary details block with `data-customer-run-interface="raw-payload"`.
- Verified by `tests/test_v03_48_customer_facing_workflow_run_interface.py`.
