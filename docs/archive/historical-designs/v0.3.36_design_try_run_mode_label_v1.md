## Problem

The Try tab has separate draft and published run buttons, but the result panel does not clearly show which mode produced the latest result. Non-technical users can confuse a draft debug result with a fixed published-version validation.

## Boundary

- Frontend-local state only.
- No backend schema change.
- No mutation beyond the existing explicit run buttons.

## Solution

- Add `lastRunMode` local state.
- Set it inside `startRun(useDraft)`.
- Render `data-try-run-mode` in the result panel.
- Mark the run buttons with mode action data.

## Acceptance Criteria

- Draft button sets draft mode.
- Published button sets published mode.
- Unknown mode has an explicit fallback.
- Source, i18n, style, and manifest markers are covered by v0.3.36 tests.

## Final State
