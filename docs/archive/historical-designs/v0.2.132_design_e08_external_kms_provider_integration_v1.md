## Problem

v0.2.108 created a local rotation-aware secret envelope, but the envelope key still lives directly in Platform Harness settings. v0.2.132 must add a real provider boundary: Platform Harness should encrypt secret values with a data key and ask a KMS provider to wrap and unwrap that data key.

## Implementation Contract

- Add a `SecretKMSProvider` protocol with wrap, unwrap, and status methods.
- Add a deterministic local provider implementation for tests and local development.
- Add v3 secret envelope writes when a provider is configured.
- Preserve v2, v1, and legacy plaintext read compatibility.
- Expose provider-backed storage mode and policy-control status.
- Wire API settings into the provider.

## Envelope Contract

New provider-backed secrets use `secret-envelope:v3:` and include:

- `provider_id`
- `key_id`
- `wrapped_data_key`
- authenticated ciphertext metadata
- no plaintext secret material

## Completion Criteria

- New secrets use v3 provider-backed envelope when KMS provider is configured.
- Provider unwrap is required to read v3 rows.
- Public secret metadata reports `encrypted_v3:<provider>:<key_id>`.
- Policy controls report `external_kms_provider_integration=true`.
- v2/v1/plaintext compatibility tests still pass.
- Full Platform Harness sidecar completion is not claimed.
