## Problem

The Try tab has a form and JSON preview, but non-technical users still need to infer whether the draft is runnable, whether inputs are valid, and whether a published version exists.

## Boundary

Do not change workflow runtime semantics. Add guidance around existing run controls.

## Solution

- Add a compact Try readiness panel with draft, input, published-version, and latest-run status.
- Add stable `data-try-guidance` markers.
- Keep existing draft and published run buttons.

## Acceptance Criteria

- Try tab shows readiness before the form.
- Missing input and no published version are visible without reading JSON.
- Source markers verify the new guidance.
