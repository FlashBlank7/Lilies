# design_v0347_workflow_reference_selection

Status: completed

## Source

- Source stage report: `docs/stage-report-archives/v0.3.x/v0.3.46_api_token_proxy_env_resolution.md`
- User product correction:
  - Right-click or drag-select bricks to reference them, similar to selecting lines for Copilot.
  - References are context, not a restriction on what can be changed.

## Problem

Workflow editing currently has no clear way to say "look at these bricks while editing the whole workflow". Users either inspect one brick or edit JSON, neither of which matches the desired workflow-scale editing mental model.

## Boundary

- Use ReactFlow-supported selection and context-menu events.
- References do not limit backend operations.
- Avoid inventing unsupported canvas gesture APIs.

## Proposed Solution

- Enable drag selection with `selectionOnDrag` and `SelectionMode.Partial`.
- Use selected nodes as workflow edit references.
- Add right-click node handling to include a brick as a reference.
- Show reference chips in the workflow edit dialog and let users clear them.

## Acceptance Criteria

- Drag-selected nodes update the workflow edit reference set.
- Right-clicking a node adds it to references.
- The UI copy says references guide context and do not limit edits.
- Backend receives references in preview metadata/request.

## Final Evidence

- Implemented in `platform/frontend/app/applications/[id]/page.tsx` via `onNodeContextMenu`, `onSelectionChange`, `selectionOnDrag`, and reference chips.
- Backend preview request and response carry `reference_node_ids` while preserving whole-workflow scope.
- Verified by `tests/test_v03_47_natural_language_workflow_edit.py`.
- Evidence archived in `docs/workingon-archives/v0.3.47/natural_language_workflow_edit_v0.3.47.json`.
