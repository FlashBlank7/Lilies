## Problem

When cancellation completes, non-technical users need a clear next step. The result card should confirm that the run was stopped and point back to input adjustment or retry, without implying the cancelled run produced a valid result.

## Boundary

- Copy and local UI state only.
- Do not change cancelled status semantics.
- Do not auto-retry or start a new run.

## Solution

- Keep the cancel-request marker through the cancelled status for the same run id.
- Show a completed-cancel guidance strip when the status becomes `cancelled`.
- Reuse the existing retry/input direction rather than adding a new mutation.

## Acceptance Criteria

- Cancelled state tells users the run was stopped.
- Guidance points to adjust inputs or retry explicitly.
- Guidance does not suggest that outputs are complete or accepted.
