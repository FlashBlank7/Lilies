## Problem

Once adaptive reuse-depth became a backend capability, Lilies still needed a deterministic artifact showing that the first policy version was aligned with the best known E05 family evidence rather than being an arbitrary rule.

## Boundary

- In scope: a deterministic backtest over the current E05 template families and documentation updates that connect the result back to the experiment ledger.
- Out of scope: fresh paid/live Builder runs, retraining, or online policy tuning.

## Final Design

- Add `scripts/e05_adaptive_reuse_policy_backtest.py` to:
  - load built-in templates,
  - score the current E05 family requirements,
  - resolve adaptive reuse depth,
  - compare policy decisions against best-known family outcomes,
  - emit JSON and Markdown evidence.
- Treat family outcomes in two buckets:
  - exact match for `code_reviewer` and `data_analyzer`
  - bounded success-envelope alignment for `customer_support_router`, where existing evidence is mixed
- Produce a concise DOCX report so the backtest sits inside the same experiment-evidence discipline as the rest of E05.

## Acceptance

- A deterministic backtest artifact exists for `code_reviewer`, `customer_support_router`, and `data_analyzer`.
- The backtest explicitly shows `data_analyzer -> deep`, `code_reviewer -> shallow`, and a bounded conservative `customer_support_router -> shallow`.
- The artifact is good enough to justify stage closure for the deterministic slice without pretending to replace live validation.
