# design_lilies_assistant_memory_and_nl_editing

## 1. Goal

把 Lilies 从“平台 + 插件”推进为具备助手体验的系统：可以自然语言修改画布，并在用户授权下利用多天工作记忆。

Status: deferred on 2026-07-08.

Deferred reason: this design needs explicit permission, memory, UI confirmation, file-system allowlist, audit, and task monitor boundary support. It should not be implemented as an unbounded local activity monitor or direct filesystem wrapper.

## 2. Module Boundary

候选模块：

- Builder Team / natural language edit endpoint
- WorkflowStorage draft mutation
- future memory store
- future permission and audit UI

## 3. Control Flow

用户自然语言修改 -> edit intent parser -> draft operation preview -> 用户确认或 passmode -> apply mutation -> validate/test。

记忆流：

本地活动摘要 -> 用户授权 -> memory retrieval -> Builder/assistant context -> 可撤销引用。

## 4. Implementation Plan

1. 先做自然语言到 draft operation 的可审阅 patch，不直接自动写入。
2. 记忆能力先做显式授权和摘要，不做无边界监控。
3. 文件系统封装必须有 allowlist、审计和取消。

## 5. Acceptance Criteria

- 画布自然语言修改能生成可审阅 patch。
- 用户能知道哪些记忆被使用。
- 文件系统访问不绕过 Platform Harness。
