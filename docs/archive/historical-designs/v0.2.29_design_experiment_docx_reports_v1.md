## 1. Problem

The project rule says every completed experiment requires a concise DOCX report with background, experiment design, result, and conclusion. The formal tranche must produce readable reports even when the conclusion is "partial evidence, not closed".

## 2. Design Goal

Goal:

- Produce one DOCX report per scoped experiment ID: E01, E02, E04, E05, and E08.
- Keep reports brief and easy to audit.
- Include raw evidence paths and applied/closed status.

Non-goals:

- Do not create decorative long-form reports.
- Do not invent screenshots if the experiment has no meaningful image.
- Do not claim render QA if LibreOffice is unavailable.

## 3. Module Boundary

- `docs/experiment-status/reports/`: final DOCX reports.
- `docs/experiment-status/evidence/`: raw evidence JSON.
- Documents skill renderer: visual QA when LibreOffice is available.

## 4. Data Flow

Experiment evidence and status facts -> python-docx report generation -> DOCX structural verification -> optional render QA -> report paths added to ledger and stage report.

## 5. Implementation Plan

1. Use `compact_reference_guide` because the reports are dense operator references.
2. Generate five DOCX files using `python-docx`.
3. Use consistent sections:
   - Background
   - Experiment Design
   - Result And Conclusion
   - Evidence Chain
4. Add a compact metadata table with experiment ID, status, evidence, and application marker.
5. Run structural checks: open the DOCX zip, extract key text, and confirm the expected headings exist.
6. If `soffice` is available, render pages and inspect PNGs; if not, record visual QA skipped due missing LibreOffice.

## 7. Risks

- DOCX files can be structurally valid but visually flawed if render QA is unavailable.
- Reports about partial experiments must remain clearly labeled to avoid accidental backlog closure.

## 8. Acceptance Criteria

- Five DOCX reports exist under `docs/experiment-status/reports/`.
- Each report has the four required sections.
- Each report includes a result status and evidence chain.
- Structural DOCX validation passes.
- Visual render QA is either passed or explicitly recorded as unavailable.
