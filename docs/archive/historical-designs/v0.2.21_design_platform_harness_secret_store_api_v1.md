# design_platform_harness_secret_store_api_v1

## 1. Goal

Add a minimal Platform Harness secret store and API that allows legitimate secret references without exposing secret values in responses.

## 2. Module Boundary

Backend:

- `platform/backend/src/agent_platform/storage.py`
- `platform/backend/src/agent_platform/platform_harness.py`
- `platform/backend/src/agent_platform/api.py`

Tests:

- `tests/test_workflow.py`

## 3. Data Flow / Control Flow

1. Operator creates a secret with `owner_id`, `name`, and `value`.
2. Storage persists the value under `(owner_id, name)`.
3. API returns only metadata plus a reference string.
4. Listing secrets returns redacted metadata only.
5. Deleting a secret removes it from the local store.

## 4. Implementation Plan

1. Add `platform_secrets` table to storage initialization.
2. Add storage methods for upsert/get/list/delete.
3. Add Platform Harness wrapper methods and public metadata formatting.
4. Add API endpoints:
   - `POST /api/v1/platform/secrets`
   - `GET /api/v1/platform/secrets`
   - `DELETE /api/v1/platform/secrets/{owner_id}/{name}`
5. Add tests that API responses do not include raw values.

## 5. Acceptance Criteria

- Secret values persist and can be retrieved internally. Completed.
- Public responses include `secret_ref` but not `value`. Completed.
- Upsert replaces the value without duplicating metadata rows. Completed.
- Delete removes the secret and returns a clear result. Completed.
