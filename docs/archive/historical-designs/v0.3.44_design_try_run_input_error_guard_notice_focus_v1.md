## Problem

If a run action is blocked by visible parser errors, users need to know why and be returned to the correction area. The guard must not silently disable the controls.

## Boundary

- Copy and local focus only.
- No API calls.
- No auto-fill or mutation of input values.

## Solution

- Add guard copy below the run buttons while parser errors exist.
- Add a local action that focuses the inline error/input area.
- Keep inline parser error panel as the detailed source of truth.

## Acceptance Criteria

- Guard copy says the run is blocked by current input errors.
- Focus action does not call an API.
- Focus target is near the inline parser error and input form.
