## Problem

Automatic evolution currently relies on manually remembered pytest command lists for v0.3.x. Running the entire historical suite produces known false red, but the project lacks a canonical current release gate.

## Boundary

- Do not delete or weaken historical tests.
- Do not make full historical `pytest tests` silently pass by changing archived expectations.
- Keep the current release gate explicit, versioned, and machine-readable.

## Solution

- Add a regression lane manifest under docs.
- Define the current v0.3.x release gate as a named lane with command, test files, rationale, and expected pass count.
- Add a small runner/audit script that reads the manifest and reports lane status.

## Acceptance Criteria

- A human can find the current gate without reading stage-report prose.
- A script can validate that lane file paths exist and produce evidence.
- The manifest explicitly says full historical sweep is diagnostic, not the current v0.3.x gate.
