# design_nl_draft_patch_preview_ui_v1

## 1. Goal

Expose the existing deterministic natural-language draft patch preview endpoint in Studio with an explicit preview-confirm-apply interaction.

The user should be able to:

- type a natural-language instruction such as `rename node end to Final Answer`;
- preview generated draft operations without mutating the draft;
- inspect warnings and unsupported instructions;
- explicitly apply supported operations to the current draft revision.

## 2. Module Boundary

Frontend:

- `platform/frontend/app/applications/[id]/page.tsx`
- `platform/frontend/lib/platform.ts`
- `platform/frontend/lib/i18n.ts`
- `platform/frontend/app/globals.css`

Backend:

- Reuse existing `POST /api/v1/applications/{application_id}/draft/preview-patch`.
- Reuse existing draft mutation endpoint for apply.

No new backend endpoint is required for this version.

## 3. Data Flow / Control Flow

1. User enters instruction in the Edit tab.
2. Studio calls `POST /draft/preview-patch`.
3. Backend returns `supported`, `intent`, `message`, `operations`, `warnings`, and `task_id`.
4. UI displays the preview and related Platform Harness task id.
5. User clicks apply.
6. UI applies operations one by one via existing draft mutation endpoint.
7. UI refreshes draft and monitor tasks.

## 5. Acceptance Criteria

- Preview action calls the backend without mutating the draft. Completed.
- Apply action uses the operations returned by preview and refreshes the draft. Completed.
