# design_v0.2.36_e02_paid_reviewer_proxy_and_report_v1

## Goal

Use a bounded paid model reviewer proxy to evaluate the raw vs readable review packets, then write the required DOCX experiment report and ledger update.

## Module Boundary

In scope:

- The v0.2.36 experiment script.
- Paid DeepSeek provider calls when `DEEPSEEK_API_KEY` is configured.
- DOCX report under `docs/experiment-status/reports/`.
- Experiment ledger update.

Out of scope:

- Claiming actual human timing or human error-rate reduction without human data.
- Broad product changes based only on proxy evidence.
- UI changes.

## Experiment Design

For each packet condition, ask the same reviewer task:

1. Identify the acceptance category.
2. Identify pass/fail status.
3. Identify the likely failure target.
4. Propose the first repair action.
5. Rate confidence and provide brief reasoning.

The paid reviewer proxy must return JSON. The script scores the answer against an answer key and records:

- provider/model
- prompt length
- duration
- parsed answer
- exact-match fields
- repair-action quality

## Acceptance Criteria

- Paid model calls are run if credentials are available; if skipped, the reason is explicit.
- Raw and readable conditions use the same evaluator prompt except for the packet payload.
- Results are saved as JSON evidence.
- DOCX report contains `背景`, `实验设计`, `结果结论`, `图片或截图`, `证据链`, and `工程应用状态`.
- Ledger marks E02 as proxy evidence completed, not as fully human-panel closed unless justified.
