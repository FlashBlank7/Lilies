# design_v0.2.35_invalid_tool_json_recovery_v1

## Goal

Keep Builder Team progress recoverable when a model emits malformed tool input JSON during a complex required-mode build.

This design belongs to `v0.2.35_e01_required_architecture_coverage`. It is not a separate roadmap item; it is a continuation required by the v0.2.35 paid/live rerun failure.

## Module Boundary

In scope:

- `platform/backend/src/agent_platform/runtime.py`
- `platform/backend/src/agent_platform/builder.py`
- `tests/test_runtime.py`

Out of scope:

- Provider-specific JSON rewriting.
- Benchmark scoring changes.
- Relaxing required node coverage.
- Increasing model budget without fixing the recoverability boundary.

## Problem

Two v0.2.35 paid/live reruns generated drafts with complete visible architecture coverage, including `context_assembler`, but the build still ended `needs_attention` because a later tool call had malformed JSON:

- `draft_add_node`: `Expecting ',' delimiter`
- `draft_update_node`: `Expecting ',' delimiter`

Before this design, `_collect_stream()` raised immediately on the JSON parse error. That turned a single malformed tool call into a whole build failure, so Builder Team had no chance to self-correct.

## Implementation Plan

1. Add a runtime marker for malformed tool-input JSON.
2. In `_collect_stream()`, convert a `JSONDecodeError` into a `tool.input_json.invalid` event and a `tool_use` input marker instead of raising.
3. In normal AgentRuntime tool execution, detect the marker and return an error tool_result instructing the model to re-emit valid JSON.
4. In Builder Team execution, detect the same marker before calling Builder tools and return the same recoverable error semantics.
5. Add deterministic regression coverage proving an invalid tool input JSON call does not crash the turn and the model can continue.

## Acceptance Criteria

- A malformed `input_json_delta` no longer raises out of `_collect_stream()`.
- The event stream records `tool.input_json.invalid`.
- The invalid call becomes an error tool_result, not an attempted draft mutation.
- Focused deterministic tests pass.
- A fresh paid/live complex required rerun is executed after the fix.

## Final Status

Completed.

Implementation:

- `runtime.py` now records malformed tool input JSON as `tool.input_json.invalid` and preserves a bounded raw preview in a marker.
- `runtime.py` normal tool execution detects the marker and returns a recoverable tool_result.
- `builder.py` detects the same marker before Builder tool execution, so Builder Team can continue its loop instead of failing the whole build immediately.
- `tests/test_runtime.py::test_runtime_feeds_invalid_tool_json_back_to_model` covers the recovery behavior.

Verification boundary:

- Deterministic regression directly triggers malformed JSON and proves recoverability.
- The paid/live rerun after the fix did not trigger `tool.input_json.invalid` again; it validates that the complete v0.2.35 complex required case can now reach `ready + benchmark passed` after the engineering change.
