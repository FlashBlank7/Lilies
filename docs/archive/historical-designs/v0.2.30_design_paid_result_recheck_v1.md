## 1. Problem

The v0.2.29 paid/live result is expensive evidence. After fixing deterministic benchmark semantics, the project should reuse that result for re-evaluation instead of immediately making another paid model call.

## 2. Design Goal

Goal:

- Reuse the v0.2.29 paid result with `LIVE_BUILDER_BENCHMARK_REUSE_RESULT=1`.
- Confirm whether the benchmark false-negative is resolved.
- Record the result as an applied supplement to the v0.2.29 experiment, without claiming the Builder build itself succeeded.

Non-goals:

- Do not run a fresh paid Builder call unless reuse is impossible.
- Do not close E01 original A/B.
- Do not mark the whole v0.2.29 tranche as applied.

## 3. Module Boundary

- `scripts/live_builder_benchmark_suite.py`
- `docs/experiment-status/evidence/experiment_v0.2.29_paid_builder_tranche_2026_07_09.json`
- `docs/experiment-status/evidence/experiment_v0.2.30_terminal_node_recheck_2026_07_09.json`
- `docs/experiment-status/v0.2_experiment_status.md`

## 4. Data Flow

Existing paid result -> reused application/build/draft -> benchmark suite evaluation with new equivalence map -> recheck JSON -> experiment ledger applied supplement -> stage report.

## 5. Implementation Plan

1. Run the live benchmark script with reuse enabled and a new output path.
2. Inspect the resulting benchmark report.
3. If the missing `end` node is resolved, mark the narrow terminal-node finding as `已应用`.
4. If the build still reports `needs_attention`, state that the engineering fix only corrected benchmark graph semantics, not the underlying Builder/test output contract.

## 7. Risks

- Reuse depends on the `.tmp/live_builder_benchmark_runtime` storage still containing the previous app/build. If reuse fails, record the blocker rather than silently running a new paid call.
- A successful benchmark recheck may still coexist with a failed build status.

## 8. Acceptance Criteria

- Recheck JSON exists.
- Recheck command and result are recorded in workingon and stage report.
- Experiment status distinguishes `已应用` narrow fix from original E01 closure.

## 9. No Next-stage Authority

This design expands one accepted v0.2.30 task only. It does not select or prioritize future stages.
