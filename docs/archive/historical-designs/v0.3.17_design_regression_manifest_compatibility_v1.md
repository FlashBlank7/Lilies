## Problem

The v0.3.15 and v0.3.16 checks should validate that their tests remain in the current gate, but they should not hard-code the latest future pass count forever.

## Boundary

- Do not weaken the current gate manifest.
- Do not remove expected pass-count evidence from the manifest itself.

## Solution

- Update the manifest for v0.3.17.
- Adjust prior manifest checks to require at least their baseline pass count and required test inclusion.
- Add v0.3.17 tests to enforce the new current expected count.

## Acceptance Criteria

- Current manifest includes v0.3.17 and expects the updated pass count.
- Older manifest checks remain stable across future gate growth.
