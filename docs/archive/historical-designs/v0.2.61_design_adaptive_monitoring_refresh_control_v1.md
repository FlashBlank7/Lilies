## Problem

v0.2.60 exposed adaptive monitoring status but did not provide a freshness signal or refresh control. Operators needed a way to record that current deterministic evidence had been rechecked.

## Boundary

- In scope: manual refresh, append-only JSONL history, Studio freshness display.
- Out of scope: scheduled background jobs, paid/live model calls, alert delivery, or database migrations.

## Final Design

Adaptive monitoring now stores refresh records at `data_dir/monitoring/adaptive_template_policy_history.jsonl`. GET status includes recent history and last refresh. POST refresh appends a compact record based on the current deterministic snapshot. Studio exposes a button and freshness fields in the existing monitor tab.

## Acceptance

- POST refresh appends history.
- GET after refresh reports `history_count=1` and a non-null `last_refresh`.
- Studio renders refresh and freshness fields.
- Backend regression passes.
