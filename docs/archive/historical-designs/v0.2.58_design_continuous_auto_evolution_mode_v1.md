## Problem

Automatic Evolution Mode allowed a final answer when the latest handoff did not name one meaningful next task. The clarified user rule is stricter: automatic evolution should continue until the user explicitly says to stop.

`v0.2.57_full_backlog_closure` made the mismatch visible by closing the original experiment backlog while still listing selection and phase-report tasks.

## Boundary

- In scope: evolution skill and operating-gate semantics.
- In scope: selection/meta-planning continuation behavior.
- In scope: bounded context reading.
- Out of scope: product runtime code and next productization lane implementation.

## Final Design

Automatic Evolution Mode continues after every archive commit. If no single implementation task is preselected, the loop checks whether the stage report contains lane-selection, phase-report, governance, cleanup, or other meta tasks. If it does, the next stage resolves that decision instead of stopping.

Final answers are reserved for explicit user pause/stop or real blockers: missing credentials/services, unbounded cost, destructive action needing consent, safety/privacy/legal risk, merge conflict, or no valid next-stage source.

## Acceptance

- Main skill states that automatic evolution continues until explicit pause/stop.
- Main skill treats lane-selection and meta-planning as valid continuation stages.
- Operating gates remove "no meaningful single next task" as a stop condition when a selection/meta task exists.
- Context rule remains bounded to latest relevant stage report plus at most five previous versions.
