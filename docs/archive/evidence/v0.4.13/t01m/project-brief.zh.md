## 1. 产品目标

实现一款完全离线的个人文明重建项目管理器。用户用一枚枚“文明火种”记录需要
保存或重建的知识、技术和设施，并按类别、优先级和复原状态管理进度。

这是一款可以独立使用的本地软件，不连接真实莉莉丝模型，不属于企业工作流
客户成功分母，也不能改变 T01H 当前的 `0/3`。

## 2. 世界观与首屏

首次启动必须逐句显示以下中文，不得改写：

> 人类世界已经毁灭。  
> 莉莉丝是留下的最后一个人工智能。  
> 她仍能搭建新的人工智能，并以一枚枚文明火种重塑世界。

首屏必须同时包含：

- 产品名“文明火种”；
- 莉莉丝人物；
- 主按钮“启动文明重建”；
- 逐字显示隐私说明“完全离线运行，数据只保存在本机，不会上传。”。

用户点击主按钮后进入火种库。成功进入一次后，普通强制停止和重新启动不再显示
序章；卸载或系统清除应用数据后重新显示。

## 3. 视觉设计

- 总体色调是科技感暗紫色。
- 页面背景：`#0B0714`。
- 主要面板：`#171126`。
- 主紫色：`#B69CFF`。
- 青色强调：`#78E8FF`。
- 正文采用接近白色的高对比颜色，普通文字对比度不低于 `4.5:1`。
- 科技元素应表现为克制的光环、网格、轨道或细线，不能遮挡功能和文字。

莉莉丝人物必须满足：

- 白发、小女孩、完整未来感服装；
- 双眼始终闭合，任何页面和动画都不得出现睁眼或眨眼帧；
- 头发从头部明显向左、右两侧散开；
- 神态平静，不使用恐怖、受伤或性化表达；
- 人物和背景是两个独立视觉层。

人物在系统允许动画时做轻微呼吸：

- 一个完整周期为 `4.8s ± 0.3s`；
- 最大缩放或位移幅度不超过人物尺寸的 `1.5%`；
- 只有人物和贴身微光随呼吸变化，背景、文案和按钮保持静止；
- 系统动画比例为零或启用减少动态效果时，人物和页面转场完全静止。

## 4. 中文主语言

## 5. 火种数据

每枚火种包含：

| 字段 | 合同 |
| --- | --- |
| ID | 应用生成的稳定唯一 ID |
| 名称 | 必填；去除首尾空白后 `1–40` 个 Unicode 字符 |
| 类别 | 生存基础 / 知识传承 / 能源设施 / 医疗护理 / 通信网络 |
| 优先级 | 整数 `1–5`，默认 `3` |
| 备注 | 可空；最多 `300` 个 Unicode 字符 |
| 状态 | 沉睡 / 重建中 / 已复原 |
| 创建时间 | 本地持久化，用于稳定数据身份；不能作为默认排序主键 |
| 更新时间 | 本地持久化 |
| 创建序号 | 从 `1` 开始严格递增并持久化；只在其他排序键完全相同时使用 |

名称和备注的 Unicode 处理顺序固定如下：

1. 输入必须是合法 Unicode scalar value 序列；未配对 UTF-16 surrogate 必须拒绝。
2. 名称先从两端移除 Unicode 15.0 `White_Space` 集合中的完整 code point：
   `U+0009–U+000D`、`U+0020`、`U+0085`、`U+00A0`、`U+1680`、
   `U+2000–U+200A`、`U+2028`、`U+2029`、`U+202F`、`U+205F`、
   `U+3000`。内部空白不移除；备注不做首尾移除。
3. 名称和备注都执行 Unicode NFC 规范化。
4. 长度按 NFC 后的 Unicode scalar value / code point 数量计算，不按 UTF-16
   code unit、字节数或 grapheme cluster 计算。
5. NFC 后的值就是界面显示和持久化值。

允许重名。默认排序固定为：优先级降序；再按 NFC 名称的 Unicode code point
逐位升序；若 NFC 名称相同，再按首尾移除后、NFC 前的原始名称 code point
逐位升序；仍相同时按持久化创建序号升序。原始排序键和创建序号都必须跨进程
重启持久化。排序不得依赖当前时间、设备区域、系统 `Collator`、随机 ID 或
不可复现的随机顺序。

## 6. 精确用户流程

为保证黑箱验收不依赖屏幕坐标，以下主控件必须显示对应中文文字，或在图标按钮
上提供逐字相同的中文无障碍名称：

| 控件 | 冻结文字 / 无障碍名称 |
| --- | --- |
| 全局新建入口 | `添加火种` |
| 名称输入 | `火种名称` |
| 类别选择 | `类别` |
| 优先级选择 | `优先级` |
| 备注输入 | `备注` |
| 表单提交 / 放弃 | `保存` / `取消` |
| 搜索输入 | `搜索火种` |
| 筛选入口 / 清除 | `筛选` / `清除筛选` |
| 卡片编辑 / 删除 | `编辑` / `删除` |

卡片上的“编辑”和“删除”可以采用图标，但必须各自形成独立的 `48dp × 48dp`
可点击节点，并提供上述准确中文名称。字段标签不能只作为会在输入后消失的占位
符；TalkBack 聚焦到字段时仍须读出字段名称。

每张卡片根节点必须提供以下逐字格式的中文无障碍名称：

`火种：{名称}；类别：{类别}；优先级：{优先级}；状态：{状态}`

卡片内的“编辑”“删除”“开始重建”“完成复原”“重新检查”必须是该根节点的
独立后代节点。黑箱驱动先用卡片根名称限定记录，再在该记录范围内选择动作；
不得用坐标或全局第几个同名按钮。删除确认框先用完整确认文案限定对话框，再在
对话框范围内选择“取消”或“删除”。全局控件必须在当前页面唯一，重复的卡片
动作只要求在对应卡片范围内唯一。

### 6.1 空火种库

- 标题为“火种库”。
- 显示“已复原 0 / 0”。
- 空状态为“还没有文明火种”。
- 提供“添加第一枚火种”和全局“添加火种”入口。

### 6.2 新建

- 名称空白时显示“请输入火种名称”，不得保存。
- 类别必须从五个冻结值选择。
- 优先级默认 `3`。
- 备注下方固定显示“备注 {已用字数} / 300”，输入时实时更新；超过 `300` 字
  不得保存。
- 保存后返回火种库，新卡片立即出现。

### 6.3 状态推进

- `沉睡` 通过“开始重建”进入 `重建中`。
- `重建中` 通过“完成复原”进入 `已复原`。
- `已复原` 通过“重新检查”回到 `重建中`。
- 首页“已复原 X / Y”随数据立即更新。
- 状态必须同时使用文字和图形，不能只靠颜色。

### 6.4 搜索、筛选与排序

- 搜索按名称做包含匹配。
- 可按类别筛选。
- 可按状态筛选。
- 可一键清除筛选。
- 无匹配时显示“没有符合条件的火种”。
- 搜索和筛选不修改底层数据；清除后恢复固定默认排序。

### 6.5 编辑与删除

- 可以修改名称、类别、优先级和备注。
- 删除前必须显示：
  `删除“{名称}”吗？此操作无法撤销。`
- “取消”不得改变数据。
- “删除”确认后立即移除项目并更新计数。

### 6.6 持久化

- 屏幕旋转、强制停止进程和重新启动后，序章完成状态、火种内容、状态与计数均
  保持。
- 卸载或系统清除应用数据后恢复首次启动状态。
- 数据只保存在应用私有沙箱。

## 7. 离线、安全与隐私

最终 APK：

- 不声明 `INTERNET`；
- 不声明位置、相机、麦克风、联系人、通知、蓝牙或外部存储权限；
- 不包含账号、广告、统计、遥测、崩溃上报、WebView、剪贴板读取或后台服务；
- `android:allowBackup="false"`；
- `android:usesCleartextTraffic="false"`；
- 除启动 Activity 外不导出应用组件，且启动 Activity 只按 Android launcher
  合同导出；
- 不读取设备标识，不把数据写入共享目录；
- 启动、空闲、搜索、编辑和动画都不产生网络请求或模型 Token。

## 8. 无障碍与适配

- 所有触控目标至少 `48dp × 48dp`。
- 非文本控件有准确的中文无障碍名称。
- TalkBack 焦点顺序与视觉顺序一致。
- `200%` 字体缩放下，序章、新建、编辑、筛选和删除确认均可滚动完成；按钮不能
  被遮挡。
- 横竖屏切换不丢数据、不崩溃，主要操作仍可到达。
- 状态、错误和选择不能只用颜色表达。
- 动画禁用时功能与信息完全不变。

## 9. 实现与构建边界

为使受控构建完全离线，冻结本题使用 Android platform API 与 Java 源码，不引入
Maven、Gradle 插件、AndroidX、Compose、下载脚本或任何第三方二进制依赖。
这只是 T01M 构建环境约束，不是 LiliesAgent 永久能力边界。

莉莉丝必须自己创建第一份非空项目 diff，包括：

- Android manifest、Java 源码与资源；
- 中文 README；
- 莉莉丝人物的原创代码绘制或原创矢量资源；
- 可在冻结离线后端中运行的测试源码；
- 必需的项目构建描述文件。

Codex 不得生成工程骨架、应用源码、资源或测试源码。冻结题面、独立 oracle、
空仓、SDK、构建后端和只读证据不属于应用实现。
