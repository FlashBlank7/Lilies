# T01M 模型用量与停止策略

状态：`candidate_pending_project_freeze`

T01M 只使用冻结的本机
`qwen2.5-coder:7b-instruct-q4_K_M`。模型费率固定为输入、输出均
`0 USD / 1M tokens`；这里记录的 Token 仍是真实模型计算量，不能因为费用为零
而省略。

## 单次调用

- 输入上界：`24,576 tokens`
- 输出上界：`8,192 tokens`
- 上下文模型上限：`32,768 tokens`
- 用量来源：Ollama 返回的 `prompt_eval_count` 与 `eval_count`
- 缺失或非法用量：标记 `unknown`，任务立即进入
  `reconciliation_required`，不得估算为零或继续调用

## 可观察性

每轮使用独立 session、assignment 与 run，持久记录：

- `development:attempt`
- `development:planning`
- `development:tool-continuation`
- `development:final`
- `development:error`

监控按 `assignment / stage / model` 显示输入、输出、总 Token、调用次数、费用和
未知用量。打开桌面软件、查看会话、刷新状态、查看用量和运行外部确定性 oracle
都不得调用模型。

## 出口与生命周期

- Ollama 只监听 `127.0.0.1:11435`，不注册系统服务。
- 每轮开始前显式启动；完成、失败、超限或 reconciliation 后停止。
- `OLLAMA_NO_CLOUD=1`、`OLLAMA_NOHISTORY=1`、`OLLAMA_KEEP_ALIVE=0`。
- 莉莉丝 daemon 的模型出口默认关闭，只在当前已冻结 assignment 执行期间显式
  打开；停止后再次核验出口关闭、监听器为零和账本不再增长。

## 立即停止条件

- 任一 Token、模型调用、工具、构建、时间或 I/O 预算达到上限；
- 用量缺失、请求摘要或模型身份无法对账；
- 请求网络、秘密、额外路径、任意命令或自行扩大权限；
- 构建副作用进入不确定状态；
- 工作区不再能唯一归属到冻结父 commit；
- 两轮连续没有可接受 diff，或三轮连续得到同一失败构建指纹；
- 外部 oracle 在一次干净重建后连续两次给出同一不可修复失败。

这些条件只停止当前项目执行，不会把失败改写为完成，也不会触发后台自动重试。
