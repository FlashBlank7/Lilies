# Lilies 系统理论审视

**李昊天, 蒋之骏** · 2026年7月

---

## 摘要

本文以图论、可计算性理论、Petri 网、范畴论、图重写系统和交互网的成熟理论为透镜，系统审视 Lilies 的架构设计。核心结论：Lilies 的架构决策与六条已被前人严格证明的理论不谋而合——它的正确性不是来自经验试错，而是来自理论边界内的必然推演。同时，本文识别出四个当前尚未充分利用的理论工具，它们可以为 Lilies 的下一步发展提供严格指导。

## 第二章：Lilies 架构决策的理论审视

### 2.1 决策 1：积木不是 Agent，工作流才是

**理论支撑**：⑥ 原语即耦合 + ① Habel & Plump 最小构造

Lilies 的核心架构决策是：**单个积木不应该是"智能的"——智能应该从积木之间的连接中涌现**。这个决策的数学基础是：

- ⑥ 证明：任何试图在积木内部嵌入 LLM 推理的"更聪明的积木"，只是在更细粒度上重建了 Harness+LLM 复合体。积木层的优化不能消除工作流层的复合体。
- ① 证明：实现图灵完备只需要三个极简单的构造（顺序、分支、迭代），不需要"智能积木"。

**审视结论**：这个决策是**逻辑必然的**，不是品味选择。存在严格的数学论证：优化积木层等价于在错误的粒度层次上重建同一结构。

### 2.2 决策 2：DAG 而非任意有向图

**理论支撑**：② Van der Aalst WF-net + ① Habel & Plump

Lilies 选择 DAG（有向无环图）作为工作流的基本结构，循环通过显式 `loop` 积木表达。理由：

1. **验证可行性**：Van der Aalst 证明了 FC WF-net（Lilies 工作流所属的子类）的 soundness 可在多项式时间内验证。如果允许任意有向图，验证会变成 PSPACE-complete。

2. **可组合性**：DAG 保证了每个节点的输入只依赖于拓扑序上前驱节点的输出。任意有向图破坏了这种局部性，使组合推理不可行。

3. **显式循环的边界**：DAG + 显式 loop 将"有限计算"（DAG 内部）和"无界计算"（loop 回边）在结构上区分开来。这与 Habel & Plump 的结论一致：加一条回边 = 从原始递归跳到图灵完备。

**审视结论**：DAG + 显式 loop 不是设计限制，而是**计算复杂度的最优划分**——在保证表达能力的前提下最小化验证成本。

### 2.3 决策 3：$ref 引用机制作为组合算子

**理论支撑**：④ 弦图 + ⑤ DPO 图重写

Lilies 的 `$ref` 引用机制（`{"$ref": {"node_id": "X", "path": ["field"]}}`）是工作流之间的数据连接方式。它的理论等价物是弦图中的**线**（wire）——将上游盒子的输出端口连接到下游盒子的输入端口。

弦图的核心原则是"只有连接关系重要"（only connectivity matters）。这解释了为什么 `$ref` 是正确设计：
- 只要 `$ref` 的 `node_id + path` 指向正确的上游输出，工作流的语义就被确定
- 不需要关心 `$ref` 在 JSON 中的位置、缩进、顺序
- 图的拓扑同构变换（重排节点）不改变 `$ref` 的解析结果

从 DPO 图重写角度看，`$ref` 的解析 `_resolve()` 实现了一个**图同态**：将跨节点的引用映射为实际值。

**审视结论**：`$ref` 机制是弦图"连接即语义"原则的工程实现，它在设计上是完备的——当前实现中 `_resolve()` 的递归解析确实是对图重写的忠实模拟。

### 2.4 决策 4：模板市场作为组合闭包

**理论支撑**：③ 交互组合子 + ① 最小性

Lafont 的交互组合子证明：从一个极小的基本集合出发，通过组合可以表达所有可计算函数。这正是 Lilies 模板市场的理论模型：

```
基本积木 (6 个核心)  →  模板 (13 个种子)
         ↓                       ↓
    串行组合 (∘)           进化引擎 (evolve)
    并行组合 (⊗)           模板匹配 (merge)
         ↓                       ↓
    组合闭包 (∞ 个工作流)  ←  模板市场 (持续增长)
```

模板市场的推荐飞轮、进化流水线和相似度匹配合并，都可以映射到组合闭包的代数操作：

| 操作 | 代数形式 | Lilies 实现 |
|------|---------|-----------|
| 模板展开 | `T → expand(T)`（函子） | `expand_into_workflow` |
| 模板合并 | `T₁ + T₂ → merge(T₁, T₂)` | `merge_engine.merge` |
| 相似度匹配 | `sim(T₁, T₂)`（图同态距离） | Jaccard(类型) + 图结构相似度 |
| 进化 | `T → T'`（图重写） | `evolution_engine.evolve_or_create` |

**审视结论**：模板市场的代数结构是完整的。但是 `merge_engine` 目前使用的是启发式近似相似度，离形式化的图同态距离还有差距——这是可以进一步形式化的地方。

### 2.5 决策 5：测试门禁作为 Soundness 的工程近似

**理论支撑**：② Van der Aalst Soundness

Van der Aalst 的 WF-net soundness 包含三个条件：
1. **Option to complete**（可达终止）：从任何可达状态都能到达 end
2. **Proper completion**（适当终止）：end 被标记时无其他节点活跃
3. **Absence of dead tasks**（无死任务）：每个节点在某种执行路径下可达

Lilies 的测试门禁（`tested_hash == content_hash` + `structural_only`）是 soundness 形式验证的一个**工程近似**：
- 结构测试验证条件 (3)（无死任务）
- 确定性工作流的运行测试验证条件 (1) 和 (2)
- 但含 LLM 的工作流的结构测试只能部分验证条件 (1)

**审视结论**：测试门禁是一个正确的折中——它覆盖了 soundness 的静态方面（通过 `validate_workflow`），并将动态验证委托给运行时行为。对于含 LLM 的工作流（非确定性不可避免），这是理论上最优的折中。

## 第三章：理论差距与改进方向

### 3.1 差距 1：自由选择性质的静态保证

**问题**：Lilies 工作流在绝大多数情况下是自由选择的，但这不是**强制保证**的。理论上存在构造非自由选择工作流的可能（例如两个 `if_else` 节点共享输入但判断条件不同）。

**理论依据**：Van der Aalst 的多项式 Soundness 验证仅对 FC WF-net 有效。

**影响**：当前 `validate_workflow` 隐式假设所有工作流是自由选择的。如果有人构造了非 FC 工作流，验证可能漏报或不完整。

**建议**：在 `validate_workflow` 中添加自由选择性质检查——如果检测到非 FC 结构，发出警告并降低质量评分。

### 3.2 差距 2：图同构与语义等价的不可判定性

**问题**：两个 BlockFlow 可能在图结构上不同但语义上等价（例如并行化的前后）。判断它们等价等价于图同构问题的加强版，目前没有已知的多项式算法。

**理论依据**：图同构在 GI 复杂度类中（准多项式时间已知，多项式时间未知）。

**影响**：`merge_engine` 的相似度计算是启发式的，不能保证找到所有语义等价的模板。

**建议**：当前启发式方法（Jaccard + 图结构）是实际可行的最优解。可以用 Weisfeiler-Lehman 图核增强。

### 3.3 差距 3：交互网的最简表示的工程化

**问题**：Lilies 有 41 个积木，但 Lafont 证明 3 个就足够了。当前没有区分"核心积木"和"便利积木"。

**理论依据**：Lafont 3 符号/6 规则 + Habel & Plump 3 最小构造。

**影响**：积木注册表缺乏层次——Builder 在 41 个积木中搜索，而实际只需要识别 ~6 个核心模式。

**建议**：为积木注册表添加分层标记——核心积木（6 个）vs 便利积木（35 个）。Builder 提示词中强调核心积木的优先使用。

### 3.4 差距 4：弦图可视化的证明性

**问题**：当前 BlockFlow 画布（`canvas.html`）是静态渲染，不支持弦图的拓扑变形语义——拖拽节点不保证语义不变性。

**理论依据**：Coecke & Kissinger 弦图 = "只有连接关系重要"。

**影响**：画布是"示意图"而非"证明环境"。

**建议**：长期——将弦图的 DPO 重写规则集成到画布中，使每次拖拽/编辑都是保语义的图变换。

## 第五章：总结

Lilies 的架构设计不是空中楼阁。每一个关键决策——积木不可再分、DAG 而非任意环图、$ref 组合机制、模板市场的闭包结构——都对应着前人已经严格证明的理论结论。

**Lilies 的正确性来自理论边界的必然推演，而非经验试错。**

它的价值不在于发明了新理论，而在于将六条成熟理论**同时**应用到了一个实际的工业级 Agent 工作流平台中。这种 "一阶理论的工程收敛"——让六条看似独立的形式化理论在同一个代码库中交汇并彼此验证——是 Lilies 真正的知识资产。

**原语即耦合。组合即智能。验证即证明。其余皆为粒度的选择。**
