# 候选方案约束检查与比较

2026-09-25。员工已经有几套工艺、资源分配、实验或排产候选，希望知道哪些满足条件、各自有什么取舍时，可以使用这个流程。无需重新训练、调用模型或填写JSON。

在项目空间的「公共工作流市场」加入同名流程，得到独立可编辑副本及项目Skill；或从示例目录创建「候选方案约束检查与比较」。示例为自编资料，创建不启动业务。通过对话使用时，智能体可按项目Skill发现和调用；没有适合的候选或明确偏好时，不编造方案、条件和权重。

## 员工操作

1. 选择候选CSV/Excel，每行一个方案，指定方案标识列。不同独立任务可以按一列分组，组内比较。
2. 在「必须满足的条件」行表中添加检查列、比较方式、固定值或同一行的对比列。例如「使用量不大于可用量」；固定值和对比列二选一。多个条件需要全部满足。
3. 在「比较目标」填写数值指标和越大/越小越好，上下移动调整优先级。默认逐项比较，前项相同才比较下一项；不清楚偏好时可不填目标，先获得条件检查。
4. 只有明确允许目标相互补偿时才选择权重评分，并填写权重和「每多少变化算1分」。分数是有方向的 `值 ÷ 尺度 × 权重` 之和；尺度固定，不随着增加另一个候选而改变。
5. 查看组内结论、各指标值、排名、失败与缺失原因；下载完整候选、条件明细、评分分项及说明。修正输入或调整条件后新建运行，旧结果仍保留。

建议问题：「比较这几套方案，先排除资源超限和配对不满足的，再解释产出与损失的取舍。如果资料还不能判断，请指出缺什么。」条件和目标是任务配置，不是平台统一审批。员工也可以直接让智能体处理适合一次性分析的问题。

## 方法和边界

| 情况 | 处理 |
| --- | --- |
| 条件全部满足 | 参加目标比较；只代表满足已声明条件 |
| 某条件明确失败 | 保留原候选和失败原因，不因分数高而恢复资格 |
| 条件值缺失、非法 | 显示待补充，不填0、不当作通过；同时存在明确失败则标记不满足，并保留全部原因 |
| 没有候选通过 | 交付失败/缺项清单，首位列表为空，不选择不满足的高分方案 |
| 比较目标缺失 | 保留条件检查，但该候选不参加排名 |
| 没有设置条件或目标 | 仍可保存、运行；分别注明只排序未检查限制，或只检查不排名 |
| 相同指标或分数 | 保留并列名次，后一名采用相应位置编号；不任意指定唯一最佳 |
| 数值边界 | 精确十进制比较，严格区分小于/不大于；文字比较不把1和1.0自动当作同义 |
| 跨任务共享资源 | 各组首位不能直接拼成整体排程，仍需领域流程检查共同库存、设备和时序约束 |

只比较输入中已有候选，不生成候选、不进行全局搜索、不证明全局最优，也不回写现场。尺寸、过程曲线、库存配对等复杂公式继续由领域代码生成指标，不能仅凭一个「已通过」字段保证其计算正确。

每次固定源文件哈希和配置快照。输出保留原始行及 `comparison_` 字段；输入存在该前缀会提示改名或选择原文件，避免覆盖。结果每次写入独立目录；快照改动时拒绝沿用，要求重新读取资料。CSV、TSV、XLSX支持单文件10 MB；多工作表需明确选择。首版上限2万候选、50个条件、10个目标及50万次条件比较，超过会提示拆分。

## 原项目参考与本轮验证

- 原切割工程提供候选枚举、评分分项和配对检查。静态检查及隔离运行确认：配对谓词全部返回否时，原实现仍返回原候选。通用流程提炼“条件与偏好分开”，没有继承这个回退行为；原客户代码保持不变。
- 原压力优化工程先限定候选，再选择评分较好的操作范围。其压力交互特征和阈值保留在领域版本；连续采样区间现由独立的[参数扫描结果与连续区间](PARAMETER_INTERVALS_WORKFLOW.md)分析，不能以本流程的单点排序替代。
- 使用原切割实现和构造输入生成20个候选、4组任务，平台对所有评分及组内首位逐项核对一致，保留一组并列。构造“全部不满足”后每组首位均为空，原结果保持不变。观测一次平台比较约2.72秒。这里验证原方法计算，不是客户生产资料验收。
- 公开样例包含资源超限、配对信息缺失、不可配、并列和换资料。后端行为测试覆盖全部比较符、零值、重复标识、Excel、多条件、缺目标、固定评分尺度、十进制同分、输入版本、平台执行及下载。
- 行表行为测试验证新增、编辑、删除、上下移动、保留无关字段和清空为真正空数组；操作本身不启动任务。浏览器另行验证员工从示例创建、运行、修改条件、换资料、下载和模拟手机尺寸。
