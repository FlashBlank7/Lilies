# v0.2.27 Worker Runner CLI And Handler

## 1. Stage Goal

Advance the v0.2.26 worker runner primitive into an operator-usable worker entrypoint with one real built-in handler.

This stage does not complete a full durable queue. It adds `agent-platform-worker`, one-shot/loop helper logic, and a `scheduler_manual_trigger` handler that launches real workflow runs through the existing scheduler/runtime while using the queued worker task as the Platform Harness parent boundary.

## 3. Completed Items

- Added `agent-platform-worker` project script.
- Added worker runner CLI options for worker id, lease seconds, task kind, owner id, limit, poll seconds, and once mode.
- Added `create_platform_worker_runner()` and `run_worker_once()` helpers.
- Added `build_platform_worker_handlers()`.
- Added built-in `scheduler_manual_trigger` handler.
- Extended `WorkflowScheduler.trigger_now()` so worker-owned queued tasks can be used as the parent Platform Harness boundary.
- Added focused integration test proving a queued scheduler manual trigger task starts a real workflow run and finishes the worker task.
