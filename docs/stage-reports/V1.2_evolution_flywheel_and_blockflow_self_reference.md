# V1.2 evolution_flywheel_and_blockflow_self_reference

## 1. 阶段目标

本阶段完成了三次连续重构，从"元认知闭环断裂"到"自进化系统可正常工作"再到"进化流水线本身成为 BlockFlow（平台自我引用）"。

核心命题来自论文《原语即耦合》的直接推论：

> 如果 Harness+LLM 复合体是不可再分的结构不变量，那么进化流水线作为 Lilies 平台上的 Harness 系统，就应该以平台自身的 BlockFlow 形式存在——可观察、可测试、可被 Builder 改进。

本阶段实现了这一命题的工程落地。

## 2. 完成的三次重构

### Session 1: 进化引擎从"记账"到"真合并"
- 候选源从 `tracker.extract_workflow()`（决策树推导）切换到 `draft.snapshot.workflow`（Builder 实际产物）
- `merge()` 从仅 bump confidence 改为实际调用 `merge_workflow_graph()` 修改工作流图
- 新增 `EvolutionEngine` + `EvolutionGate` 模块，基于真实 WorkflowSpec 的门控
- `TemplateMeta` 新增 `success_rate`、`evolution_history` 等质量追踪字段
- `quality_score` 公式引入 `success_bonus`

### Session 2: SoftBlock 从"积木类型"到"积木属性"
- 移除 `soft_block` 作为运行时积木类型（违反 ADR-001）
- `FAMILY_MAP` 保留为纯数据模块
- 24 个 Agent 架构积木通过 `get_family()` 自动标注 `editor.family`
- API 端点 `/soft-block/strategies` → `/blocks/families`
- 原则确立：**家族是积木的属性，不是积木本身**

### Session 3: 进化流水线成为 BlockFlow + 推荐飞轮闭合 + 家族感知相似度
- `EvolutionGateTool` 注册为 `evolution_gate` 工具，桥接 Python 函数到 BlockFlow
- `templates/evolution_pipeline.json` — 8 节点 9 边确定性 BlockFlow 模板
- `BuildTeamState.expanded_from_template` + `builder.py` 回写 + `TemplateStore.record_usage()` 闭合推荐飞轮
- `MergeEngine._compute_similarity()` 混入 40% family 级别 Jaccard
