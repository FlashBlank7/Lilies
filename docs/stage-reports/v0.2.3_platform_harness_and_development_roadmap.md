# v0.2.3 Platform Harness And Development Roadmap

## 1. Stage Goal

根据当前 intellectual assets、竞品与未来方向报告、v0.2.1/v0.2.2 stage reports，抽取功能开发任务，并优先完成能提升 Lilies 工业可用性的后端能力。

本 stage 的主线是把“可靠性、可观测性、可验证生成”从文档建议推进到可运行代码：

1. 建立平台级 Platform Harness / task monitor boundary。
2. 建立 Builder benchmark v1，给 Builder 能力回归提供结构指标。
3. 建立自然语言画布修改的非破坏性 preview 入口。
4. 使用真实付费模型做 Builder/Harness live acceptance，而不是只停留在离线玩具测试。

## 5. Incomplete / Deferred Tasks

- Platform Harness 仍是 in-process 版本，不具备跨进程持久化、账号级预算、网络 egress policy、secret policy 和 durable retry queue。
- Builder benchmark v1 只做 deterministic structural scoring，尚未做多需求、多模型、多轮 live benchmark suite。
- Natural-language draft patch preview 是窄确定性 parser，尚未接入模型辅助编辑、权限门禁和 preview-confirm 流程。
- 前端还没有完整展示 Platform Harness task monitor、benchmark report 和 patch preview。
- 没有生成正式实验 `.docx`；本 stage 的 live acceptance 属于工程验收，不是完整实验报告。

## 6. Next-stage Task Pool

1. 将 Platform Harness task monitor 接入前端，展示 task、usage、violation、预算状态和 run/build/test 关联。
2. 将 Builder benchmark 升级为可配置 benchmark suite，支持多需求、多模型、成本记录和回归趋势。
3. 将 natural-language patch preview 接入画布 UI，形成 preview-confirm-apply 的安全修改链。
4. 将 Platform Harness 从 in-process memory 推进到 durable storage，并明确账号预算、secret policy、network policy。
5. 执行正式实验并生成 `.docx`：Platform Harness live acceptance、Builder benchmark、NL patch preview usability。
