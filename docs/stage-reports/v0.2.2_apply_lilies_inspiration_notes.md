# v0.2.2 Apply Lilies Inspiration Notes

## 1. Stage Goal

把后端设计阅读笔记从“灵感、疑问、实验想法、设计构想”转化为可执行的 Lilies 项目能力。

本 stage 的核心目标不是单纯整理文档，而是按项目 evolution-development skill 完成完整链条：

1. 在 `workingon` 中分类笔记、记录问题、建立实验 backlog。
2. 在 `current-design` 中拆出可实现的设计。
3. 按设计逐个实现代码。
4. 用 focused tests 验证。
5. 将完成内容、未完成内容和智力资产候选归档为 stage report。

## 4. Incomplete / Deferred Tasks

### 4.1 Lilies assistant memory and natural language editing

状态：deferred

原因：

- 该方向涉及用户活动监控、多天记忆、自然语言画布修改和文件系统封装。
- 当前还缺少权限模型、UI 确认流程、memory store 边界、文件系统 allowlist、审计和 task monitor boundary。
- 如果直接实现，会违反 `asset_platform_harness_task_monitor_boundary.md` 的硬边界原则。

下一 stage 建议：

1. 先设计 `NaturalLanguageDraftPatch`，只生成可审阅 draft operation，不直接写入。
2. 再设计 memory surface：显式授权、可撤销、可审计。
3. 文件系统封装必须进入 task monitor boundary。

### 4.2 正式实验报告

状态：not started

本 stage 建立了实验 backlog 和 `.docx` 报告规则，但没有完成正式对比实验，因此没有生成实验 `.docx`。

下一 stage 可优先执行：

- E01 plan-first vs node-by-node
- E02 readable TestFrame
- E04 local repair vs full rebuild
- E08 Harness sidecar passmode
