# V1.4 clyins_project_manager

## 1. 阶段目标

本阶段将 Clyins——一个 AI 项目经理的构想——从对话中的模糊直觉落地为 **可运行的 BlockFlow 模板 + Web 上传界面 + 公网部署**。

核心命题：

> 如果"调 harness 不调 agent"是 Lilies 的方法论，那么 Clyins 就是这个方法论在项目管理领域的**自我指涉式验证**——Clyins 本身就是一个 BlockFlow，它用 Lilies 搭建，生成的结果又可以投喂给 Lilies 执行。

## 3. 完成的任务

### 3.1 核心 BlockFlow 模板

**文件**: `templates/clyins.json`

7 节点 6 边的 Clyins 工作流：

```
start(会议记录, 团队背景, 会议日期)
  → template_transform(组合分析提示)
  → llm(Clyins 行动项提取, structured_output + schedule_table)
  → task_dispatcher(依赖排序, Kahn 拓扑)
  → template_transform(生成日程表与纪要)
  → human_input(人工核验)
  → end(日程表, 摘要, 任务列表, 核验状态)
```

**设计决策**:
- 完全使用现有积木（start / template_transform / llm / task_dispatcher / human_input / end），零新积木引入
- LLM 同时输出 `summary`、`schedule_table`（markdown 格式表格）、`tasks`（结构化数组），解决 template_transform 无法从数组渲染表格的限制
- `human_input` 节点作为质量闸门，支持人工 review 后再发布

### 3.2 运行时改进

**文件**: `platform/backend/src/agent_platform/workflow_runtime.py`

- `task_dispatcher` 增加 `title` 字段回退查找：LLM 输出 `title` → `task_dispatcher` 原本只查 `name`/`subject`，现增加 `task.get("title", ...)` 作为第三回退

### 3.3 API 端点

**文件**: `platform/backend/src/agent_platform/api.py`

新增 `POST /api/v1/clyins/run`：
- 接收会议文本（`meeting_transcript`），自动创建 Application → 展开 Clyins 模板 → 运行工作流
- 返回 `run_id` 供前端轮询
- 后台任务自动处理 `human_input` 暂停（核验节点自动批准，用户在前端确认最终结果）

**文件**: `platform/backend/src/agent_platform/workflow_models.py`

新增 `ClyinsRunRequest` 模型。

## 5. 已发现的限制与后续方向

### 当前限制

1. **template_transform 无法从数组渲染表格**: 通过让 LLM 输出预格式化的 `schedule_table` 字段绕过，但增加了 LLM 输出的复杂度
2. **项目状态不持久化**: 每次生成是独立的 WorkflowRun，无法跨会议跟踪任务完成状态
3. **无语音输入**: 当前仅支持文本粘贴，语音转文字需要额外的 speech-to-text tool
4. **无日历集成**: 生成的日程表是文本格式，不支持一键导入 Google Calendar / Outlook

### 后续方向

1. **Clyins → Lilies 自动分派**: 当用户选择 `assign_to_lilies=true` 时，自动将拆解出的任务提交给 Builder Team 创建对应的 BlockFlow
2. **项目持久化**: 增加 Project 模型，支持跨会议的任务状态跟踪
3. **语音接入**: 新增 `speech_to_text` tool，支持会议录音直接输入
4. **模板自进化**: Builder Team 使用 Clyins 模板生成变体 → 验证通过后进化回模板市场
