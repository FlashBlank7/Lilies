## 总体目标对齐

| 字段 | 值 |
| --- | --- |
| 总体目标 | 让智能体/工作流生成平台自行理解并对齐客户系统正式接口，使平台生成的工作流能够在没有实验人员代写适配器的条件下介入真实宿主项目。 |
| 本阶段贡献 | 先补齐最普遍的 REST/OpenAPI 自动接口对齐闭环，并用 Paperless、InvenTree、Chatwoot 同时检验交付正确性和交付性能，包括首次契约通过时间、映射覆盖、修复轮次、成本和人工介入，为后续 WebSocket、MQTT、SDK/CLI 和真实工作流干预建立可信前提。 |
| 声明边界 | 本阶段最多声明经过冻结官方材料和受控黑盒契约验证的 REST/OpenAPI 能力；不声明非 HTTP 协议、完整业务工作流交付、客户生产可用性或性能优于原流程。 |
| 总体阻塞判断 | 自动完成接口对齐本身就是本阶段必须测量的平台交付性能，不能延期。只有原流程与替换流程的运行时 p95、吞吐、CPU、内存和故障恢复比较，以功能合同通过为前置条件；接口对齐未通过时不得用手工 Connector 绕过。 |
