# v0.2.23 Sandboxed Stdio MCP Runner

## 1. Stage Goal

Close the next Platform Harness stdio MCP slice after `v0.2.22` by adding a sandbox-backed stdio MCP runner for the restricted no-network path.

This stage deliberately does not claim allowlist-grade stdio egress enforcement. The completed capability is a platform-boundary slice: stdio MCP calls can run through the existing sandbox session when the effective sandbox/agent network policy is `none`, while allowlist-grade stdio remains blocked until a hard per-host sandbox firewall exists.

## 3. Completed Items

- Added `MCPClient.call_tool(..., sandbox=...)` support.
- Added a sandbox bridge for stdio MCP JSON-RPC initialize, initialized notification, and `tools/call`.
- Updated `MCPTool` so tool execution passes the current sandbox session to MCP calls.
- Extended `PlatformHarness.enforce_stdio_mcp_policy()` with an optional sandbox network policy.
- Allowed stdio MCP only for the sandboxed `none` policy path where network isolation is provided by the sandbox boundary.
- Kept sandboxed allowlist stdio MCP blocked because the current sandbox does not enforce per-host allowlists for stdio child processes.
- Updated AgentRuntime and WorkflowRuntime policy checks to pass the sandboxed-stdio context.
- Added deterministic tests for allowed sandboxed no-network stdio MCP, blocked sandboxed allowlist stdio MCP, blocked unsandboxed restricted stdio MCP, and direct MCPClient sandbox bridge behavior.
