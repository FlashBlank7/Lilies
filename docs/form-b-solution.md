# 形态 B 解决方案：状态机 + 小模型的判断力供给（草案）

> 状态：v0.1 骨架。命门实证来自 2026-08-22/23 真机 20+ 单构建；§3 调研结论
> 与 §4 方案待专项调研回填。

## 1. 定位

形态 B = mechanical 引擎：确定性状态机管全部流程（建图→写测试→跑测→修复→
发布，阶段转移机械可判），小模型（Qwen3-4B）是无状态提案函数；配十级机械
护栏 + 卡死自动升级 32B 的阶梯；B v2 增加"架构师（32B）开工前一次性定选型"。
它是三形态中**成本最低、行为最可控、判断力最稀缺**的一档。

## 2. 命门实证（本平台真机数据）

### 2.1 主结论：护栏压得住机械错误，压不出判断力

- 简单任务：4 单 3 过（75%），产物以**未见输入**独立复跑验证（排除硬编码
  骗验收）；建图/写测试阶段小模型边界拒绝率可降到 **0**。
- 复杂任务（日报）：**0/8**。死因高度一致——选错积木：用只做变量合并的
  `variable_aggregator` 实现分组求和。第 10 级护栏（查过手册才准用）逼它
  读了说明，**仍选回同一个**；B v2 的 32B 架构师也被这个名字骗过。

### 2.2 十级机械阶梯（全部由真实失败逼出）

给信息 → 机械算下一步 → 记账守卫 → 工具面硬门 → 机械子阶段 → 关卡达成即判
→ 强制指定必调工具（约束解码）→ 简化提案接口（复杂 schema 压垮约束解码）
→ 代劳确定性步骤（状态机代读诊断）→ 查过手册才准用。
配套原则：恢复手段优先于放弃手段（判停前先升级）；守卫按信息增量判定。

### 2.3 测量效度教训

五次"错怪模型、实为管道"（流式丢片段 / think 带崩解析器 / 思考吃光预算 /
缺闭合括号被静默丢弃 / 我们自己读错快照键路径）。实验纪律：任何"小模型
能力不足"结论必须先用非流式直连复现。

### 2.4 积木目录的可发现性缺陷（平台侧责任）

`variable_aggregator` 的名字与描述让 4B 与 32B 两代模型都误判其能做聚合计算
——命名/描述本身是选型错误的共犯。判断力问题一部分其实是**信息设计**问题。

## 3. 领域调研结论（2026-08-23，原文见 research/form-b-judgment-survey-2026-08.md）

改变方案权重的五条：

1. **改"怎么选"比改"怎么写文档"值钱得多**：Looking Is Not Picking（2026-06）
   ——80% 选型失败里模型注意力已落在正确工具上，错在读出层；改描述只救
   ≤23%，改选择机制救 59-91%。我们的 aggregator 陷阱在 Canary Tools（2026-08）
   里有正式名字："语义诱饵"，且小模型易感性差 36 倍——工程兜底是必须。
2. **专训检索器碾压按名字选**：ToolLLM 检索器 NDCG@5 84.9 vs 通用向量 45.4
   vs BM25 17.0；但 ToolRet 证明通用 embedding 在大工具集上不够（nDCG@10 33.8）。
3. **选型不求一次命中**：Agentless/LLM-Modulo 路线——采样多候选、让确定性
   验证器裁决，规划成功率可从个位数拉到 40%+；ADaPT 的"先试原子执行、失败
   才请求分解"可直接编入状态机。
4. **计算类子任务走代码**：CodeAct +20pp——分组求和这类活让模型写一段
   Python 比在积木目录里挑对积木容易得多（我们已有沙盒代码节点）。
5. **提示词可以被"编译"而非手写**：DSPy/GEPA 以护栏通过率为 metric、32B 为
   教师离线优化各状态提示（GEPA 超 GRPO 6-10% 且 rollout 省 35×）；中期
   PDDL-INSTRUCT 路线（验证器反馈微调，计划有效率 28%→94%）与我们的边界
   反馈完全同构。

## 4. 解决方案（定稿）

按成本递增分三档；每档独立可测，对应 §5 的实验臂。

### 4.1 近期：机制层（零训练，1-2 天量级）

1. **选型两段式**（对应调研 §2）：新增选型检索步——按需求语义检索积木目录
   出 3-5 个候选（先用现成 embedding + 积木手册全文，不追求完美），4B/32B
   **只在候选集内选**；候选集作为工具面硬门执法（第 11 级阶梯）。
2. **目录反诱饵改造**（对应 Canary/Anthropic 指南）：每个积木的描述补三件套
   ——能力签名（输入→输出的真实语义）、"何时不用"、易混积木指引；
   `variable_aggregator` 类语义诱饵优先处理。用 DRAFT 式流程让 32B 离线试用
   各积木自动生成初稿，人工过目。
3. **计划机械校验**（对应 LLM-Modulo）：B v2 架构师产出的选型清单先过
   确定性检查——所选积木的输出契约能否拼出需求的输出字段、依赖是否闭包；
   不过审就重采样（≤3 次），全败升级。坏计划死在开工前。
4. **计算子任务改走代码节点**（对应 CodeAct）：状态机识别"确定性计算"类
   子需求（分组/求和/对账），直接派给沙盒 Python 节点，绕开积木选型面。

### 4.2 中期：编译层（一次离线成本，长期生效）

5. **DSPy/GEPA 编译各状态提示**：以"边界通过率 + 关卡达成率"为 metric，
   拿平台已积累的转录（含每次拒绝原因）做反思素材，离线优化建图手/验收
   作者/修理手三个角色的提示与少样本。
6. **template_suggestions 升级为案例库**（对应 AWM/Memento）：成功构建的图
   按任务特征入库；命中案例时把积木候选**硬约束**到模板所用集合，失败案例
   存为负例。平台已有 template 机制，缺的是"按语义检索 + 命中即约束"。

### 4.3 远期：训练层（有 GPU，数据已在自动积累）

7. **选型/规划 LoRA**（对应 PDDL-INSTRUCT/APIGen-MT）：用自家验证器当 VAL，
   以"计划过机械校验"为信号微调 4B 的选型头；AgentPRM 式过程评分做复审。
   训练数据 = 平台转录（每单自动落盘，零额外标注）。
8. **XGrammar-2 分步约束**：选中积木后动态切到该积木的参数子语法，把
   "简化提案接口"（第 8 级）从手工瘦身 schema 升级为自动化。

## 5. 实验计划

- **臂**：B v0（现状）/ B+检索候选 / B+候选+反诱饵目录 / B+候选+计划校验 /
  B+代码节点。任务：问候语（回归）+ 日报（主战场）+ 一个新中等任务（防过拟合
  日报）。每臂 ≥5 seed。
- **主指标**：published 率、选型首次命中率、边界拒绝率、token 成本、升级触发率。
- **预注册预测**：检索候选把选型首次命中率提最多（Looking Is Not Picking 的
  59-91% 区间）；反诱饵目录单独上收益有限（≤23% 区间）——两条预测方向相反，
  可证伪。

## 6. 局限

调研中"anti-pattern 描述"的独立量化对比未找到（间接证据）；DSPy 对 4B+固定
流水线的官方数字缺乏，需自测。
