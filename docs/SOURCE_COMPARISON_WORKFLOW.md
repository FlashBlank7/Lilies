# 多份材料的事实与分歧整理

2026-09-25。员工选择项目材料并描述关心的问题，流程按事项列出各份材料的说法、原文位置、适用范围及缺项。可从项目空间「公共工作流市场」加入，也可从示例创建同名项目；得到独立可编辑的工作流、使用 Skill、5份自编材料及修改练习。

## 员工如何使用

1. 在「参与比较的材料」逐行选择文件，可说明用途、日期、对象或范围。需要对照某份要求时，将其用途选择为「要求/标准」；这只是本次比较依据，不代表平台认证了其权威性。
2. 填写关心的问题，例如“测试摘记与约定哪里不同，哪些还不能判断”。模型连接可稍后配置，草稿仍能保存；实际分析使用项目获准的原始模型调用积木。
3. 运行后先看事项与来源对照表，再看理由和引用。报告分开呈现材料陈述与模型解释；未做测试、未提及、不同批次的计划不能直接写成未实现或要求变更。
4. 下载 Markdown报告、CSV对照表、JSON结果、提取原文及定位。引用错误会保留问题和模型原判断，事项显示「待核对」；不自动反复调用模型修补。
5. 换成新资料或修改提示词时清空「沿用已有分析结果」，重新分析。若只需筛选，选择前次 `analysis.json`，调整状态或关键词再运行；这条分支不需要模型连接，也不重复分析。

没有筛选结果时仍生成可下载报告，并保留原分析。建议不会自动启动其他任务；员工可继续追问或调用项目中的其他工作流。

## 从原项目提炼了什么

原需求与方案反复提出多材料交叉比较、原文定位、矛盾展示、要求对应及缺项说明。本流程将这些共性落为可编辑步骤；来源定位及详细原件检查在本地私有记录中。

| 已有经验或要求 | 流程中的具体处理 |
| --- | --- |
| 同一事项在不同材料中分散出现 | 按事项整理来源矩阵，而不是只给一段合并摘要 |
| 材料中的要求、计划、测试摘记和主张容易混淆 | 每条陈述保留来源、适用范围及原文；日期更新不自动覆盖旧约定 |
| 找不到内容不代表功能不存在 | 缺少对应陈述时展示缺项；不能用未做测试推出未实现 |
| 二手资料引用了没有提供的原件 | 只定位实际选中的材料，不伪造外部原件页码 |
| 重复副本与同名更新 | 使用实际字节哈希区分内容；相同副本提示重复，不视为新增印证 |
| 用户只想换一种报告视图 | 沿用原文快照与分析文件，筛选分支不调用LLM，旧报告保留 |

与既有流程的分工：单份结构化抽取、两个版本的原文增删、知识库检索问答分别沿用原流程。这条流程比较选定材料的陈述；不是完整源码设计评审，也没有复现原案件分析或投资判断系统。没有继承原方案中的固定角色、阶段审批或自动反复审查。

## 实现与边界

流程使用输入、条件分支、代码、一次原始LLM调用和输出积木。平台仅为普通行表补充了项目文件下拉选择，没有新增运行时、市场系统或生成门槛。原始材料只读；每次运行保存独立结果与原文快照，副本和高级代码仍可编辑。

- 支持UTF-8文本/Markdown、文字PDF、DOCX、CSV/TSV、XLSX；每次1至8份文件，每份至多10MB，合计至多3万正文字符、400个片段。超限明确提示拆分，不静默截断。
- PDF按页提取文字，图形、图内分支和版面关系不算已识别；无文本页面单列。DOCX按包含表格的正文段落定位，不猜页码、不读取页眉/批注/附件；图片列为未读取。Excel保留工作表及单元格位置，使用已有值和公式缓存，不重算公式。
- 一次模型输出最多12个事项；这不是所有要求已逐条覆盖的证明。不同单位、对象、时段的陈述是否可比仍依赖模型理解和用户给出的语境。
- 代码只检查引用文字是否能在本次来源片段定位，以及跨来源判断是否有对应来源；不证明材料陈述真实、引用充分或解释正确。没有把检查通过当作业务验收结论。
- 引用错误不追加付费重试；保留问题供员工决定是否改提示词、补资料或核对原文。原文快照改变会明确拒绝沿用，避免旧报告悄悄引用新内容。
- 运行产物中的模型用量来自最初分析，筛选运行的实际调用情况应看该次步骤记录。API计费和模型回答质量未在本轮实测。

## 验证记录

自动验证使用明确的模型替身，代码处理与平台运行实际执行。覆盖同名不同内容、错误引用/来源、缺少要求材料、重复副本、超限、空文件、项目外路径、DOCX表格/PDF空页/Excel多表定位、旧原文冻结、筛选空结果，以及关闭模型连接后重用原分析。

四份真实项目原件在私有目录完成正文解析：7,218个字符、305处片段；三处人工预选引用完成定位和报告检查，原文件字节保持不变。这验证解析及预选引用，不代表模型理解已验证或原业务已经完成。
