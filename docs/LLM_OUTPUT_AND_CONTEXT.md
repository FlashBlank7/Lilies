# LLM 输出与对话上下文：9 月 27 日修正

## 本次实现

LLM 积木声明结构化输出时，仍先校验 Schema，再调用模型，最后严格校验实际输出。必填字段在输入末尾再次明确；未知业务事实不应为了凑齐字段而编造。

项目使用 OpenAI 兼容协议且输出明确为对象时，请求增加 `response_format={"type":"json_object"}`。这适用于支持该参数的服务，包括 DeepSeek 的 Chat Completions 接口。JSON 模式约束 JSON 语法，不能替代必填字段及业务正确性校验；依据为 [DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)，2026-09-27 核对。

普通文本、顶层数组/数字/联合类型、Anthropic Messages 连接和旧自定义 Provider 保留原有调用方式；不会为启用 JSON 模式更换服务、地址或模型。工具会话不附加该参数。接入服务返回 HTTP 400 时，错误提示会提醒核对 JSON 模式支持，不回显服务商响应中的潜在敏感内容，不自动降级或追加请求。

输出缺少必填字段时仍失败，不补造字段、不交给后续节点。错误显示节点及原校验原因，提醒从原运行继续以重试失败节点。恢复沿用现有机制，没有新增自动重试循环。

项目对话将所有工作流共用的调用说明从各条目录项提到目录外一次提供；工作流编号、用途、输入输出、修订号及按需读取入口保留，每轮仍读取当前草稿。没有清空会话、裁剪员工回答或更改历史结果。
