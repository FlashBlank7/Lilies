一 · 判据

先把"算通过"写成代码

出题人即判卷人时，"通过"极易被放宽。因此四条件全部写死在 scripts/daily_report_benchmark.py 里，判卷结果落盘，出题人无法临场放水：

  • C1 发布成立——status == published。
  • C2 锚定验收——存在 mandatory 测试，且至少一条断言了具体数值（equals，非结构断言）；平台持有对当前草稿有效的验收证据。
  • C3 照妖镜——按种子随机生成验收中从未出现的门店名与金额，复跑正式版，与判卷方自带的独立 Python 参照解逐字段比对。
  • C4 无豁免——构建 error 为空，发布决策事件里没有 missing_evidence。

C3 是这套判据的核心。它挡住的是"把样例答案硬编码进工作流"——一种能让所有形状类验收全绿的静默作弊。判卷方的参照解不 import 任何平台模块：判卷方与被判方共用一份代码就等于没判。

基准效度必须先于模型评价。该基准曾在积木层根本无解（公式引擎无法对对象数组分组求和），两形态早期"失败"里有一半是无解考卷的必然。现已补 sum_by/pluck 并附机器可证的参照解——能力若倒退，参照解测试先红。

二 · 架构

验证器经济体

三个形态不是三个产品，而是同一套结构下"提案粒度"与"控制流归属"的三个取值。所有模型都是提案者，确定性验证器是唯一裁判，0/1 判决同时充当质量门、教学信号与路由学习信号。

  P["提案层

阶段推进 · 关卡判定 · 预算与守卫"]
  P -- 提案 --> V
  V -- "0/1 判决 + 可执行改法" --> F
  F -- 上下文 --> P
  V -- 关卡达成 --> S
  S -- 下一步 / 工具面 / 强制动作 --> P

形态 A：提案者是一个自由循环的 32B，提案粒度大（一轮多次调用），受同一验证器与纪律硬门管辖。形态 B：提案粒度最小化到单次工具调用，控制流全部归代码。形态 C 不是独立引擎，是 B 的提案层从 n=1 变 n=N。

形态 B 的分工来自 MinionS 的落点——强模型把任务切碎到机械粒度，小模型照单执行。本实验中它的具体形式是：架构师在 architecture_plan 里写下积木选型与完整公式表达式，执行者只负责落库、接线与填表；选型偏离是硬门，不是建议。

三 · 机械阶梯

模型每不肯前进一次，代码就多拿回一层控制权

十级，全部由真实失败逼出。它回答的是"哪些职责可以从模型手里收回代码"，判据是可下放度 = 硬门覆盖度 × 调用频次。

  1. 给信息：草稿投影、积木目录、已存在 id幻觉不存在的积木类型
  2. 给机械算出的下一步：校验待办每轮现算加完节点不知道该干什么
  3. 记账式守卫：反刍判停、只读循环判停同一被拒提案重试 17 轮
  4. 收窄工具面（执行边界硬门）工具列表只是建议——模型照着系统提示里的名字乱叫
  5. 机械子阶段：骨架齐了就只准接线三个节点全加好，从不调 draft_connect
  6. 关卡达成即判，不等模型宣布完成测试早写好了却继续查目录到预算耗尽
  7. 强制指定必调工具（命名 tool_choice → 约束解码）工具被收走后干脆不调任何工具
  8. 简化提案接口（瘦身 schema，边界校验不减）复杂 schema 压垮约束解码，连吐三次空参数
  9. 代劳确定性步骤：状态机替它读执行台账、替它查手册修理手读完诊断就是不动手，反复重读同一份
  10. 方案与判据也进硬门：选型偏离当场拒、验收输入与断言先被校验方案文本里的"按此实现"只是建议；判据本身错了后面每一步都在追不存在的问题

阶梯尽头的形态很清楚：小模型剩下的唯一职责是"给出一个具体的配置提案"，其余全部由代码承担。这条演化路径本身就是形态 B 的结果——它把"harness 与模型无关"从口号变成了可度量的清单。

死因性质的迁移

比通过与否更有信息量的是死因类型随修复推进的变化：

1–4  轮   机制互锁、拒绝不指路      →  模型无路可走
5–9  轮   判停不判关卡、方案只是建议  →  平台不认账
10–18 轮  教错语法、报错被误读       →  平台把它教歪，或认不出对的

后期九轮的产物质量都很高：第 14 轮的工作流手动复跑输出一字不差、第 13 轮的验收测试完全合格、第 17 轮数字全对。模型做对了，平台没认出来，或者平台先把它教歪了。

五 · 纪律

七条由失败逼出的工程约束

这些不是本基准的特例，而是"确定性验证器 + 小模型提案"这套架构的通用约束。每条都带真机构建号，可回溯。

判停

任何判停路径，判死之前先判一次关卡。守卫与预算是用来止损的，关卡已达成就没有损可止。

同一错误在三个出口各犯一次：93430e0b · 82a730cd · 400a231e

教学文本

给模型看的每一个字，都要按"它会原样粘回去"来写。人类友好的显示格式会被当成输入格式，示例里像真名字的东西会被当成真名字。

点号路径 881d90a6 · 占位符「记录」04a81cb8 · 目录只给英文标题 1334c391

报错

报真因，不报最先撞上的症状。字符位置、类型不匹配往往只是真因的副作用。

template( 报字符错 04a81cb8 · JSON 字符串报"需要数组" 13284038

歧义

错误信息还要排除误读。模型可以自由命名节点，而节点名会嵌进平台的句子里——凡是把用户数据拼进模板的地方，都要假设它会和模板词撞车。

节点 id output 与"输出"撞车 1cc9a0a5

判据

验收是判据，判据本身要先被校验——输入类型对照起点声明，断言路径对照终点交付字段。判据错了，后面每一步都在追一个不存在的问题。

输入 13284038 · 断言 bdefc84a

信息面

改善信息面会带来新的误用面。每条"格式类"的信息都要配一条机械校验，不能指望提示词把适用范围说清楚。

投影的引用格式被搬进断言 bdefc84a

进展判定

判进展看状态变了没有，不看工具调用成没成功。反复重写同一条测试、反复提交零变化更新，执行边界都会回"成功"。

400a231e · 82a730cd

判卷器

判卷器也要按判据写，不按实现细节写。C2 曾按转录里有没有 test_run 判——机械引擎由状态机发起，因而一律被误判。

a6284ec0：修完后 C2 翻绿、C3 依然红，证明放宽的是误判不是真错

另有两条贯穿性判断：能机械判出来的事不要留给模型猜（该修引用方还是产出方，用 difflib 判近亲即可）；同一条规则对"谁在做"要分开裁——判据是这一步之后还有没有人会看一眼。没人看，平台要么替它做对、要么拦住；有人看，平台只提示、不代劳。

六 · 局限

这份报告不能声称什么

  • 单任务族、单机、样本量小。形态 A 九单、形态 B 十八轮，一个任务族。作为形态验证与机制清单成立，不作为统计结论。
  • 判卷人即出题人。缓解手段是判据机械化 + 独立参照解 + 随机照妖镜，但出题人仍然是同一人。
  • "十七个缺陷全是平台的"有归因边界。每一处都有可复现的转录与回归测试支撑，但"若这些缺陷不存在，模型是否仍会失败"无法反事实验证。
  • 缺陷发现循环需要人在环。十七个缺陷全部由人读转录定位。客户撞上第十八个时，目前没有等价路径——这是产品化的真实缺口，不是实验结论。
  • 提案竞争（形态 C）与学习型路由未进本轮实验。多温度 best-of-N 已实现但未做消融；Beta-TS 路由与树搜索仍在设计阶段。

七 · 参考文献

设计依据

下列文献分两类：承重——直接决定了本架构的某个结构选择；参照——提供量级预期或反面证据。

承重 · 接口即能力

NeurIPS 2024Yang et al., SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering。为 LM 定制的接口（紧凑观察、即时反馈、护栏）比裸 shell 高 10.7 个百分点；单是"编辑内嵌 lint 门、语法错即拒并回显"一项就带来可测增益。本架构的"拒绝即教学"与十级阶梯直接源于此。
githubmini-swe-agent（SWE-agent 团队，2025）：100 行、纯 bash、线性历史，SWE-bench Verified >74%。结构极简不是瓶颈——这支持了"控制流归代码"而非"更复杂的 agent 框架"的取向。

承重 · 强弱模型分工

arXiv:2502.15964Stanford Hazy Research, Minions / MinionS（ICML 2025）：云端强模型统筹、本地小模型执行；把任务切碎到机械粒度后，自由对话式协议省下约 30 倍云端成本。形态 B v2 的"架构师定选型、执行者填表"即此落点，本实验把它推到"架构师写下完整公式表达式"。
arXiv:2305.05176Chen et al., FrugalGPT：级联 + 答案打分器，省 98% 成本匹配 GPT-4。升级阶梯（4B 卡死→32B 接手）的成本依据。
arXiv:2502.11133MasRouter：级联控制器统一决定协作模式→角色→每角色模型。与 arXiv:2505.13516（HALO，三层 + MCTS 搜索工作流）同为"学习型路由"的参照，对应本框架尚未落地的 L2。

承重 · 验证器 × 采样

arXiv:2407.21787Brown et al., Large Language Monkeys：有验证器的域里，覆盖率随采样数对数线性上升。这是"提案竞争"在本架构里成立的前提——我们守着一个完美的验证器却在做单点采样。
arXiv:2501.14723CodeMonkeys：并行 + 串行组合，ensemble 裁决 66.2%，超过最好的单一成员。
arXiv:2510.02611多温度实证：Qwen3 0.6–8B 在多温度下较单温度再 +7.3 分，且 N 越大最优温度越高。本实现的温度阶梯 0.2/0.7/1.0 依据此。
arXiv:2503.04412Sakana AI, Wider or Deeper? Scaling LLM Inference-Time Compute with Adaptive Branching Tree Search（AB-MCTS / TreeQuest）：0/1 验证信号与 Beta-Bernoulli 共轭，树可序列化进构建状态。对应尚未落地的 L3。

承重 · 约束解码与提示编译

arXiv:2501.10868JSONSchemaBench（1 万个真实 schema）：语法约束可保证合法输出且比无约束快约 50%，但复杂 schema 下覆盖率会从 86% 崩到 3%。这是阶梯第 7 级"瘦身 schema"的直接依据——强制 tool_choice 那一步换成只含必要字段的精简定义，落库仍过完整校验。
arXiv:2411.15100XGrammar：已内置 vLLM / SGLang，是本实现命名 tool_choice 走约束解码的运行时基础。
arXiv:2507.19457GEPA（ICLR 2026 Oral）：反思式提示进化，平均超 GRPO 6–10%（最高 +20%）且 rollout 省 35 倍。边界拒绝的错误正是现成的反思素材——这是把本架构的 0/1 判决回灌为提示优化信号的路径。
arXiv:2509.13351PDDL-INSTRUCT：用 VAL 验证器反馈做逻辑 CoT 微调，Llama-3-8B 计划有效率 28%→94%。"机械验证器 × 小模型微调"与本架构的边界反馈同构，对应 L4 搜索蒸馏。

参照 · 量级与反面证据

arXiv:2406.04692Together AI, Mixture-of-Agents：分层聚合多个开源模型输出，AlpacaEval 2.0 达 65.1%（GPT-4o 57.5%）。但 arXiv:2502.00674（Self-MoA）给出反面证据——单模型自聚合常常更好。多模型异构不是无条件收益，这也是本实现先吃同模型温度阶梯的原因。
arXiv:2408.06292Sakana AI, The AI Scientist；v2 见 arXiv:2504.08066（去掉人写模板，改为实验经理 agent 管理的并行 agentic 树搜索）。同期的 AI CUDA Engineer 曾曝出 agent 钻评测空子的 reward hacking 事件——这是本报告坚持"照妖镜 + 独立参照解"的直接教训来源。
vLLM #19056流式工具解析器丢片段（修复于 v0.11.0）。曾导致连续数小时把"4B 拍平嵌套 JSON"误判为模型能力问题。由此立下纪律：任何"小模型能力不足"的记录，先用非流式直连复现、排除管道故障后才可归因模型。
