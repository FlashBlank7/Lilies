# 已知缺陷与修复顺序（病历单）

> 与 [lean-core-stage-report.md](lean-core-stage-report.md)（成绩单）配对阅读。
> 排序原则：按"什么时候会咬人"，不按学科分类。
> 建立日期 2026-08-08；每修一项在行首打勾并注提交号。

## 一、已经在咬的

- [ ] **1. 数据层无节制增长** — DB 实测 557 MB / events 表 82.8 万行（仅 321 个运行、29 个构建）。事件无归档/清理/分表；真实客户节奏下数月到 GB 级：查询变慢、备份笨重、SQLite 写锁竞争加剧。
  修法：运行事件冷归档（JSONL 落盘，DB 只留近期），读取端合并回退——诊断能力不因归档丢失。
- [ ] **2. 构建期弱测试穿透** — ERP 盲测实证：她的测试金额全 0 也全绿（只断形状不锚数值），而"测试绿才能发布"是核心闸门。
  修法：建造者数值锚定纪律 + 监理出卷数值断言回灌构建期测试。
- [ ] **3. 返修的信念锁死** — 错误诊断进历史后，后续投诉全被旧结论打发（盲测中外部事实也未击穿，最终靠平台修复解围）。证据身份已补，机制性解法未做。
  修法：返修时强制用报障原始输入自跑复现，新鲜账本压过旧信念。

## 二、接真实客户单就会咬的

- [ ] **4. 商用外壳四缺** — 无部署包装（Docker/HTTPS/备份）；单 token 无权限体系（访问码是唯一对外隔离）；无计费核算——且 provider 缓存折扣字段未入账，成本估算虚高 5–6 倍；并发未压测（单进程 + SQLite 写锁）。
- [ ] **5. 双执行体系并存** — API 直跑与 worker 认领两套执行路径共存；连坐 bug 已修，但执行权架构未统一，同类竞态还会再长。
  修法：收敛单一执行权（全队列，或 worker 仅离线任务）。
- [ ] **6. 审计脱敏误伤计量字段** — 事件里 `input_tokens` 等含 "token" 的键被脱敏成 `***`，诊断被迫绕道数据库。
  修法：脱敏词表区分凭证 token 与计量 tokens。

## 三、规模化才咬的

- [ ] **7. 质量体系单腿** — 后端 443 测试全绿，但前端零测试文件（"切换不即时"的闭包 bug 即由此漏过）、无 CI、lint 不强制。
  修法：GitHub Actions（pytest + tsc）先立起来；use 页/会话页补烟测。
- [ ] **8. 知识索引全局命名空间** — 跨应用同名索引互踩，目前靠约定。一客户一实例可天然化解；多客户同库前必须加命名空间。
- [ ] **9. 转录/产物无生命周期** — 单构建 78 轮的先例说明重返修应用会长出巨型转录；运行产物目录只增不减。

## 四、已知且接受的能力边界（不承诺、不宣传）

- 模型单供应商（DeepSeek；思考失控风险由自愈重试兜底）
- 训练能力 = 表格二分类逻辑回归
- 搜索 = 新闻源级别（Google News RSS）
- 真实厂商 ERP 协议未实战（确定性假靶通过 ≠ 用友/金蝶直连）
- 对话界面无服务端会话状态（记忆依赖工作流自带历史字段）
- 移动端未验证
