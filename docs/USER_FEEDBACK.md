# 用户意见反馈

2026-09-28。全局账号导航提供「意见反馈」和「反馈记录」，记录页面为 `/feedback`。可直接提建议，也可在对话回答、工作流画布、运行结果及对话错误旁选择「反馈给平台」。

## 员工如何使用

1. 写一句意见或问题。类型可选结果不对、操作不方便、运行问题、功能建议或其他；不要求关联项目。
2. 从业务入口打开时，可选择附带当前项目、会话、回答或运行的定位编号。不会自动复制对话全文、原文件、模型配置或运行日志。页面显示关联范围，编号可展开查看。
3. 如需具体说明，可主动勾选并编辑当前内容片段，或者选择一张 PNG/JPEG/WebP 截图（最多3 MB）。提交前可查看或移除。关闭面板保留当前页面内的草稿，刷新页面不保证保留未提交内容；切换账号不会继承草稿。
4. 提交后从「反馈记录」继续补充、查看管理员回复和处理进展。已解决或暂不处理的问题仍可回复，并可勾选「问题仍存在，重新打开」。已提交内容、回复和阅读进度保存在服务端。

「有用／需要修改」仍用于快速评价。选择需要修改后可选填文字意见；不会强制打开表单。「让智能体修改」继续原有业务处理，「反馈给平台」交给平台维护者，提交、回复和查看均不调用模型或重新执行任务。

## 管理员如何处理

打开「反馈记录」，默认查看用户反馈；可切到自己的反馈。支持按状态、类型、来源功能筛选，并按意见摘要、项目名称或提交者搜索。阅读内容后可以回复并更新为「已收到、处理中、已解决、暂不处理」。状态变更必须附说明，提交者看到同一条回复与状态记录。

账号导航显示未读条数；页面可见时约每30秒检查一次，窗口重新获得焦点、提交反馈或阅读后也会刷新。不发送邮件、聊天软件通知或自动代答。两个管理员同时修改状态时，过期提交返回冲突，刷新后继续，已写文字保留。普通补充可以追加；读旧版本或在旧页面补充，不会吞掉尚未看过的新回复。

反馈只对提交者和平台管理员开放；同项目协作者不能互相查看。项目被移除或权限收回后，提交者仍可查看自己的已提交内容和管理员回复，原项目入口显示不可访问，不借反馈授予原资源权限。截图经过同一反馈权限验证。

## 实现与验证

- 复用现有登录、账号和 SQLite 数据库，新增反馈、消息和阅读进度表；兼容初始化不清除项目或原快速评价。文字与可选截图在同一事务保存，失败不留下半条反馈。重复提交键保持同一条记录，修改内容复用旧键会明确报冲突。
- `POST/GET /api/v1/feedback` 提交和查询；`GET /feedback/unread` 查询当前账号未读；`GET /feedback/{id}` 读取；`POST /feedback/{id}/messages` 回复及状态更新；`POST /feedback/{id}/read` 标记实际看过的版本；`GET /feedback/{id}/messages/{message_id}/image` 读取所选截图。提交/回复为 multipart，`payload` 是 JSON 字符串，`image` 为可选单张图片；这些 JSON 不要求普通用户填写。
- 自动测试模型出口关闭：最终受影响后端21项通过，前端全量219项通过，类型检查和生产构建通过。覆盖账号/项目/会话隔离、截图权限、失败回滚、去重、状态冲突、未读版本、草稿保留、可选片段、焦点恢复及入口兼容。
- 隔离实例的员工与管理员通过浏览器完成主动提交、管理员回复并解决、员工重新登录看到未读、补充并重新打开；从实际运行结果提交关联反馈并编辑所附片段。390×844同源内嵌视口完成窄屏输入与提交；属于模拟尺寸，不是物理手机。截图经真实 multipart 和组件选择/预览测试，未操作原生文件选择窗口。
- 验收使用自编内容，原任务及输出保持，模型调用为0。没有向真实员工发送测试消息，也没有引入第三方反馈服务、自动训练或自动经验更新。

首版使用按钮提交与站内回复；对话自动生成反馈草稿、邮件通知、公开投票及反馈自动转开发任务不在本次实现中。后续根据实际收到的问题决定改进优先级。
