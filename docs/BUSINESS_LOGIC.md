# 业务结构 · v0.6

产品意图见 PRODUCT_NORTH_STAR.md。以下为实施合同；完成状态见 DEVELOPMENT_PLAN.md 和 WEEKLY_LOG.md。

## 三类独立对象

任务保存输入、运行状态、结果、费用与停止接续信息，可以是独立训练，也可以是工作流运行。
工作流保存可编辑草稿及历史修订；结构合法且符合项目权限即可保存，资源未就绪作为待配置项。重新运行固定当前草稿，继续运行沿用原快照。
资源属于项目，包括数据集、模型引用、文件、知识及共享记录。模型引用可先创建后绑定；运行固定实际模型版本、预处理和环境，重新绑定不改变旧结果。

## 客户路径

人通过画布装配或从预设加入工作流/任务智能体 → 助手通过项目能力目录查看接口并调用 → 查看结果。助手也可以查询全局积木目录协助搭建，但新建或修改的草稿需要人加入可调用清单；不得通过直接代码或训练工具绕过清单。

AI 和人工共用草稿接口。一次完整图或相关批量改动原子保存，使用修订号防止覆盖并发修改；直接应用并提供撤销。生成不会自动执行业务。

## 接入与交付范围

首次接入新系统允许确认业务含义、配置连接、由助手生成适配代码并迭代验证；必要时技术人员协助。验收针对约定的接口、输入范围和业务规则，不要求智能体面对任意陌生系统一次自主交付，这也不属于未来产品目标。

配置和流程确认后，日常使用应复用已保存的规则与适配结果，避免反复解释同一事项。平台正确执行、保留进度并说明未完成原因；缺少接口、业务含义不明或外部操作状态未知时可以停止等待补充。零技术救援目标针对固定验收范围内的重复运行，不包含首次接入的全部准备工作。

上述范围说明不新增审批、自测门槛或复核角色，不改变随时保存草稿的能力。业务工作优先使用现有积木、适配代码和可复用工作流，只有明确的平台共性缺口才进入平台开发范围。

## 工作流搭建与调试方法

按用户确认，复杂任务默认采用以下方法。分析、搭建与调试可迭代进行，任何阶段都可保存或修改草稿；这些步骤不是新增审批或保存门槛。

1. **分析问题，划清边界。**明确业务目标、完成条件、可用资料与服务，区分平台可承担的处理、外部系统的实际功能以及需要补充的业务信息。把可解决的部分纳入流程，未知部分保留为明确待配置项。
2. **拆分工作流，定义输入输出。**按可独立使用、验证和恢复的业务目标拆分，明确每条流程的输入、输出、依赖、字段含义及失败表现。小任务不强拆；不按每个 API 请求机械拆成一个工作流。
3. **准备假服务与合成输入。**对外部依赖按接口资料、样例或明确约定创建有状态的假服务，模拟读取、写入及故障。纯计算流程可以只用合成数据。缺少真实接口资料时标明假设，不能把自己定义的模拟接口称为原厂兼容接口。
4. **逐个工作流独立调试。**即使 B 依赖 A，也先用符合 A 输出约定的合成数据作为 B 的输入，无需等待 A 完成或每次重跑 A。合成输入保留标识、版本、时间和业务含义，覆盖正常、空值、歧义及适用的部分完成场景。核对实际输出与假服务状态，不能为了通过而把预期值当成实际结果，也不能无依据改变假服务来迁就错误流程。
5. **串联验证。**各流程能独立工作后，按真实依赖关系连接，用 A 的实际输出运行 B，检查字段和语义传递、原目标保留、失败恢复与重复操作。单个流程通过不自动代表整条链路通过；联调失败可回到相应流程独立修正。
6. **按范围接入真实服务。**在约定环境中配置真实连接，核对认证、字段、状态变化和结果查询，确认适配是否成立。模拟测试通过不等于真实接入完成；接入差异通过适配与迭代处理，不默认扩大平台职责。

以影音任务为例，可按“盘点数据 → 筛选清理目标 → 执行清理 → 回读核对”拆分。筛选流程先用模拟盘点结果调试；执行流程先用合成目标列表及假服务调试；回读流程先用原目标与不同完成状态调试，再串联。这是后续搭建的拆分示例，不表示现有验收流程已改成四个独立工作流。

假服务和输入样例可由智能体生成，业务含义与外部接口仍以可用资料和已确认约定为依据。人员配置连接、把流程加入项目能力的原有分工保持有效。该方法本身不新增执行引擎、复核智能体或审批流程。

## 项目与界面

主导航为对话、工作流、资料与知识、模型、运行记录；连接和能力权限归入设置。项目 Skill 列表只返回用途，正文及引用资料按需读取；首批说明如何调用已有流程及建模工具。

## 账号与共享

用户名密码开放注册，新账号为普通用户，使用管理员后台配置的项目 API 助手或 Codex 服务。项目创建者是负责人，可添加已有账号为协作者；平台管理员管理账号及旧项目归属。协作者使用项目资源并编辑运行工作流，负责人管理成员及业务资源连接；项目助手和生成服务的来源、模型连接由平台管理员配置。

项目接口、旧资源地址、文件下载和运行事件使用相同身份与成员权限。浏览器使用可撤销会话，多设备独立登录；既有项目不会自动开放给新注册用户。独立对话与明确保存的项目共享结果分开管理。

官方智能体提供独立账号服务、项目来源选择、员工会话隔离、额度保留和持久排队。生成与任务来源可分别设置，业务 LLM/视觉/Embedding 仍为原始 API。结果可保存为项目方法，并主动分享到指定项目形成独立副本。功能统计不记录正文，详见 [使用说明](OFFICIAL_AGENT.md)。

## 兼容

保留现有工作流格式、历史快照和必要执行器。旧控制积木退出默认目录；不自动修改客户草稿和运行。独立 LiliesAgent 仍是单独项目，若接入使用版本化 HTTP，不共享数据库或直接导入源码。
