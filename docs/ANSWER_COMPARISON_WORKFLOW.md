# 同题回答与用量对照

2026-09-25。用于员工想比较同一问题的两份回答，并保留材料、请求模型、用量和失败原因的场景。可从「公共工作流市场」加入项目，或从示例创建同名项目；副本包含可编辑流程、使用 Skill、三份自编材料和修改练习。

## 使用方法

1. 填写问题，可选择项目中的 TXT、Markdown、CSV 或 TSV 文字资料。默认两条回答都沿用项目模型，属于同一模型的两次回答。
2. 要比较同一 API 支持的不同模型，在画布选择「回答A/B」，展开「指定同一 API 的其他模型」，填写模型名并保存。仍使用原项目连接的地址和凭据，不能在这里更换服务商；缺少模型时明确报错，不自动替换。
3. 运行后查看获得了几份回答、实际提示词和图片输入是否一致，再对照内容与已报告用量。没有另一个模型评分，也不根据一次结果自动选赢家。
4. 可下载回答原文、Markdown、用量 CSV、输入快照及 `answers.json`。只需重新导出时选择已有 `answers.json`；这条分支不调用模型，连接禁用时也可运行。
5. 换问题、资料、模型或提示词时，新建运行并将「只导出已有回答」留空。前次结果保持原输入和原回答。

建议消息仅准备输入，由用户发送。员工可以继续询问、纠正和保存有用的方法，不要求先完成对照流程才能处理其他任务。

## 经验来源与实现

来自已有研究工作台交接材料中的同题多模型回答、上下文保留、耗时和用量展示需求。本地该来源只有文档，没有可运行的原工作台代码；本轮实现通用方法，没有宣称复现原系统或验证模型质量。已有机器学习候选的指标、基线和试验耗时继续使用现有建模页面。

流程由输入、条件、代码、两次原始 LLM 和输出积木组成。每条调用默认最多2048输出 token，顺序执行，不自动重试或互评。一次失败仍保留另一份回答；两次均失败时显示0/2，生成报告不等于模型成功。

输入问题最多4000字，可选文字材料最多16000字符/2MB，代码先检查再调用模型。材料用于提供共享文字上下文，CSV并不因此获得数值计算；文档解析与数值分析分别使用其他已有流程。没有嵌入完整外部智能体。

制作时修复了两项底层问题：原始LLM节点的显式模型名原先被项目默认值覆盖，现在在该节点调用期间生效，退出后恢复；OpenAI兼容服务未提供的用量字段原先会补0，现在保留未知并正确识别明确报告的0。节点输出补充请求模型、调用秒数及输入指纹供流程引用。

## 如何理解结果

- 请求模型名不证明服务端实际权重或版本；不同模型的通用质量不能从一次回答推出。同名模型的两次输出也不能当成不同模型比较。
- 实际输入指纹包含该节点系统指令、提示词和图片。员工若单独修改其中一个节点，报告会说明输入不同；不能把这种差异只归因于模型。
- `未报告` 表示当前没有该项用量，不能解读为0或免费。明确报告的0原样保留；缓存与推理计数不额外加到总量中。只有服务报告或已有明确价格配置支持的费用才展示。
- 秒数是一次节点调用所观察到的耗时，包括等待与传输，不是稳定性能比较。报告分开保存输入/输出用量，不从字数反推供应商计费。
- 失败调用保留错误，其模型和耗时若未取得输出则提示查看运行步骤；不估算失败调用费用。报告显示完整原回答，引用格式、事实和结论仍需要使用者判断。
- 旧回答重新导出的用量是原调用记录，不能当作导出时又调用了模型；本次步骤记录可查看实际执行。

## 验证范围

自动测试关闭远程模型出口。OpenAI与Anthropic两种协议、主模型与视觉连接均通过本地HTTP替身核对：显式节点模型到达请求，下一节点继续使用项目默认值，连接配置不被改写。测试覆盖缺模型、0/2与1/2、用量缺项、同名文件改动、输入指纹、旧结果重用和原输入快照变化。

员工账号浏览器实际创建副本，在画布修改模型名、保存、运行、修复缺模型、换资料和问题，并在关闭连接后重新导出旧回答。四次运行依次得到2/2、1/2、2/2、旧2/2；前三次共六条本地替身请求，导出没有新增请求。24项产物下载接口通过，旧结果与文件保留。桌面实际下载CSV，390×844下选择旧回答、运行和下载Markdown通过，整页宽度保持390，表格内部滚动。

受影响模型测试68项通过，新流程及目录测试11项通过，后续相关回归53项通过/10项额外计算配置跳过（测试集合有重叠）；前端194项、类型检查和生产构建通过。未新增付费调用，未测试实际模型回答质量或员工生产使用效果。试用项目中的本地替身连接已禁用，报告仍可重开和导出。
