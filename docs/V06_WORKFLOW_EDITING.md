# v0.6 工作流生成与修改

项目负责人在“设置 → 工作流生成模型设置”选择沿用主模型，或单独配置模型 API、密钥及思考模式。生成连接仅负责创建和修改工作流；项目对话、业务 LLM 和视觉模型仍使用各自连接。独立连接未启用或调用失败时直接显示错误，不自动改用其他连接。恢复“沿用项目主模型”会移除独立连接，后续生成跟随主模型设置。

工作流画布的“让 AI 修改工作流”支持整个流程、选中节点和循环内部三种范围；嵌套循环按名称路径选择。点击画布“修改所选”或右键菜单会打开选区输入。描述修改后一次应用，无需先运行、确认需求、阅读手册或获取预览凭据；未绑定模型、未准备数据的草稿仍可保存。

选区修改保留范围外节点、配置、位置和边界连线。需要删除边界端点时扩大选区；循环内部修改保留外层节点的参数与连接。生成结果仍须符合积木结构、引用关系和项目能力限制。

每次修改固定开始时的草稿修订号。期间发生其他已保存编辑，会返回冲突并保留已有修改；撤销也使用相同的修订号保护，不能覆盖后续人工编辑。当前未保存的节点表单须先保存。生成和撤销均不会启动业务运行。

当前验证覆盖独立连接保存/继承、密钥不回传、负责人权限、局部及多层循环修改、撤销、并发冲突。生产构建页面实测了连接设置与重开、选区提交和缺少连接的明确错误。生成合并测试使用替身模型；本阶段未以此替代真实模型生成效果验收。旧的无项目编辑器仍保留兼容入口。后续已补齐 [循环内部人工画布编辑](V06_LOOP_EDITOR.md)，内部选区修改会同时携带层级路径。

阶段回归：后端全量 3622 通过、14 跳过；前端全量 110 通过，类型检查及生产构建通过。自动测试关闭模型出口，真实供应商未产生本轮调用。


## 2026-09-21：真实选区修改与并发

使用现有公开论文验收项目和原引用问答流程，在生产页面选择回答节点，要求仅将输出上限从 256 改为 128。生成沿用已授权的 DeepSeek 模型，独立生成连接关闭思考，未修改业务模型连接。第一次请求一次保存为新修订，逐字段比较证明仅指定参数变化，选区外节点、布局和连线均保留；页面撤销后上限恢复为 256。

第二个页面基于撤销后的修订，将同一参数人工改为 192。第一页再次启动真实 AI 修改后，第二页立即保存；人工修改成功，模型返回时保存被 409 拒绝，最终草稿仍为人工值 192。没有注入延迟、替换模型输出或直接构造冲突结果。

实际证明的是选中节点修改、撤销和并发保护；循环内部真实模型页面效果仍待有限次数复验。原有范围、引用及循环自动测试继续保留，不能替代这项真实验证。
