# 当前版本的机器学习能力升级

目标来自用户：彻底进化机器学习的能力。工作覆盖从企业数据到可复用预测流程的完整路径，不能用新增一个算法或一组单元测试代替整体完成。

## 已核对的基线

现有平台支持 CSV/TSV/XLSX、表格分类与回归、按预测时点提取工艺时序特征；已有 scikit-learn、Optuna、AutoGluon，固定评估划分、独立训练任务、停止接续、模型绑定、下载及工作流调用。数据分析此前仅提供概况扫描。工作流建模节点共用宽泛配置，输入输出及表单仍需要按用途整理。

## 本版持续推进的范围

1. 数据操作：明确输入数据形态，提供实际统计与清洗能力，保留原数据及可继续计算的结果。首先覆盖用户点名的异常值处理和 Spearman。
2. 训练预处理：将需要估计参数的清洗、编码、特征筛选放进训练折，保存后在预测时复用。探索性全表分析与模型评估的拟合过程要明确区分。
3. 建模与比较：核对现有引擎的真实能力、可配置范围和限制，在一致的数据划分下比较基线、候选、分组误差与资源消耗。按实际项目失败增加必要能力，不把安装新模型库当成效果提升。
4. 工具与工作流：独立智能体操作和工作流执行使用同一实现，操作可配置、结果可连接、流程可复用；长任务保留停止、接续及环境版本。草稿始终可以在资源就绪前保存。
5. 用户操作：整理宽泛的建模配置，按操作展示参数和输出，明确不支持的数据；基础分析无需用户写代码或 JSON。
6. 工业项目验证：在当前企业项目资料中确定可计算的任务、目标列、划分方式和业务指标，实际跑数据处理、训练、预测及工作流复用。单元测试、构造数据和历史日志不能替代真实项目效果；真实模型调用仍需当次授权。

## 2026-10-16 第一批：数据分析与异常值操作

分支 `codex/ml-capabilities-20261016`，独立工作区；未部署。

`project_modeling(action="analyze", dataset_id, analysis=...)` 与画布 `data_analysis` 使用同一计算实现。旧节点省略 analysis 时继续输出原来的数据概况。

参数例子：

```json
{"operation":"spearman","columns":["temperature","quality"],"missing":"pairwise"}
```

```json
{"operation":"outliers","columns":["temperature"],"method":"bounds","lower":0,"upper":200,"handling":"drop"}
```

- Spearman：逐对有效样本数、相关系数、渐近 p 值、矩阵与 CSV/JSON 文件；支持成对删除、完整行删除、遇缺失值停止。常数列与不足三个样本返回未定义原因，不能把它们写成零相关。
- 异常值：IQR 或指定上下限；只标记、删除所在行、截到边界。只修改明确选择的数值列；缺失值保留，无穷值报错。输出异常位置和原始行号映射。
- 删除与截断产生独立数据集，输出 `dataset_id` 可直接连接下一次分析或训练；原数据不变。运行使用独立版本的建模环境。
- 新操作当前接受单张表格的数值列；独立标签表和工艺时序需要先明确整理，运行时返回具体限制。IQR 在全表估计，不能把这种探索性处理宣称为无泄漏的训练预处理。
- 画布按操作显示参数，并提供中文选项及对应输出字段。列与资源可先留空保存草稿，运行时再检查。

## 2026-10-16 第二批：混合数值到可复用预测

仍在同一独立分支，未合并或部署。

- `analysis.operation="numeric"` 对明确选择的列做确定性数值整理。`numeric.missing_tokens` 指定文字占位符，`numeric.intervals` 可选拒绝、中点、下限、上限或缺失；默认拒绝区间，未知文字和布尔值报错并指出列和数据行。CSV、TSV、XLSX 中被选列的 `NA` 等原始文字保留到规则处理阶段，不能先被读取器悄悄解释为缺失。
- 输出新数据集、逐项转换文件和行号映射；不删除行、不覆盖源文件。表头位置与表头下方跳过行数可以配置，导出的普通 CSV 重置表头设置，继续分析不会再跳过有效样本。
- `FeaturePlan.numeric` 调用同一个转换实现；规则保存进候选配置和完整模型下载包，训练、后续无标签预测与 AutoGluon 均复用。转换本身不估计统计量，缺失值填补等仍在训练折内拟合。下载包中的独立 `model.joblib` 不包含文件读取与这部分外部规则，复用完整包时需保留配置及 worker。
- 新预测文件使用自己的工作表和表头位置，模型继续固定字段含义、特征方案与环境。平台训练模型和导入的 Pipeline 都支持这一行为。旧候选缺省新字段时按默认值比较，避免把新增默认设置误判为用户改变特征。
- 画布提供中文数值整理选项、占位符和区间策略，以及对应输出；特征节点可通过表单配置训练数值规则，无需手写代码。

例如独立分析或数据分析节点：

```json
{"operation":"numeric","columns":["height"],"numeric":{"missing_tokens":["/"],"intervals":"midpoint"}}
```

训练时保留原始输入并在预测复用规则，则使用候选的特征配置：

```json
{"columns":["height","pressure"],"numeric":{"columns":["height"],"missing_tokens":["/"],"intervals":"midpoint"}}
```

上述规则仅为配置示例，不能据此自动认定企业表格的区间或占位符含义。

## 2026-10-17 第十二批：训练中保留类别缺失

沿真实检查暴露的“缺失调平方式被混成已知类别”继续核对，发现使用说明建议直接保留原类别列，但 sklearn/Optuna 的默认预处理仍会用训练众数填补缺失。实际复现中，缺失与最常见类别得到完全相同的编码。另用当前依赖实测 AutoGluon 默认特征生成器：训练只有两个已知类别、预测首次出现缺失时，其二值转换也会将缺失变成其中一类。

- 增加 `features.preprocessing.categorical_missing='preserve'`，三种引擎共用训练折内的独热编码，跳过类别众数填补。训练出现过的缺失单独编码；训练未见类别（包括未见过的缺失）全零编码，不冒充某个已知类别。该选项针对非数值类别字段；数值代码列仍按数值处理，不推断业务类型或标签定义。`auto` 保留原有引擎行为，旧研究及预测不会被自动改写。
- AutoGluon 选择 preserve 时也使用已保存的类别预处理，避免其默认二值转换把未知值变成已知类别。各折独立拟合，最终开发集重新拟合后随模型保存；预测和留出测试只使用保存结果。未见类别不进入已有词表，不能把编码成功解释为已经认识其业务含义或预测可靠。
- 接通特征积木中文表单、模型工具说明和项目 modeling Skill，明确需要保留未知类别时选择该选项。训练笔记保留实际设置，完整模型包包含拟合后的编码器。环境快照记录 worker 支持的选项；固定到旧镜像的研究使用 preserve 时给出更新环境并新建研究的提示，默认候选仍可创建。草稿保存仍不依赖任何运行环境。
- 在另一人工验证项目的普通工作流中，通过浏览器将 auto 改为 preserve 并保存，实际完成 60 行诊断数据的两折分组训练和 4 条新数据预测，覆盖已知、缺失和未见类别。运行配置与保存表单一致，CSV 下载字节相符；下载包按 README 创建输入/输出目录后，在独立、禁网容器中使用包内 worker 预测，四行结果与平台完全一致。该诊断验证不涉及企业未确认值的解释，也不构成企业预测效果结论。

验证：受影响后端主组 63 项、worker/工具/笔记组 41 项、工具帮助和导入模型组 9 项通过。针对“缺失只在预测时出现”的情况追加覆盖后三引擎预处理文件完整 20 项通过，与主组重叠；包括已见/未见缺失、留出专有类别不进入训练词表、保存后预测、旧环境兼容及资源未就绪草稿。新镜像 `lilies-modeling:ml-category-missing-20261017` 中真实 Docker 完整链路 2 项通过，覆盖默认和 preserve；前端相关 20 项及类型检查通过。前端产品源码未改，未重复生产构建或全量回归。
