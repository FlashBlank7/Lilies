# 多步预测与滚动回测

2026-09-25。把已有数值预测方案中的“按当时已知数据训练、逐预测时点评价、区分点位/方向/边界/排序”做成可编辑流程。沿用代码、迭代、数据分析、模型训练和模型预测积木；没有新增训练服务或模型调用代理。

在项目空间「公共工作流市场」加入同名流程，或从示例创建「多步预测与滚动回测」。副本包含使用 Skill、自编日序列、迟到版本、建议问题和修改练习。通过表单运行无需大模型；对话调用沿用项目智能体。

## 员工如何使用

1. 选择 CSV、TSV 或 XLSX，指定观测时间和数值列。Excel 多工作表需选表。不同对象可以指定序列列，各自独立训练。
2. 核对时间间隔和实际可用时间。一天填86400秒，一小时3600秒；缺时段保留，不能把“下一行”当成“下一时段”。没有可用时间列时明确假定观测时刻即可使用，不能据此证明现实发布时间正确。
3. 先用少量回测起点与默认线性模型；需要时比较线性和随机森林。设置未来步数、滞后长度、季节周期，以及扩大或固定长度历史窗口。首个回测起点可留空，流程从最后完整窗口往前取指定数量。
4. 查看相同记录上模型与两种简单基线的误差。模型可能更差；完成训练不意味着应当采用。各步长、序列分别评价，不把不同单位的误差混合排名。
5. 可选预测文件最后时点之后的数据。这部分与历史回测分开保存，没有实际值时不计成绩；文件最后时点不保证等于当前生产时点。
6. 下载预测、逐步/逐起点评价、配置/模型版本、说明以及各起点样本来源 ZIP。模型和预处理保存在现有建模记录。换输入或训练配置时新建运行，旧结果保留。

示例建议问题：“请用项目中的滚动回测流程预测后续三个时段，比较模型是否超过简单基线，解释不同步数的误差。”没有模型连接也可以直接运行本流程。它不要求先完成数据摸底、审批或其他工作流。

## 方法与口径

| 环节 | 实际处理 |
| --- | --- |
| 时间和版本 | 时间统一到UTC；无时区值按表单偏移解释。相同观测可有不同可用时刻的修订；同序列、观测、可用时刻重复则报错 |
| 历史特征 | 每个样本起点的滞后值只使用该起点已可知版本，后来的修订不能倒灌为早期特征 |
| 训练标签 | 每个外层回测起点只取当时已可知标签；内部时间验证继续排除验证起点尚未知的标签 |
| 多步建模 | 滞后值加步长作为输入，一个回归模型共享多个步长，直接预测目标值；不是递归灌入未来真实值，也不是每步单独训练一个模型 |
| 预处理 | 数值填补、缩放及类别编码由原训练管线在各训练折内拟合；最终模型带同一预处理保存 |
| 缺值 | 部分滞后缺失由训练管线处理；所有滞后都无效的训练样本排除，当前预测输入全无效时报错。零与负值有效 |
| 最近值基线 | 取该起点最新可知的有效观测，保留其真实观测时刻，迟到时可以早于起点 |
| 季节基线 | 从起点之前相同周期位置取值；步数跨周期时向前回溯相应周期，缺项不回退为其他方法 |
| 比较 | MAE、RMSE、偏差、方向正确率使用三种方法共同可评价的记录；各方法自身覆盖和MAE另列，不能靠漏算记录取得更好成绩 |
| 方向 | 相对起点最近可知值，使用本次填写的原数值单位容差；不等同远期区间均值趋势分类 |
| 边界与排序 | 可选员工填写的上下界；分别计事件精确率/召回率，无事件不填成满分。每起点另算未来各步的平均秩相关，常量或不足两点不可计算 |
| 实际值 | 评价采用输入文件提供的最新版本，保留原记录及可用时刻；这些未来实际值仅进入评价，不进入该起点的训练或预测特征 |

训练样本数按“历史样本起点×预测步长”计，不等于原表行数。同一未来时刻可能被多个起点预测，保留这些不同决策，但不能把它们当成统计独立样本。回测结果用于调参后，需另留新的后续时段评价，不能继续称原回测为独立测试。

流程默认3个起点、每次3步、7个滞后。每起点内最多2个候选、总训练预算240秒、单候选60秒；默认只执行一个线性候选。首版最多20次逐起点训练、每表2万条记录、每起点2万训练样本。预算和方法可在现有节点配置中编辑；先缩小问题，不默认开启大规模搜索。

每起点保存实际 study/candidate/slot 和计算镜像。重新使用某个模型时，输入须符合本流程制备的滞后与步长结构，不能直接把原始时间序列表当成该模型的预测表。多频率外部指标可以先参考「按当时已知信息制备数据」；本流程首版仅建模数值序列自身。

方法参考：滚动起点应只用过去训练，且可以分别评价多步误差；训练残差不能代替真实预测误差。[Forecasting: Principles and Practice](https://otexts.com/fpp3/tscv.html)。滞后特征采用随机打乱划分可能造成过于乐观的评价，应保留时间结构。[scikit-learn 官方示例](https://scikit-learn.org/stable/auto_examples/applications/plot_time_series_lagged_features.html)。本流程另外处理实际可用时刻和历史修订，不能据这些文献推定客户数据已经满足条件。

## 本轮验证与修复

源项目提供的是预测需求和算法方案，未找到可复现的原价格训练集。定位及详细比较留在私有资料目录；公共示例为90天自编序列，包含周期、趋势和小扰动。没有把VMD、ARIMA、GRU融合、概率区间或报价策略写成已经复现的能力。

- 原生Docker训练完成逐起点训练、预测、模型版本固定、同版本独立预测一致，以及只改报告后复用计算。原训练和预测服务未被替换。
- 修改未来实际值不影响较早起点训练输入；标签修订、迟到、缺时段、负值/零、滑动窗口、长于季节周期的步数、共同评价分母及无事件指标均有行为测试。
- 员工页面三次成功运行分别为默认3起点×3步的9条、换迟到资料并启用未来预测的10条、手机修改为线性/随机森林比较的2条。独立核对7,504个滞后值、所有训练标签时点及报告MAE/RMSE；18个产物与旧报告可下载。
- 默认构造案例中线性模型各步MAE约2.0092、0.86054、1.5308，季节基线约0.26、0.71、0.71；如实保留简单方法更好的结果。三次页面运行约29.18、23.15、11.41秒，包含训练与文件处理，不是生产性能承诺。
- 390×844下表单可修改，页面宽390，无整页横向溢出，表格在314宽容器内滚动；CSV、Markdown和来源ZIP实际触发下载。输入步数0后收到具体范围错误，修复后原项目再次成功，失败记录保留。
- 首次示例运行暴露循环内输入引用被导入过程改成外层输入；改用明确的循环开始节点引用并验证创建后的实际执行。既有员工副本单独修复相关节点，未覆盖其输入默认值，原失败运行保留。
- 原运行时仅保存外层步骤。起点间停止后，循环内制备会重做并产生新路径，与已固定数据登记冲突。现按循环/迭代出现位置保存完成与跳过步骤，继续原任务时保留已完成起点；真实验证完成第一起点后停止、改变源文件、继续，仍使用原快照，两个起点只各训练一次。
- 迭代允许明确选择复用已完成结果，内部必须全部支持复用；输入、内部定义、声明的文件、输出、模型和计算环境改变时重算。旧流程默认不开启跨运行迭代复用；同任务暂停接续不依赖该选项。HTTP、完整智能体等未知副作用不自动复用。

另通过项目智能体工具发现、查看并启动一次单起点预测，完成1条实际预测及6个产物；与页面三次运行合计独立核对7,714个滞后值、24个产物。这里验证的是工具调用链，没有调用真实LLM进行对话选路。

受影响后端147通过、12项因额外计算配置跳过；补充文件依赖与旧环境指纹兼容后，方法/复用检查32通过、2项额外计算检查跳过。真实Docker方法与接续测试20通过，创建示例后的完整训练/独立预测/复用另行通过。前端192通过，类型检查与生产构建通过。本轮没有付费大模型调用；工具调用和员工页面模拟分别记录，不冒充真实员工反馈或生产预测准确率。
