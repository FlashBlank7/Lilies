## 开发演练中发现并修复

- 预览加载导致布局跳动；现在保留加载提示位置，并合并快速选列请求。
- 模型分类明细未显示已保存的类别名称；现在显示编码与业务含义，并补组件回归。
- 中间 CSV 从文件入口复用时必须携带状态和源行侧文件；读取、绑定和版本计算均已统一。
- 保存链的读取布局不能固定套在不同格式的新表上；现将工作表与表头设置暴露为可配置输入。
- 处理链重复保存键被局部变量遮蔽；已修正并补同请求重复保存测试。
- 开发过程中一次主动重启调试后端中断了在途分析；保留中断记录，页面重新运行产生独立成功结果。

开发排错过程包含技术介入，不能算作零救援验收。后续还修复了内部注册数据重复出现在搜索结果、预测表 `_sample` 被默认 JSON 编码器隐藏、预测结果续用时左侧源行位置、保存链的文件类型/必需字段声明，以及 PDF 内置预览在调试浏览器中黑屏。PDF 改为服务端按页渲染，不执行文档脚本。

## 补修后的固定流程复验

同一隔离调试项目，使用上述演练中已录入的字段定义和已训练模型。浏览器进行表单配置与操作，原始资料准备、测试用输入构造和调试服务启动不计入业务操作阶段。没有在这一复验阶段改源码、改数据库、用脚本补运行或修结果。

| 步骤 | 实际结果 |
|---|---|
| 保存整理与相关分析链，以原表运行 | 550 行；两高度字段 457 个有效对 |
| 指定历史模型，对新表预测 | 555 行全部保留；464 可预测、91 不可预测；编号及源行一致 |
| 在预测结果上筛选并继续选取数据 | 91 行复核子表；第一个源行为原表第 10 行，原因仍为待确认符号 |
| 故意保留无效行停止策略 | 明确失败，提示区间含义待确认；本次无产物，无旧报告混入 |
| 在页面改为明确排除并重跑 | 新训练与独立测试成功；旧失败记录保持 |
| 单独设置分析范围上限 6.5、只标记 | 单独分析结果；不新增模型、不改旧评价 |
| 将训练预处理改为折内 IQR 截断 | 新模型版本及独立评价；旧模型保留 |
| 保存链换新表调用 | 555 行；456 个有效对；相关系数 0.100548，与原表结果分别保存 |

这段固定复验总耗时 **334.85 秒（5 分 35 秒）**。计数口径：**8 次运行配置提交、1 次流程名称配置、1 次筛选配置，共 10 次计划内业务配置；技术救援 0 次**。故意触发的失败及页面修正计入这段耗时与配置次数。时间包含自动化操作、观察与同机测试等待，不是业务人员操作速度的估计；零救援仅适用于这条固定演练，不能外推到任意工业项目。
