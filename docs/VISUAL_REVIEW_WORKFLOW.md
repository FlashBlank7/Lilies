# 看图复核与经验记录

2026-09-25。把已有检查图片、机器原判断和员工复判放在同一条可编辑流程里，逐张记录观察、理由及适用条件，再整理参考样本候选。可从「公共工作流市场」加入项目，也可创建同名示例。无需大模型或视觉模型，创建不会运行。

## 员工如何使用

1. 将图片和CSV/Excel清单放入项目。默认列是 `sample_id`、`image_path`、`product_type`、`machine_prediction`，表单可改列名。机器判断没有提供也可复核；样本标识必须明确，不能重复。图片可填项目完整路径或唯一文件名；同名图片会要求明确路径。
2. 填写已知判定依据，选择起始记录和本次数量。默认最多10条，可选1至20条；报告列出未选入数量，不把选中部分说成全批检测。
3. 等待表单显示当前图片、可选参考图片和相关记录。填写合格、不合格或无法判断，再补理由及“下次可参考的方法和适用条件”。理由未知可留空，不会据此编造经验。
4. 提交后继续下一张。刷新后从「运行记录」打开原任务；已提交答案保留。等待输入时也可停止，之后由用户继续原运行，不能把新问题的回答提交到旧卡片。
5. 查看报告中机器原判断与人工复判的差别，下载逐条记录、未知项、参考候选及完整JSON。选择旧 `review.json` 可以重新导出，不再逐张提问。

报告里的图片链接可以在项目内预览和下载。输入原图及原始机器判断不会被改写；新资料、新参数或重新复判产生新运行，旧结果可查看。只有明确判断、理由、产品类型完整，且员工主动选择时，才列为参考候选；候选还没有被应用到模型、参考库或现场设备。

## 如何承载已有经验

原图像误判复核资料提出：保留设备结果、由工程师复判、将纠正样本作为以后参考；同时指出误判原因和工程师经验没有逐条记录，参考库未按产品区分。流程据此保存不同来源的结论、图片内容版本、适用产品、参考元数据、理由和方法，不自动把个人经验推广到其他产品。

可选清单列：`reference_path`、`reference_product`、`reference_version`、`reference_available_at`、`captured_at`、`batch`。参考产品不明或不同、版本缺失、时间缺失或参考晚于检测都会提示。时间比较要求带时区的ISO日期时间；无法判断时保留缺项，不补造时间。元数据仍是资料提供的说法，不是平台认证。

相同内容图片在本批出现多次会提示，避免把它们当成独立训练/测试样本。未来整理训练数据还需按产品、批次和时间隔离；填写人工标签不等于完成独立评价或让模型学会了新方法。

已有「预测与实测反馈对照」继续处理数值或类别指标。本流程负责看图和记录反馈，不重复实现评价或训练服务。员工可以将有用经验整理成项目Skill；没有自动学习或发布步骤。

需要比较类别时，使用输出 `labeled_path` 或 `feedback_inputs` 调用现有反馈对照，只有明确人工标签的行进入这份数据。完整复核表中的“无法判断”不能当成一种质量类别。没有明确标签时保留未知项，不启动空数据评价。

## 实现和范围

- 使用原生输入、条件、代码、顺序迭代、人工输入和输出积木；先保存本次清单和图片，再逐张暂停/恢复。没有平台阶段审批，也不要求其他任务必须先经过此流程。
- 清单支持UTF-8 CSV/TSV及XLSX，每表最多1万条、文件不超过10MB；多工作表时需指定名称。本次只处理明确选中的最多20条。
- 图片支持单帧PNG/JPEG/WebP，单图最多5MB、2000万像素。损坏、缺失、重名未明确和项目外路径在提问前报错，失败准备不留下半份输入。既有图片快照改变时拒绝继续保存判断。
- 复判结论面向质量二分类。其他标签体系可以编辑人工输入和后续代码，不能把0/1或任意类别悄悄解释成合格/不合格。
- `review-item.json` 保存逐张结果，`review.json` 保存可再次导出的本次复核，CSV及Markdown帮助阅读。图片来源、内容哈希和参考元数据留在JSON中；不建立另一个运行系统或现场参考库。
- 人工输入积木的 `context` 兼容原文字；也可引用 `{markdown, images:[{path,label}]}`，显示当前项目的图片。外部地址、跨项目路径与路径穿越不能变成图片请求。原始输出仍可展开查看。

## 示例与验证

示例包含两张代码生成的教学图、自编清单、其他对象清单和练习。教学规则只用于“演示线条”的连续性与边界，不是工业缺陷规则或生产图片。正常清单展示机器误报与漏报；其他对象没有同样判定依据，可以记录无法判断。

自动测试通过完整项目运行时验证两次不同等待步骤、明确答案提交、过期卡片拒绝、停止/恢复、原图变更不污染本次输入、错误文件清理和旧报告导出。项目工具能够将员工明确回答交给原步骤；没有真实模型选路或回答质量测试。

私有原件中的3张实际嵌入图片经平台解码并保存本次副本，字节哈希全部一致；没有配套标签，任务在验证读取后停止，没有填造人工结论。此前清点的5项中有两个ZIP目录条目，已更正为3张实际图片。

后端新方法9项与受影响回归60项通过，10项需要额外计算配置而跳过。页面交互与最终前端回归结果记录在本周开发记录。客户图像、文档和具体定位只保留私有目录；本流程没有验证生产误判率或视觉训练效果。

自动衔接验证将一条明确标签和一条未知复判交给现有反馈流程，只有前者参与评价。前端202项、类型检查及生产构建通过；普通文字补充表单仍兼容，图片表单未自动提交答案。等待时缺少停止入口、弹窗表单挤成横排以及长图片名溢出的问题在页面实测中修复。

独立模拟员工五次页面运行：两张教学图复核、非法数量失败、修复并更换对象后记录未知、两次旧结果重导出。四次成功结果的25项文件可读取，原结果保持不变。刷新及服务重启后继续原等待步骤，停止后由员工明确恢复；未知判断即使勾选候选也不进入参考候选。桌面及390×844模拟手机完成CSV、Markdown和原图下载；最终图片预览弹窗宽340、内部宽340，图片308像素且实际加载成功。此验证没有真实员工参与或模型调用。
