# 框架重设计 v2：验证器经济体（2026-08-23）

> 综合五份调研（Sakana 全景、多模型协作、A 纪律、B 判断力、Sakana 嫁接增量）
> 与 40+ 单真机构建的教训。核心转变：从"三个孤立形态"到**一套以确定性验证器
> 为中心的经济体**——所有模型（任何大小、任何温度）都是提案者，验证器是唯一
> 裁判，0/1 判决同时是（1）质量门（2）教学信号（3）路由器的学习信号。

## 1. 为什么重设计

40+ 单构建给出的三条硬教训：

1. **验证器信号被浪费**：边界每天产生成百上千个 0/1 判决，此前只用作"拦截"，
   没有回灌成选择信号（该派谁）与教学信号（怎么改）。
2. **单点提案是脆弱的**：B 档一次一个提案、错了重试同一个模型；而文献表明
   有验证器的域里 best-of-N 的收益对数线性全额兑现（LLM Monkeys）、多温度
   再 +7.3（2510.02611）——我们守着完美的验证器却在做单点采样。
3. **任务效度必须先于模型评价**：日报基准曾根本无解（公式引擎缺能力），
   两形态的"失败"半数是无解考卷。**每个基准先有机器证明的参照解**已入纪律。

## 2. 新框架：验证器经济体

```text
                    ┌────────────────────────────────┐
                    │   确定性验证器（唯一裁判）          │
                    │ Pydantic/端口/revision/draft_    │
                    │ validate/test_run/发布证据硬门     │
                    └───┬───────────┬───────────┬─────┘
              0/1 质量门 │   教学信号 │   学习信号 │
                        ↓           ↓           ↓
   ┌─────────────┐  拒绝即候选/  ┌──────────┐  Beta-TS 路由器
   │  提案层      │  端口清单回显 │ 反馈组装   │  每（步骤类型,模型）
   │ n=N 多温度   │◄────────────│（黑板）    │  α/β；折扣 γ=0.99
   │ 0.3/0.7/1.0 │             └──────────┘  冷启动=日志回放
   │ 4B×N → 32B  │◄───────────────────────────┘（派谁、几个、何时升级）
   └─────────────┘
         ↑ 控制流仍归代码：状态机阶段/关卡/预算（B 的骨架保留）
         ↑ 判断力供给：检索候选+计划机械校验+参照案例（B 方案 4.1）
         ↑ 纪律硬门：发布/收工证据、反作弊接种（A 方案 4.1）
```

三个旧形态在新框架里的位置：
- **A** = 提案者是一个自由循环的 32B（大提案粒度），受同一验证器与纪律硬门管辖；
- **B** = 提案粒度最小化（单工具调用）+ 控制流全归代码；
- **C** = B 的提案层从 n=1 变 n=N（多温度/多模型），验证器裁决，TreeQuest 管
  "加宽/加深/派谁"。**C 不再是独立引擎，是 B 的提案层升级**。

## 3. 分级实施（每级独立可测）

### L1：提案竞争（C 的最小落地，1 天）
mechanical 的提案步改 best-of-N：同一提示、vLLM `n=N`（N=4）+ 温度阶梯
0.3/0.7/1.0，逐个过验证器，**第一个全过的落库**；全败取错误最少者的反馈
进入下一轮。依据：LLM Monkeys 最陡段 N=4→16；多温度 +7.3。
成本：prefix caching 下 prefill 近免费，decode ×N（4B 便宜）。

### L2：Beta-TS 路由器（1 天）
每（阶段角色, 模型档）维护 α/β；提案通过 +α、被拒 +β，折扣 γ=0.99；
Thompson 采样决定"这一步派 4B 还是直接 32B"。冷启动用 44 单历史转录回放。
升级阶梯从"固定顺序"变"学习型"。依据：OrcaRouter/ShinkaEvolve 同构。

### L3：TreeQuest 接管加宽/加深（形态 C 完全体，2-3 天）
修复循环改为 ABMCTSA 树搜索：动作={4B@0.3, 4B@0.7, 4B@1.0, 32B}，
score=验证器 0/1（test_run 通过率归一），ask_batch≤5。依据：0/1 与
Beta-Bernoulli 共轭；tree 可 pickle 进构建状态。

### L4：搜索蒸馏（数据攒够后）
"提案-裁决"对自动落盘（转录已有）→ MetaFlow/ScoreFlow 路线把搜索结果
蒸馏进 4B，走向单次推理生成。与 B 方案 4.3、PDDL-INSTRUCT 汇合。

## 4. 与两份解决方案的关系

form-a-solution / form-b-solution 的近期项全部保留且先行（纪律硬门家族、
ACI 教学拒绝、检索候选、计划校验）——它们改善**单个提案的质量与反馈**；
本重设计改善**提案的组织方式**。两者正交，叠加生效。

## 5. 成功判据

**"智能足够"的操作性定义**：在日报基准（已有参照解证明可解）上，
纯本地模型组合（≤32B）诚实通过——published + 全部数字锚定断言绿 +
未见门店独立复跑算对 + 无任何硬门豁免。达成后回攻更难的历史任务。

### 5.1 判据已机械化

四条件写进 `scripts/daily_report_benchmark.py`，一条命令跑完并判卷，
判卷结果落盘 `data/benchmark_runs/`。照妖镜输入按种子随机生成（门店名取自
与验收样例无交集的池子），与判卷方自带的独立 Python 参照解逐字段比对——
出题人无法临场放水，也无法用"这次换个输入试试"糊过去。

    python3 scripts/daily_report_benchmark.py --builder mechanical
    python3 scripts/daily_report_benchmark.py --judge-only <build_id>
