# 平台测试：申请校验与资源分配

这是虚构的独立平台测试，不属于工业项目验收。包内没有实现或工作流答案。

我们有一项可以被独占使用的资源，希望申请校验、资源分配由两条独立工作流完成，并由主流程串起来。请先读资料，向用户说明理解，整理需求文档；收到开始搭建指令后再创建工作流。算法、字段映射和节点配置由搭建者完成。

申请输入包含申请编号、申请人和资源编号，三个字段均不能为空。编号是业务唯一标识。校验不通过时给出原因，不能占用资源。两条成员流程共享申请和资源的业务记录。

资源不存在时创建为空闲。分配成功后资源被该申请独占，申请状态为已分配。另一条申请竞争同一资源时，必须保留等待状态并说明原因，不能覆盖已经成功的占用。

同一业务请求重复提交要返回原任务；同一申请再次处理时，也不能重复分配。人工可以在平台业务记录中释放资源，然后继续原来等待的申请。已完成的申请记录保留。人工释放时以资源记录为准，历史申请不自动删除。

这次测试只处理单资源申请。等待申请由用户点击继续或发出按需处理指令，不需要后台自动抢占、公平队列或定时扫描。并发分配谁先成功均可，但同一时刻只能有一个占用者。

请自行创建测试与运行结果：申请 A 和 B 同时申请资源 R1，只能一个成功；释放 R1 后继续等待的申请应成功。错误输入、重复提交与数据冲突要有明确结果。也需要展示 Codex 在业务阶段按需调用已搭建工作流并汇报结果。

工作流应可在平台画布中编辑，并展示共享记录、各成员运行及等待原因。这一测试不使用内置模型节点和外部系统。
